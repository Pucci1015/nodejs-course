# 作る順番（実装の計画）

小さく作って、そのたびにテストを通し、コミットする。章ごとに「動くもの」で終える。

| 章     | 作るもの                                                                                               | 終わりの確かめ                                                            |
| ------ | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- |
| 第67章 | 要件・画面・API・データの設計（docs/）、予約の決まりの純粋な関数（src/domain/）、マイグレーション 002  | 単体テストと、制約のテスト（重なり 23P01）が通る                          |
| 第68章 | 役割（member・admin）と管理者だけの API、会議室と予約のリポジトリ・サービス・ルート                    | HTTP のテストで R1〜R10 が全部確かめられる。2人同時の予約で片方だけが入る |
| 第69章 | 画面（その日の表・予約のダイアログ・自分の予約・会議室の管理）、SSE、リマインドと取り消しのメール、E2E | 2つのブラウザで、片方の予約がもう片方に出る（E2E）                        |
| 第70章 | Dockerfile・compose・render.yaml・CI・デプロイ、README、運用の手順、振り返り                           | `docker compose up` で本番と同じ形が動く。CI の YAML が読める             |

## 小さく切る

1つのコミットは、1つのことだけ。テストと一緒に入れる。

| 順  | コミット                                               | テスト                |
| --- | ------------------------------------------------------ | --------------------- |
| 1   | 日本の時刻の関数（time.ts）                            | time.test.ts          |
| 2   | 予約の時刻の決まり（booking-rules.ts）                 | booking-rules.test.ts |
| 3   | 1日の枠（slots.ts）                                    | slots.test.ts         |
| 4   | マイグレーション 002                                   | constraints.test.ts   |
| 5〜 | 第68章: 役割 → 会議室 → 予約（作る → 一覧 → 取り消す） | 各 HTTP のテスト      |
