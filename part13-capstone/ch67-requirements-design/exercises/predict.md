# 第67章 練習問題4: 考えて答える

コードを書かずに、本文と `docs/` を読んで答えてください。答えは [../solutions/README.md](../solutions/README.md) の「問題4」にあります。

## (1) 確かめてから入れる

サービスで「重なる予約が無いか SELECT で確かめてから INSERT する」だけにして、データベースの EXCLUDE 制約を付けなかったとします。alice と bob が、同じ会議室の 10:00〜11:00 を、ほぼ同時に予約しました。何が起きうるでしょうか。時刻の順に、2人の SELECT と INSERT を並べて説明してください。

## (2) 枠の番号で持つ

予約を `starts_at`・`ends_at` の2つの瞬間ではなく、「日付」と「枠の番号（8:00 が 0、8:30 が 1、…）の配列」で持つ設計も考えられます。会社が「来月から 15 分の区切りにする」と決めたとき、2つの設計で、それぞれ何を直す必要があるでしょうか。

## (3) 日本の日付

次のコードは、日本の「今日」を `'YYYY-MM-DD'` で返すつもりで書かれています。

```ts
const today = new Date().toISOString().slice(0, 10);
```

日本の時刻で 12月10日 の 8:30 にこのコードを動かすと、何が返るでしょうか。それはなぜですか。本文の `tokyoParts` は、どうやってこれを避けていますか。

## (4) 作らないもの

`docs/requirements.md` には「作らないもの（この版では）」の節があります。この節が無いと、作る途中でどんな困りごとが起きやすいでしょうか。1つ挙げてください。

## (5) 10 件までは制約にしない

R7（1人のこれからの予約は 10 件まで）は、データベースの制約ではなく、サービスで数えて確かめます（`docs/data.md`）。同じ人が、2つのタブから同時に 11 件目と 12 件目を予約したとき、何件まで入りうるでしょうか。それでも制約にしなかったのはなぜでしょうか。
