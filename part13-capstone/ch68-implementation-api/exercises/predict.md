コードを書かずに、本文と [../solutions/app/](../solutions/app/) を読んで答えてください。答えは [../solutions/README.md](../solutions/README.md) の「問題4」にあります。

## (1) 道を書く順番

`src/routes/bookings.ts` で、`router.get('/mine', …)` を `router.get('/:id', …)` の**後ろ**に書いたとします。alice が `GET /api/bookings/mine` を送ると、どんな応答が返るでしょうか。どのコードのどの行で、何が起きるかを順に説明してください。

## (2) 422 と 409

次の4つの予約のリクエストは、それぞれ 422 と 409 のどちらで断られるでしょうか。本文 3.2節の「入力を直せば通るか」で説明してください。

|     | リクエスト                                                              |
| --- | ----------------------------------------------------------------------- |
| a   | 10:15 に始まる                                                          |
| b   | 会議室A の 10:00〜11:00（会議室A には、もう 10:30〜11:30 の予約がある） |
| c   | 停止した会議室を予約する                                                |
| d   | 題名が 101 文字                                                         |

## (3) 役割をセッションに覚えさせる

`requireUser` は、リクエストのたびにデータベースからユーザー（と役割）を読みます。ログインしたときに `req.session.role = 'admin'` と覚えさせ、`requireAdmin` はセッションだけを見る書き方にすれば、データベースへの問い合わせが1回減ります。この書き方では、どんな困りごとが起きるでしょうか。

## (4) 取り消しの UPDATE の条件

`pg-bookings.ts` の `cancel` は `UPDATE bookings SET canceled_at = now(), canceled_by = $2 WHERE id = $1 AND canceled_at IS NULL` です。サービスの `cancel` は、先に `get` で「取り消していないこと」を確かめてから、これを呼びます。それでも `AND canceled_at IS NULL` を書いておくのはなぜでしょうか。書かなかったとき、何が起きうるかを、alice と管理者が同時に取り消す場面で説明してください。

## (5) 本当の 11 件目

alice は、これからの予約をちょうど 9 件持っています。2つのタブから、ほぼ同時に、別の会議室の予約を1件ずつ送りました。2つのリクエストのサービスの `create` が、どの順に何をすると、両方とも 201 になるでしょうか。それは要件として困ることでしょうか（第67章 練習問題4 の (5) を思い出してください）。
