# 第13部 総合演習

第12部までで、Web アプリを設計・実装・テスト・公開するための部品が、ひととおりそろいました。この部では、それを**1つのアプリを最初から最後まで作る流れ**の中で使います。題材は教材が決めた「会議室の予約」です。実際の開発と同じ順に、要件を決め、設計し、API と画面を作り、テストし、公開の準備をして、振り返ります。規模は小さくしてありますが、手順は省きません。

全部に模範解答があるので、詰まったら見比べながら進められます。この部を終えたら、同じ順番で、自分で決めた題材のアプリを作ってください（自分のアプリは、この教材には入りません）。

| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| [第67章 要件と設計](ch67-requirements-design/README.md)  | この部の進め方、土台をコピーする、要件定義（目的・ユーザーストーリー・決まり R1〜R10）、画面と API の設計、データの設計と EXCLUDE 制約（重なる予約を断る）、決まりを純粋な関数にする、ADR と作る順番 | 4〜6時間               |
| [第68章 実装（前半）](ch68-implementation-api/README.md) | 役割（管理者）、入力の形とエラー、会議室と予約のデータの層・サービス・ルート、決まりを守る場所の分け方、要件を1つずつ HTTP のテストで確かめる                                                        | 5〜7時間               |

> **お金と外のサービスについて**: この部は、手元（自分の Mac と Docker）だけで最後まで進められます。第70章 5節の Render と GitHub Actions は、**読むだけで済ませてもかまいません**。執筆の環境からはクラウドのサービスと GitHub Actions を動かせなかったので、そこに書いた手順は各サービスの説明に基づくものです。画面や料金は変わるので、必ず公式で確認してください。

## 準備

第13部の練習問題は、外部のパッケージ（zod・yaml・pg・express・ESLint など）を使います。第5〜12部と同じく、**第13部のフォルダを `~/dev/part13` にコピーし、そこで動かします**。第67章の最初に、次を1回だけ実行します。

```sh
$ bash （ここに Finder から part13-capstone フォルダの中の setup-part13.sh をドラッグ）
```

- `~/dev/part13` が作られ、`npm ci` で練習問題のパッケージが入ります
- [setup-part13.sh](setup-part13.sh) は、作成先（既定 `~/dev/part13`）が既にあれば、何もせずに終わります
- 入るパッケージとバージョンは [package.json](package.json) と [package-lock.json](package-lock.json) のとおりです（express 5.3.0、pg 8.23.1、yaml 2.9.1、zod 4.6.7、typescript 6.0.3、eslint 10.13.0 など）
- アプリは `~/dev/part13/base` を `~/dev/room-booking` にコピーして育てます（第67章 2節）。アプリのパッケージは、そこで `npm ci` します
- Docker Desktop（か OrbStack）を使います（第6部 第32章で入れたもの）。アプリの `compose.yaml` が、PostgreSQL（127.0.0.1:5434）と Redis（127.0.0.1:6381）を動かします。第6部（5433・6380）とはぶつかりません

## 各章の使い方

第1〜12部と同じ構成ですが、「手を動かす」で書くものは、ほとんどが `~/dev/room-booking` のアプリのファイルです。

| 場所         | 中身                                                                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `README.md`  | 本文。番号の付いた節（1, 2, 3, …）に分かれている。「手を動かす」の節で、アプリのファイルを自分で書いて動かす                                           |
| `exercises/` | 練習問題（`README.md`）と、問題で使うファイル。アプリの部品を小さな関数にして練習する問題と、アプリに機能を足す問題（第68・69章の `app-tests/`）がある |
| `solutions/` | 模範解答（`README.md`）と、解答のファイル。第67〜69章の `solutions/app/` は、その章を終えたときのアプリ                                                |
| `samples/`   | 第70章だけ。「手を動かす」で書く小さなスクリプトの完成形                                                                                               |
| `base/`      | アプリの土台（第12部のタスク管理アプリから、どの題材でも使う部分だけを残したもの）                                                                     |

- コードは TypeScript（`.ts`）です。`node x.ts` で動かし、`npx tsc` で型を確かめます。練習問題は `node --test x.test.ts`、模範解答は `MODULE=../solutions/x.ts node --test x.test.ts` で確かめます
- アプリのポートは、開発の API 9900・画面 5174・偽の SMTP 1025（届いたメールは 8025）、E2E 9906〜9908、`compose.prod.yaml` 9911・9913 です。第12部（9490・5173・9801〜9803）と同時に動かしてもぶつかりません
- データベースを使うテストは、`test_` で始まるスキーマを作り、終わったら消します
- パスワード・鍵・合言葉は、`dev-only-…` で始まる開発用の仮のものです。例のメールアドレスは `alice@example.com`・`bob@example.com`、ドメインは `example.com` です
- 章ごとに、アプリの `main` にコミットします。練習問題でアプリに機能を足す問題（第68・69章の問題7）は、ブランチを作って行い、終わったら `main` に戻ります

## 第13部を終えたときにできること

- 作りたいものを、目的・ユーザーストーリー・番号を付けた決まり・作らないもの、に分けて書ける
- 画面・API・データの設計を表で書き、技術の選び方を ADR に残せる。決まりを、データベースの制約とアプリのどこで守るか決められる
- 決まりを純粋な関数と表のテストで固めてから、データの層 → サービス → ルート → 画面 の順に、小さく作ってはテストできる
- 要件の決まりを1つずつ、HTTP のテスト・画面のテスト・E2E で確かめられる
- 自分のアプリを1つのイメージにし、本番と同じ形を手元で動かして外から確かめ、CI とデプロイの設定を書ける
- 運用の手順・README・振り返りを書き、次のアプリの計画に生かせる

## 第13部で作るもの

- Dockerfile・`compose.prod.yaml`・CI・`render.yaml`・デプロイのワークフロー、運用の手順、README、振り返り（第70章）
