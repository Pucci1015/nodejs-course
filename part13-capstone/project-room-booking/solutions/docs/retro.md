# 振り返り

作り終えたところで、計画（`plan.md`）と比べて、何がうまくいき、何に困り、次に何を変えるかを書きます。形は KPT（Keep・Problem・Try）です。数は、各章の終わりの `npm run check` などの結果です。

| 章     | 計画の終わりの確かめ                                          | 実際                                                                          |
| ------ | ------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 第67章 | 単体テストと、制約のテスト（重なり 23P01）が通る              | 通った（単体 26・制約 6）                                                     |
| 第68章 | HTTP のテストで R1〜R10 が確かめられる。同時の予約は片方だけ  | 通った（HTTP 17 を足して 82 個。同時の予約は 409 が 1 つ）                    |

決めていなかった「停止した会議室の、これからの予約」は、計画どおり**残す**ままにしました。困ったら次の版で決めます。

## 2. Keep（続けること）

- **決まりを純粋な関数にしてから作った。** `checkBookingTime` を先に表のテストで固めたので、API でも画面でも同じ関数を使え、画面の「送る前の確かめ」がそのまま書けた
- **重なりはデータベースに守らせた。** 2人同時の予約は、アプリのコードでは防げない。EXCLUDE 制約にしたので、同時のテストを足しても、コードは変えずに済んだ
- **1章1コミット、テストと一緒に。** どの章の終わりも「動くもの」で、戻りたくなったらその章のコミットに戻れた
- **土台を使った。** ログイン・メール・仕事の列・監視を作り直さずに済み、時間を題材の部分に使えた

## 3. Problem（困ったこと）

| 困ったこと                                                                                                  | 原因                                                  | どうしたか                                                                  |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- | --------------------------------------------------------------------------- |
| `grant-admin` を、サーバを一度も起動していないデータベースで動かすと失敗した                                | 表を作るマイグレーションは、サーバの起動のときに動く  | スクリプトの最初で `migrate()` を呼ぶ（動かしてあれば何もしない）           |
| 日付がずれやすい。UTC の「今日」と日本の「今日」は、日本の朝 9 時まで違う                                   | `new Date().toISOString().slice(0, 10)` は UTC の日付 | 日本の日付は `tokyoParts` だけで作る。テストは UTC 15:00 の前後を必ず入れる |
| 最初のページの見出しを「会議室の予約」から「その日の予約」に変えると、土台のテストを 3 か所直す必要があった | 画面のテストと E2E が、見出しの名前で探している       | 名前を変えるときは `grep` してから。名前で探すテストの、よい面でもある      |
| 管理者が取り消したときのメールを、サービスの中で送ろうとすると、サービスが SMTP を知ってしまう              | 層の向き（サービスは外の仕組みを知らない）            | `onCanceledByOther` を受け取り、`server.ts` がメールの仕事につなぐ          |
| リマインドを2回動かすと、2通届きそうになった                                                                | 再試行と、決まった時刻の重なり                        | `reminder_log` の主キー（人・日）に入れられた時だけ送る                     |

## 4. Try（次にやること）

- 予約の**変更**（時刻・題名）。今は取り消して入れ直す。`If-Match` と版（第25章）で作れる
- 繰り返しの予約（毎週の定例）。1件ずつの行にするか、決まりを持つ行にするかを、ADR を書いてから決める
- 停止した会議室の、これからの予約を、管理者の画面に出す
- 画面のコピー（`web/src/domain/`）を、ワークスペース（npm workspaces）で API と共有する
- 実際の GitHub と Render で、CI とデプロイを動かす（`render.yaml`・`deploy.yml` は形だけを確かめた）
