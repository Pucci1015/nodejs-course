# 要件定義 — 会議室の予約

## 1. 目的

社内の会議室の予約を、紙の表やチャットのやりとりから、Web の画面に移す。だれがいつ使うかが一目で分かり、2人が同じ時間を取ってしまうことを無くす。

## 2. 使う人

| 役割               | 人数の目安 | すること                                               |
| ------------------ | ---------- | ------------------------------------------------------ |
| メンバー（member） | 50 人      | 空いている会議室を探して予約する。自分の予約を取り消す |
| 管理者（admin）    | 1〜2 人    | 会議室を登録・変更・停止する。だれの予約でも取り消せる |

- 登録とログインは、土台のもの（メールの確認つき）を使う。登録した人はメンバーになる
- 最初の管理者は、サーバで `scripts/grant-admin.ts` を動かして決める（画面からは決められない）

## 3. ユーザーストーリー

| #   | ストーリー                                                                       | 優先   |
| --- | -------------------------------------------------------------------------------- | ------ |
| S1  | メンバーとして、ある日の全部の会議室の予約を表で見たい。空いている時間を探すため | 必須   |
| S2  | メンバーとして、空いている枠から予約したい。題名を付けて                         | 必須   |
| S3  | メンバーとして、自分のこれからの予約を一覧で見て、取り消したい                   | 必須   |
| S4  | メンバーとして、ほかの人が予約したら、表を開き直さなくても反映されてほしい       | 必須   |
| S5  | メンバーとして、前の日の夕方に、翌日の予約をメールで知らせてほしい               | 必須   |
| S6  | 管理者として、会議室を登録し、名前・定員を変え、使えなくしたい                   | 必須   |
| S7  | 管理者として、だれの予約でも取り消したい。取り消された人にはメールで知らせたい   | 必須   |
| S8  | メンバーとして、毎週同じ時間を一度に予約したい                                   | 後回し |
| S9  | メンバーとして、定員や設備（モニター）で会議室を絞り込みたい                     | 後回し |

## 4. 予約の決まり

| #   | 決まり                                                                  | 破ったとき |
| --- | ----------------------------------------------------------------------- | ---------- |
| R1  | 時刻は 30 分の区切り（:00 か :30）                                      | 422        |
| R2  | 予約できるのは 8:00〜21:00（日本の時刻）。日をまたがない                | 422        |
| R3  | 長さは 30 分〜3 時間                                                    | 422        |
| R4  | 始まりが過ぎた時刻は予約できない。60 日先まで                           | 422        |
| R5  | 題名は前後の空白を除いて 1〜100 文字                                    | 422        |
| R6  | 同じ会議室で、時間が重なる予約はできない（取り消したものは数えない）    | 409        |
| R7  | 1人の「これからの予約」（終わっていない・取り消していない）は 10 件まで | 409        |
| R8  | 使えない（停止した）会議室は予約できない                                | 409        |
| R9  | 取り消せるのは本人か管理者。始まった予約は取り消せない                  | 403・409   |
| R10 | 会議室の名前は重ならない。定員は 1〜100                                 | 409・422   |

- 時刻はいつも**日本の時刻**で考える（使う人がみな日本にいる前提）。サーバとデータベースは UTC の瞬間で持つ
- 会議室は消さない（過去の予約が会議室を指しているため）。停止するだけ

## 5. 機能以外の要件

| 項目       | 決めたこと                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------------- |
| 同時の予約 | 2人が同時に同じ枠を予約しても、片方だけが入る（データベースの制約で守る）                      |
| 反映の速さ | ほかの人の予約は、数秒以内に表に出る（SSE）                                                    |
| 権限       | 権限は画面ではなく API で守る（画面は使いやすさのために隠すだけ）                              |
| 個人情報   | 表には、予約した人のメールアドレスを出さない（題名と時刻だけ）。自分の予約にだけ「自分」と出す |
| 動かす場所 | 第12部と同じ形（Docker のイメージ・PostgreSQL・Redis・PaaS）                                   |
| テスト     | 決まり（R1〜R10）は、どれも自動のテストで確かめる                                              |

## 6. 作らないもの（この版では）

- 繰り返しの予約（S8）、設備での絞り込み（S9）
- 承認の流れ（予約したら、すぐ決まる）
- カレンダーのアプリとの連携（iCalendar）
- 会議室の写真（第12部の添付ファイルの仕組みで、後から足せる）
