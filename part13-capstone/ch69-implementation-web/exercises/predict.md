# 第69章 練習問題4: 考えて答える

コードを書かずに、本文と [../solutions/app/](../solutions/app/) を読んで答えてください。答えは [../solutions/README.md](../solutions/README.md) の「問題4」にあります。

## (1) 知らせに中身を入れない

予約の知らせ（`booking.created`）は `{ id, roomId, date }` だけで、題名もだれの予約かも入れていません。題名と `mine` も知らせに入れ、画面が読み直さずにキャッシュに足す書き方にすると、通信が1回減ります。この書き方では、どんな困りごとが起きるでしょうか。`mine` に注目して答えてください。

## (2) 描画の中の「今」

`DayGrid` の中で `const now = new Date()` と書き、`useNow` を使わなかったとします。次の2つの場面で何が起きるでしょうか。

- 9:25 に表を開いたまま、何も触らずに 9:35 になった（9:30 の枠）
- 画面のテスト（`booking.test.tsx`）を、夜の 22 時に動かした

## (3) 送る前に確かめても 409

予約のダイアログは、送る前に `checkBookingTime` で確かめます。それでも API が 409 を返すのは、どんなときでしょうか。2つ挙げてください。また、API が「30 分の区切り」を「15 分の区切り」に変え、`web/src/domain/` のコピーを直し忘れたら、画面はどうなるでしょうか。

## (4) リマインドが2通届くとき

`sendReminders` は、人ごとに「記録を入れる → 送る → COMMIT」の順です。これを「送る → 記録を入れる」の順（トランザクションなし）にしたとします。ワーカーが2台あり、同じ時刻に同じ仕事を動かしたとき（か、1回目の仕事が途中で失敗して再試行したとき）、何が起きるでしょうか。本文の順番では、どの場面なら2通届くでしょうか。

## (5) E2E で「明日」を開く

`e2e/booking-flow.spec.ts` は、`/?date=明日` を開いて 10:00 の枠を押します。今日の表を開く書き方にすると、どんなときにテストが失敗するでしょうか。また、bob の画面を確かめる `getByRole('cell', { name: '定例', exact: true })` から `exact: true` を外すと、どんな間違いを見逃すでしょうか。
