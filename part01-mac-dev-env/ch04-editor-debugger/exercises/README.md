## 問題1 ターミナルから VS Code を使う（基本）

1. `which code` で、`code` コマンドがどこにあるかを確かめてください。見つからないときは、本文1.1節の手順で入れます。
2. `ls -l` で、1 の場所のファイルを調べてください。シンボリックリンクですか。どこを指していますか。
3. `code --list-extensions` で、入っている拡張機能の一覧を表示してください。本文4節の表の ESLint・Prettier・EditorConfig が入っていなければ、`code --install-extension` で入れてください。
4. `code --list-extensions | wc -l` で、拡張機能の数を数えてください。
5. 統合ターミナル（`` Ctrl + ` ``）を開き、`pwd` を実行してください。どのフォルダが表示されましたか。それはなぜですか。

## 問題2 設定の階層を使い分ける（基本）

`~/dev/settings-practice` というフォルダを作り、`code ~/dev/settings-practice` で開いてください。次の状態になるように、**ユーザー設定**・**ワークスペース設定**（`.vscode/settings.json`）・**`.editorconfig`** のどれかに設定を書いてください。どこに書いたか、なぜそこに書いたかも答えます。

1. 自分の VS Code では、どのプロジェクトでも文字の大きさを 15 にする。
2. このプロジェクトでは、インデントを空白2つにする。VS Code 以外のエディタを使う人にも守ってもらう。
3. このプロジェクトでは、JavaScript のファイルだけ、保存するときに Prettier で整形する。
4. このプロジェクトでは、`node_modules` フォルダを、全体の検索（`⌘ + Shift + F`）で探さないようにする。

ヒント: 使う設定の名前は、本文3節の「よく使う設定の名前」の表と、言語ごとの設定（`"[javascript]": { ... }`）の書き方にあります。

## 問題3 エディタの機能で書き換える（基本）

[refactor-me.js](refactor-me.js) を、次の手順で書き換えてください。**手で文字を打ち直すのはできるだけ減らし**、VS Code の機能を使うこと。使った機能（キー）をメモしておきましょう。

書き換える前に、出力を保存しておきます（本文5.4節）。

```sh
$ cd exercises
$ node refactor-me.js > before.txt
```

1. 変数 `d` の名前を `tasks` に変える（`F2`）。
2. オブジェクトの `t`・`p`・`f` の名前を、それぞれ `title`・`priority`・`done` に変える（オブジェクトを書いている所で `F2`）。
3. `var` を、すべて `let` に変える（`⌘ + D`）。
4. `+` で文字列をつないでいる3か所を、テンプレートリテラル（`` `...${}...` ``）に変える（`⌘ + .`）。
5. 「優先度3以上か」の条件（`tasks[i].priority >= 3`）を、`isHighPriority` という名前の関数に切り出す（その部分を選んで `⌘ + .`）。
6. ファイル全体を整形する（`⌥ + Shift + F`）。

最後に、出力が変わっていないことを確かめます。

```sh
$ node refactor-me.js > after.txt
$ diff before.txt after.txt && echo 同じです
```

## 問題4 デバッガの基本の操作（基本）

[../samples/debug-demo.mjs](../samples/debug-demo.mjs) を開き、JavaScript Debug Terminal（本文10.1節）で動かします。

```sh
$ cd samples
$ node debug-demo.mjs 3
```

1. 行(A)（`const summary = ...` の行）にブレークポイントを置いて実行してください。止まったら、左の「変数」で `tasks` の中身（4つのタスク）を見てください。
2. `F10`（ステップオーバー）で1行ずつ進め、`summary` の `total`・`done`・`highPriority` がいつ増えるかを見てください。ループの1回目が終わったとき、それぞれいくつでしたか。
3. 行(B)（`console.log(formatTask(task))` の行）で止まったとき、`F11`（ステップイン）を押して `formatTask` の中に入ってください。左の「コールスタック」には、何が表示されていますか。`Shift + F11` で戻ってください。
4. 行(A) のブレークポイントを外し、行(B) にブレークポイントを置いて、もう一度実行してください。ウォッチ式に `summary.total` を登録し、`F5`（続行）を押して次に止まるたびに、値がどう変わるかを見てください。
5. 最後に、ブレークポイントを外して `F5` で最後まで実行してください。ターミナルに何が表示されましたか。

## 問題5 特別なブレークポイントを使う（応用）

問題4 と同じ [../samples/debug-demo.mjs](../samples/debug-demo.mjs) を使います。問題4 のブレークポイントは、外しておきます。

1. 行(C)（`if (task.priority >= 3) ...` の行）に、条件 `task.priority >= 3` の**条件付きブレークポイント**を置いて実行してください。何回止まりましたか。止まったときの `task.title` は何でしたか。
2. 1 のブレークポイントを外し、同じ行に**ログポイント** `{task.title}: {task.priority}` を置いて実行してください。どこに、何が表示されましたか。止まりましたか。
3. 「ブレークポイント」の画面で「Uncaught Exceptions」にチェックを入れ、`node debug-demo.mjs 99` を実行してください。どの行で止まりましたか。そのときのコールスタックには、どの関数が並んでいますか。
4. 3 で止まったとき、デバッグコンソールで `id` と `tasks.map((t) => t.id)` を実行してください。エラーになった理由を説明してください。

## 問題6 ステップ実行でバグを探す（応用）

[bug-grades.mjs](bug-grades.mjs) は、生徒の平均点を計算して、順位と合格者を表示するプログラムです。期待する出力は、ファイルの最初のコメントにあります。

```sh
$ cd exercises
$ node bug-grades.mjs
1位 佐藤 55.7
2位 鈴木 61.0
...
合格者（平均70点以上）: （0人）
```

**バグが3つあります。** 次の手順で見つけて直してください。

1. まず手で計算しておきます。佐藤さん（80, 92, 75）の平均は、いくつになるべきですか。
2. `average` 関数の中（`sum += scores[i];` の行）にブレークポイントを置き、ステップ実行しながら `i` と `sum` の変化を見てください。1回目に足されたのは、どの点数でしたか。1つ目のバグを直してください。
3. 直して動かし直すと、平均は正しくなりますが、順位が点数の高い順になりません。`rank` 関数の `sort` の比較関数の中（`a.avg < b.avg`）にブレークポイントを置き、比較関数が何を返しているかを見てください。本文8.1節の `sort` の説明と比べて、2つ目のバグを直してください。デバッグコンソールで `[3, 1, 2].sort((a, b) => a < b)` を試すのも手がかりになります。
4. まだ、合格者の人数が期待と合いません。`filter` の中（`r.avg > 70` の部分）に、条件 `r.name === '高橋'` の条件付きブレークポイントを置いて、高橋さんの `r.avg` と、条件の結果を確かめてください。3つ目のバグを直してください。
5. 3つのバグそれぞれについて「何が原因で、デバッガで何を見て気づいたか」を1〜2行で書いてください。

## 問題7 DevTools でブラウザ側のバグを探す（応用）

この `exercises` フォルダを配信して、ブラウザでページを開きます。

```sh
$ cd exercises
$ node ../samples/serve.mjs .
# → Chrome で http://localhost:8000/buggy-page.html を開き、⌘ + ⌥ + I で DevTools を開く
```

本当は、[tasks.json](tasks.json) の3件のタスクが表示され、フォームで追加でき、「完了したものを隠す」で完了済みのタスクを隠せるページです。ところが、次の3つの問題があります。

1. ページを開くと「読み込みに失敗しました（404）」と表示され、タスクが1件も出ない。
2. 「完了したものを隠す」のチェックを付けても外しても、表示が変わらない（タスクを読み込めるように直してから確かめること）。
3. タスクを何件か追加すると、2件目からは、追加するたびに名前が空のタスクも増えていく。

それぞれ、次の DevTools の機能を使って原因を突き止め、[buggy-page.js](buggy-page.js) を直してください。

| 問題 | 使う機能 |
| --- | --- |
| 1 | Network パネル。どの URL にリクエストし、何が返ってきたか。`tasks.json` は、ページと同じフォルダにあります（本文11.3節の URL の説明） |
| 2 | Elements パネルでチェックボックスを選び、Console で `$0.value` と `$0.checked` を、チェックを付けたときと外したときで比べる |
| 3 | Elements パネルでフォーム（`<form id="form">`）を選び、右側の「Event Listeners」タブで `submit` のリスナーの数を見る。タスクを追加するたびに、数がどうなるか |

直したら、ブラウザで `⌘ + Shift + R`（前に取ってきたものを使わずに読み直す）で確かめます。終わったら、ターミナルで `Ctrl + C` を押してサーバを止めます。

## 問題8 設定がぶつかったとき、どれが使われるか（発展）

問題2 のフォルダを使います。

1. **ユーザー設定**に `"editor.tabSize": 4` を書いてください。
2. このプロジェクトで新しい `.js` のファイルを作ると、インデントの幅はいくつになりますか。問題2 の 2 で `.editorconfig` に書いた設定と、ユーザー設定の `4` の、どちらが使われるかを**予想してから**確かめてください（ステータスバーの「Spaces: 2」のような表示で分かります）。
3. `.editorconfig` の `indent_size = 2` の行を消して保存し、新しいファイルを作ると、どうなりますか。
4. 確かめ終わったら、ユーザー設定の `"editor.tabSize": 4` を消しておきます。

## 問題9 Chrome DevTools で Node.js をデバッグする（発展）

VS Code ではなく、Chrome DevTools を Node.js のデバッガとして使います（本文9節）。

```sh
$ cd samples
$ node --inspect-brk debug-demo.mjs 3
```

1. Chrome で `chrome://inspect` を開き、「Remote Target」の `inspect` をクリックしてください。どの行で止まっていますか。それはなぜですか。
2. Sources パネルで、行(C) にブレークポイントを置き、`F8`（Chrome DevTools の「続行」）を押してください。止まったら、右側の「Scope」で `task` の値を見てください。
3. 終わったら、ターミナルで `Ctrl + C` を押して Node.js を止めてください。
4. ターミナルに表示された `Debugger listening on ws://127.0.0.1:9229/...` の `127.0.0.1` は、何を意味していますか。本文9節の「注意」を読んで、`--inspect=0.0.0.0:9229` で起動してはいけない理由を説明してください。
