# 第1部の成果物: 開発環境の設定（dotfiles）を GitHub で管理する

第1部で整えた設定ファイルを1つの Git リポジトリにまとめ、GitHub で管理します。
`.zshrc` や `.gitconfig` のように `.` で始まる設定ファイルを **dotfiles** と呼びます。dotfiles をリポジトリにしておくと、

- 設定を変えた履歴が残り、壊したときに戻せる
- 新しい Mac を用意したとき、clone してスクリプトを1回動かすだけで、同じ環境になる
- 「なぜこの設定にしたか」を、コミットのメッセージやコメントとして残せる

という利点があります。第1部の4つの章で学んだこと（シェル、PATH、Homebrew、mise、Git、SSH、VS Code）をまとめて使う課題です。

## 1. 仕組み: シンボリックリンク

dotfiles の管理では、設定ファイルの**実体をリポジトリの中に置き**、本来の場所（`~/.zshrc` など）には、実体を指す**シンボリックリンク**（第2章4.3節）を置きます。

```
~/.zshrc  ─────(シンボリックリンク)─────▶  ~/dev/dotfiles/zshrc   ← Git で管理されている実体
```

zsh は `~/.zshrc` を読もうとして、リンクをたどって、リポジトリの中のファイルを読みます。`~/.zshrc` を書き換えると、実際にはリポジトリの中のファイルが変わるので、そのまま `git diff` で確かめてコミットできます。

> dotfiles のリポジトリは、OneDrive などの同期フォルダではなく、`~/dev/dotfiles` のようなローカルのフォルダに置いてください（第1章2.5節）。同期が遅れたり、ほかの Mac と食い違ったりすると、シェルの設定が読めなくなることがあります。

## 2. この成果物で新しく使うコマンドと書き方

### 2.1 ln -s: シンボリックリンクを作る

```sh
$ ln -s ~/dev/dotfiles/zshrc ~/.zshrc     # ln -s 実体 リンクを置く場所
$ ls -l ~/.zshrc
lrwxr-xr-x  1 alice  staff  31 11  4 10:00 /Users/alice/.zshrc -> /Users/alice/dev/dotfiles/zshrc
$ readlink ~/.zshrc                       # リンクが指している先だけを表示する（第2章4.3節）
/Users/alice/dev/dotfiles/zshrc
```

- `ln` はリンクを作るコマンドで、`-s` を付けるとシンボリックリンクになります（symbolic）。**1つ目が実体、2つ目がリンクを置く場所**です。順番を逆にしないように気をつけます。
- `ls -l` の最初の文字 `l` が、シンボリックリンクの印です（第1章8.1節）。
- **リンクを置く場所に、既にファイルがあると失敗します**（`ln: /Users/alice/.zshrc: File exists`）。先にそのファイルを別の場所に移します（`mv`。第1章3.4節）。
- 実体は、`~/dev/dotfiles/zshrc` のように**ホームから始まるパス**（絶対パス）で書きます。`ln -s zshrc ~/.zshrc` のように書くと、リンクは「リンクを置いた場所から見た `zshrc`」、つまり `~/zshrc` を指してしまい、読めません。
- 実体のファイルを消したり移したりすると、リンクは「切れた」状態になり、読もうとするとエラーになります。

### 2.2 dirname: パスからフォルダの部分を取り出す

```sh
$ dirname ~/.config/git/ignore
/Users/alice/.config/git
$ mkdir -p "$(dirname ~/.config/git/ignore)"   # リンクを置くフォルダが無ければ作る（第1章3.3節、5.3節）
```

`dirname` は、パスの最後の名前を除いた部分（フォルダ）を表示します。第1章9.4節の `basename`（最後の名前だけを取り出す）と対になるコマンドです。

### 2.3 if の条件と elif

第1章9.3節の条件に加えて、次のものを使います。

| 条件 | 正しいとき |
| --- | --- |
| `[[ -L "$path" ]]` | シンボリックリンクがある（link）。リンクが切れていても正しい |
| `[[ -e "$path" ]]` | ファイルかフォルダがある（exist）。リンクのときは、**リンクの先**があるかを調べる |

`elif` を使うと、「そうでなく、もし〜なら」を続けて書けます。上から順に調べ、最初に正しかったところだけを動かします。

```bash
if [[ -L "$dest" ]]; then
  echo "リンクがあります"
elif [[ -e "$dest" ]]; then
  echo "リンクではない、ふつうのファイルがあります"
else
  echo "何もありません"
fi
```

### 2.4 関数に引数を渡す

第1章11.3節の `mkcd` と同じように、bash でも関数を作れます。関数の中では、渡された引数を `$1`・`$2` で読めます（スクリプトの引数と同じ。第1章9.3節）。

```bash
greet() {
  echo "$1 さん、$2"
}
greet alice こんにちは      # → alice さん、こんにちは
```

## 3. 要件

### 3.1 含めるファイル

| リポジトリの中のファイル | リンクを置く場所 | 中身 | 参照 |
| --- | --- | --- | --- |
| `zprofile` | `~/.zprofile` | Homebrew の `brew shellenv`、`~/.local/bin` の PATH | 第1章11節、第2章3.3節 |
| `zshrc` | `~/.zshrc` | エイリアス、関数（第1章11.2・11.3節の `ll`・`mkcd`、練習問題9の `bak` など）、`mise activate` | 第1章11節、第2章6.1節 |
| `gitconfig` | `~/.gitconfig` | 第3章2節の設定 | 第3章2節 |
| `gitignore_global` | `~/.config/git/ignore` | `.DS_Store` など | 第3章13.1節 |
| `ssh_config` | `~/.ssh/config` | GitHub への接続の設定 | 第3章11.3節 |
| `vscode-settings.json` | `~/Library/Application Support/Code/User/settings.json` | VS Code のユーザー設定 | 第4章3節 |
| `Brewfile` | （リンクしない） | 第2章の練習問題8で作ったもの | 第2章4.5節 |
| `install.sh` | （リンクしない） | リンクを作るスクリプト（5節） | |
| `README.md` | （リンクしない） | このリポジトリの説明と、新しい Mac での手順 | |

### 3.2 リポジトリの中のファイルの名前

リポジトリの中では、ファイルの名前に `.` を付けません（`.zshrc` ではなく `zshrc`）。Finder や `ls` で隠しファイルにならず、見通しがよいからです。リンクを置く側で `.zshrc` という名前にします。

### 3.3 リポジトリに入れてはいけないもの

dotfiles を Public で公開している人も多いですが、次のものは**絶対にリポジトリに入れません**。

| 入れないもの | 理由 | 代わりにどうするか |
| --- | --- | --- |
| SSH の秘密鍵（`~/.ssh/id_ed25519`） | ほかの人が、あなたとして GitHub に push できてしまう | 新しい Mac では、鍵を作り直して登録する |
| API キー、トークン、パスワード | 悪用される | `~/.zshrc.local` のような、Git で管理しないファイルに書き、`zshrc` から読み込む |
| `~/.zsh_history` | 打ったコマンドに、秘密の情報が入っていることがある | |
| 個人のメールアドレス（Public の場合） | 迷惑メールや、個人の特定に使われる | GitHub の noreply アドレスにする（第3章2節） |

## 4. 基本: 手でリンクを作る

まずスクリプトを書かずに、手で1つずつ作って、仕組みを確かめます。

```sh
# 1. リポジトリを作る
$ mkdir -p ~/dev/dotfiles && cd ~/dev/dotfiles
$ git init

# 2. 今の設定ファイルを、リポジトリにコピーしてくる（まだリンクにはしない）
$ cp ~/.zshrc zshrc
$ cp ~/.zprofile zprofile
$ cp ~/.gitconfig gitconfig

# 3. 中身を見直す。要らない行を消し、各行の意味をコメントで書き、秘密の情報が無いか確かめる
$ code .

# 4. 1つ目のリンクを手で作る。元のファイルは、消さずに名前を変えて残しておく
$ mv ~/.zshrc ~/.zshrc.before-dotfiles
$ ln -s ~/dev/dotfiles/zshrc ~/.zshrc
$ ls -l ~/.zshrc

# 5. 新しいターミナルのタブ（⌘ + T）を開いて、エラーが出ないこと、ll や mkcd が使えることを確かめる

# 6. コミットする
$ git add -A && git commit -m "zshrc、zprofile、gitconfig を追加"
```

`.zprofile` と `.gitconfig` も、4 と同じ手順でリンクにしてください。うまくいかないときは、`rm ~/.zshrc`（リンクだけが消え、実体は残ります）と `mv ~/.zshrc.before-dotfiles ~/.zshrc` で元に戻せます。

## 5. 応用: install.sh を書く

新しい Mac で、4 の手順を1回で済ませるための `install.sh` を、bash で書いてください。

### 5.1 要件

1. 3.1節の表の「リンクを置く場所」の6つに、リポジトリの中のファイルを指すシンボリックリンクを作る。
2. **何度動かしても安全**であること。リンクを置く場所に、既にシンボリックリンクがあれば、`[ok]` と表示して何もしない。
3. リンクを置く場所に、リンクではないふつうのファイルがあれば、**消したり上書きしたりせず**、`[skip]` と、手で確かめてほしいことを表示する。
4. リンクを置く場所のフォルダが無ければ作る（例: `~/.config/git/`）。パスに空白が入っていても動く（`Application Support`）。
5. リポジトリの場所は `~/dev/dotfiles` に決めてよい。
6. macOS に最初から入っている bash 3.2 で動く（2節と第1章で学んだ書き方だけを使えば、そのまま動きます）。

### 5.2 ヒント

- 「リポジトリの中のファイルの名前」と「リンクを置く場所」を受け取って1つのリンクを作る関数 `link` を作り（2.4節）、6回呼ぶと短く書けます。
- 関数の中は、2.3節の `if` / `elif` / `else` で、「リンクがある」「ふつうのファイルがある」「何も無い」の3つに分けます。
- 変数を使うところは、すべて `"$dest"` のようにダブルクォートで囲みます（第1章4.3節）。囲まないと、`Application Support` の空白で2つの引数に分かれてしまいます。

実行の例:

```sh
$ bash install.sh
[ok]   /Users/alice/.zshrc
[link] /Users/alice/.zprofile -> /Users/alice/dev/dotfiles/zprofile
[skip] /Users/alice/.gitconfig にファイルがあります。中身を確かめて、別の名前に移してから、もう一度動かしてください
...
$ bash install.sh              # 2回目は、すべて [ok] か [skip]
```

### 5.3 確かめる

- [ ] `ls -l` で、表の6つの場所がすべてシンボリックリンクになっている
- [ ] 新しいターミナルを開いて、エラーが表示されない
- [ ] `which brew`、`which node`、`node -v` が、第2章のとおりの結果になる（第2章の練習問題10の `env-check.sh` を作った人は、それを動かす）
- [ ] 第1章の関数（11.3節の `mkcd`、練習問題9の `bak`）が使える
- [ ] `git config user.email` で、意図したメールアドレスが表示される
- [ ] `ssh -T git@github.com` が成功する
- [ ] VS Code の設定が反映されている
- [ ] `bash install.sh` を2回続けて動かしても、2回目は何も変わらない
- [ ] `git log -p | grep -i password` や `git log -p | grep -i token` で、秘密の情報が見つからない（`git log -p` は、すべてのコミットの差分。第3章4.5節）
- [ ] README.md に、新しい Mac での手順（第2章の練習問題8・第3章の手順の順番）が書かれている

できたら、GitHub に push します（第3章11.5節）。

```sh
$ git add -A && git commit -m "install.sh を追加"
$ gh repo create dotfiles --private --source=. --push
```

## 6. 発展（できなくても次に進んでかまいません）

1. **正しいリンクかを確かめる**: 要件2 では「リンクがあれば OK」としましたが、別の場所を指しているリンクかもしれません。`readlink "$dest"` の結果が、リポジトリの中のファイルのパスと同じときだけ `[ok]` にし、違うときは `[skip]` にしてください。
2. **バックアップに移す**: 要件3 で `[skip]` にしていたふつうのファイルを、`~/.dotfiles-backup/日時/`（日時は `date +%Y%m%d-%H%M%S`。第1章5.3節）というフォルダに `mv` で移してから、リンクを作るようにしてください。
3. **`--dry-run`**: `bash install.sh --dry-run` と動かしたときは、実際には何も変えず、「何をする予定か」だけを表示するようにしてください（`[[ "$1" == "--dry-run" ]]` で、1つ目の引数を調べられます）。
4. **新しい Mac のリハーサル**: macOS に新しいユーザーアカウントを作り、そのアカウントでログインして、README の手順だけで環境を整えられるか試してください（終わったらアカウントを消します）。手順の抜けが見つかったら、README を直します。
