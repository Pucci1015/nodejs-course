# 第1章 ターミナルとzshの基本

この章では、教材全体を通して毎日使う**ターミナル**の操作を、実際に打ちながら身につけます。ターミナルは、マウスでクリックする代わりに、文字でコマンドを打ってコンピュータを動かす道具です。
目標はコマンドの暗記ではなく、**自分が打ったコマンドが、どう読まれ、何が起きたのかを説明できること**です。ここがあいまいだと、後の章で `node: command not found` や `permission denied` が出たときに、原因を切り分けられません。

| フォルダ | 中身 |
| --- | --- |

> **読み方**
> - 「**手を動かす**」の所は、読むだけでなく、実際に打って動かしてください。練習問題は、そこで打ったコマンドや書いたスクリプトを広げていく問題です。
> - `$` から始まる行は「ターミナルに入力するコマンド」です。`$` 自体は入力しません。`$` の無い行は、表示される結果（出力）です。`#` から後ろは説明なので、打たなくてかまいません。
> - 実習は、教材のフォルダではなく `~/dev/ch01/` で行います（教材のフォルダは見本として残しておくため）。作業フォルダは、2.5節の「手を動かす」で作ります。それより前の1〜2節は、ファイルを作らないので、どこで打ってもかまいません。
> - 出力の例の `alice` は、ユーザー名の例です。自分の Mac では、自分のユーザー名になります。日付や数も、人によって違います。

## 1. ターミナル・シェル・zsh の関係

### 1.1 3つの言葉

| 用語 | 役割 | Mac での例 |
| --- | --- | --- |
| ターミナル（端末エミュレータ） | 文字を表示し、キーボードの入力を受け取る「窓」 | ターミナル.app、iTerm2、VS Code の統合ターミナル |
| シェル | 入力された文字を読み取って、プログラムを起動する「通訳」 | zsh（macOS の標準）、bash |
| コマンド | シェルが起動するプログラム、またはシェル自身の機能 | `ls`（プログラム）、`cd`（シェルの組み込みの機能） |

ターミナル.app は「アプリケーション → ユーティリティ」にあります。Spotlight（`⌘ + Space`）で「ターミナル」と打っても開けます。よく使うので、Dock に入れておくと便利です。

### 1.2 手を動かす: 最初のコマンドを打つ

ターミナルを開くと、`alice@MacBook-Air ~ %` のような行（**プロンプト**。入力を促す印）が出て、入力を待っています。「ユーザー名@コンピュータ名 今いるフォルダ %」の形で、`~` は「自分のホームフォルダ」です。この本文では、プロンプトを短く `$` と書きます。

次の3つを打ってみます。

```sh
$ whoami             # 自分のユーザー名
alice
$ echo こんにちは     # echo は、後ろに書いたものをそのまま表示する
こんにちは
$ echo $SHELL        # $SHELL は「SHELL という変数の中身」。ログインしたときに使うシェル
/bin/zsh
```

`echo $SHELL` では、シェルが `$SHELL` を中身（`/bin/zsh`）に置き換えてから `echo` に渡しています。この「シェルが先に置き換える」は、4節でくわしく見ます。

### 1.3 コマンドの形: コマンド名・オプション・引数

コマンドは、空白で区切った「単語」の並びです。

```sh
$ ls -l Desktop
```

| 部分 | 名前 | 意味 |
| --- | --- | --- |
| `ls` | コマンド名 | 何をするか（ここでは「一覧を表示する」） |
| `-l` | オプション | どのようにするか（ここでは「詳しく」）。`-` で始まる |
| `Desktop` | 引数（ひきすう） | 何に対してするか（ここでは「Desktop フォルダの中を」） |

- 1文字のオプションはまとめて書けます。`-l -a` は `-la` と同じです（順番は関係ありません）。
- `--help` のように、`--` と単語の長いオプションもあります。`-n 20` のように、後ろに値を取るものもあります。
- オプションの意味は、コマンドごとに違います。`ls` の `-l` と `grep` の `-l` は、まったく別の意味です。

**オプションを調べる**: `man コマンド名` で、マニュアルが開きます。`↓` かスペースキーで進み、`/` に続けて言葉を打つと探せます。`q` で終わります。全部を読む必要はありません。「この `-h` は何だろう」と思ったときに、そこだけを探して読みます。

```sh
$ man ls             # ls のマニュアル。/-h と打って Return で、-h の説明へ飛ぶ。q で終わる
```

### 1.4 手を動かす: type でコマンドの正体を調べる

```sh
$ type ls
ls is /bin/ls                  # ディスクの上にあるプログラム（/bin フォルダの ls というファイル）
$ type cd
cd is a shell builtin          # シェルの組み込みの機能
```

`ls` は `/bin/ls` という**ファイル**で、シェルはこれを別のプログラムとして起動します。動いているプログラムの1つ1つを**プロセス**と呼びます。

`cd` が組み込みなのには理由があります。もし `cd` が別のプロセスだったら、そのプロセスの中で移動して終わり、シェル自身の場所は変わりません。**今のシェルの状態を変えるものは、組み込みでなければならない**と覚えておくと、10節の `export` や11節の `source` が分かりやすくなります。

## 2. ファイルシステムとパス

### 2.1 フォルダの木

macOS のファイルは、すべて `/`（**ルート**）から始まる、1本の木の形に並んでいます。ターミナルでは「フォルダ」を**ディレクトリ**とも呼びます。

```
/
├── Applications/        アプリ
├── System/              macOS 本体（基本的に書き換えられない）
├── opt/homebrew/        Homebrew（第2章で入れる）
├── usr/bin/             macOS に最初から入っているコマンド（git など）
└── Users/
    └── alice/           ホームフォルダ（~ と書ける）
        ├── Desktop/
        ├── Documents/
        └── dev/         この教材の作業フォルダ（2.5節で作る）
```

### 2.2 パスの書き方

ファイルやフォルダの場所を表す文字列を、**パス**と呼びます。

- **絶対パス**: `/` から始まる。どこにいても同じ場所を指す。例: `/Users/alice/Desktop`
- **相対パス**: 今いる場所（**カレントディレクトリ**）からの道順。例: `Desktop/memo.txt`、`../other`

| 記号 | 意味 | 例 |
| --- | --- | --- |
| `~` | 自分のホームフォルダ（`/Users/alice`） | `~/Desktop` は `/Users/alice/Desktop` |
| `.` | 今いる場所 | `./script.sh` は「今いる場所の script.sh」 |
| `..` | 1つ上のフォルダ | `../..` は「2つ上」 |
| `/` | フォルダの区切り（先頭にあるときはルート） | `Desktop/memo.txt` |

### 2.3 手を動かす: pwd と cd で歩き回る

```sh
$ pwd                    # 今いる場所を表示する（print working directory）
/Users/alice
$ cd Desktop             # Desktop へ移動（相対パス）
$ pwd
/Users/alice/Desktop
$ cd ..                  # 1つ上へ
$ cd /usr/bin            # 絶対パスで移動
$ pwd
/usr/bin
$ cd -                   # 直前にいた場所へ戻る（移動した先を表示してくれる）
/Users/alice
$ cd                     # 何も書かなければ、ホームへ
```

**Tab キーで補完する**: パスを途中まで打って `Tab` を押すと、残りを入力してくれます。候補が複数あるときは、もう一度 `Tab` で一覧が出ます。**パスは手で全部打たず、Tab に任せる**と打ち間違いが減ります。

### 2.4 スペースや日本語を含むパス

シェルは**空白で単語を区切る**ので、空白を含む名前はそのまま書けません。

```sh
$ cd ~/My Documents          # だめ: "~/My" と "Documents" の2つの引数になる
$ cd ~/"My Documents"        # よい: クォート（" "）で1つの引数にまとめる
$ cd ~/My\ Documents         # よい: 空白の前に \ を付けて「ただの文字」にする（エスケープ）
```

`Tab` で補完すると、`\` は自動で付きます。また、**Finder のフォルダやファイルをターミナルのウィンドウにドラッグすると、そのパスが（エスケープ付きで）入力されます**。教材のフォルダのように、長くて日本語や空白を含むパスは、この方法で入れます。

### 2.5 手を動かす: 作業フォルダ ~/dev/ch01 を作る

この教材の実習は、すべて `~/dev/` の下で行います。理由は2つです。

- 教材のフォルダは「見本」として、きれいなまま残しておきたい（試して壊しても、見本と見比べられる）
- 教材を OneDrive や iCloud Drive などの同期フォルダに置いていると、第3部からの `npm install` で数万のファイルができ、同期がとても重くなる。`~/dev` は同期されない

この章の作業フォルダ `~/dev/ch01` を作り、教材の `samples` と `exercises` をコピーします。

```sh
$ mkdir -p ~/dev/ch01 && cd ~/dev/ch01
$ cp -R （ここに Finder から samples と exercises のフォルダをドラッグ） .
$ ls
exercises	samples
```

1. `cp -R ` まで打ちます（最後に空白を1つ）。
2. Finder で教材の `part01-mac-dev-env/ch01-terminal-zsh` を開き、`samples` と `exercises` の2つのフォルダを選んで、ターミナルのウィンドウにドラッグします。2つのパスが入力されます。
3. 最後に ` .`（空白とピリオド。「今いるフォルダへ」）を打って Return を押します。

| 部分 | 意味 |
| --- | --- |
| `mkdir -p ~/dev/ch01` | フォルダを作る（make directory）。`-p` は途中の `~/dev` もまとめて作り、もうあってもエラーにしない |
| `&&` | 左が成功したときだけ、右を動かす（7.2節） |
| `cd ~/dev/ch01` | 作ったフォルダへ移動する |
| `cp -R 元… 先` | コピーする。`-R` は「フォルダを中身ごと」（3.4節） |

**この章のコマンドは、ことわりが無ければ `~/dev/ch01` で打ちます。** 新しいターミナルを開いたら、まず `cd ~/dev/ch01` してください。

## 3. ファイル操作の基本

### 3.1 手を動かす: 練習用のフォルダを作る

[samples/make-playground.sh](samples/make-playground.sh) は、練習用のファイルとフォルダを `~/dev/ch01/playground` に作るスクリプトです（中身は9節を学ぶと読めます）。

```sh
$ cd ~/dev/ch01
$ bash samples/make-playground.sh       # bash でスクリプトを動かす（9節）
作成しました: /Users/alice/dev/ch01/playground
中身を見るには: ls -laR "/Users/alice/dev/ch01/playground"
$ cd playground
```

もう一度動かすと「既に存在します」と言って何もしません（作ったものを上書きしないため）。作り直したいときは、中身を確かめてから消します（3.5節）。

### 3.2 手を動かす: ls で一覧を見る

```sh
$ ls
LICENSE			docs			logs			memo.txt		src
My Documents		draft final v2.txt	meeting notes.txt	photos			todo.txt
$ ls -la
total 24
drwxr-xr-x  13 alice  staff   416 11  7 10:00 .
drwxr-xr-x   5 alice  staff   160 11  7 10:00 ..
-rw-r--r--   1 alice  staff     0 11  7 10:00 .hidden-config
-rw-r--r--   1 alice  staff    13 11  7 10:00 LICENSE
drwxr-xr-x   4 alice  staff   128 11  7 10:00 My Documents
...
$ ls photos                   # パスを書くと、そのフォルダの中を表示する
IMG_0001.jpg	IMG_0002.jpg	IMG_0103.jpg	screenshot.png
```

| オプション | 意味 |
| --- | --- |
| `-l` | 詳しく表示する（1行に1つ。権限・持ち主・大きさ・更新した日時） |
| `-a` | `.` で始まる**隠しファイル**も表示する（all） |
| `-h` | 大きさを `1.2K` のように読みやすくする（`-l` と一緒に使う。human-readable） |
| `-t` | 更新した日時の新しい順に並べる（time） |
| `-F` | フォルダの後ろに `/`、実行できるファイルの後ろに `*` を付ける |

`-l` の1行は、左から「種類と権限（8節）・リンクの数（気にしなくてよい）・持ち主・グループ・大きさ（バイト）・更新した日時・名前」です。最初の文字が `d` ならフォルダ、`-` ならファイルです。

`.` で始まる名前（`.hidden-config` や11節の `.zshrc`）は、設定のファイルによく使われます。Finder では `⌘ + Shift + .` で隠しファイルの表示を切り替えられます。

### 3.3 手を動かす: mkdir と touch で作る

```sh
$ mkdir backup                 # backup というフォルダを作る
$ mkdir backup/2026/11         # 途中の 2026 がまだ無いので失敗する
mkdir: backup/2026: No such file or directory
$ mkdir -p backup/2026/11      # -p: 途中のフォルダもまとめて作る
$ touch notes.txt              # 空のファイルを作る。もうあれば、更新した日時だけを今にする
$ ls -F backup                 # -F: フォルダの後ろに / を付ける
2026/
```

### 3.4 手を動かす: cp と mv でコピー・移動する

```sh
$ cp memo.txt memo-copy.txt          # memo.txt をコピーして memo-copy.txt を作る
$ mv memo-copy.txt memo2.txt         # 名前を変える
$ mv memo2.txt backup/               # backup フォルダの中へ移動する
$ cp docs backup/                    # フォルダは、そのままではコピーされない
cp: docs is a directory (not copied).
$ cp -R docs backup/                 # -R: フォルダを中身ごとコピーする
$ ls backup
2026	docs	memo2.txt
```

| 書き方 | 意味 |
| --- | --- |
| `cp 元 先` / `mv 元 先` | 先に「元」、後に「先」を書く。先がフォルダなら、その中へ同じ名前で |
| `mv` | 「移動」と「名前の変更」の両方に使う。名前の変更は「同じ場所の別の名前への移動」だから |
| `-R`（`cp`） | フォルダを中身ごと（recursive） |
| `-i` | 先に同じ名前があるとき、上書きする前に `overwrite …? (y/n [n])` と聞く（interactive）。付けないと**何も聞かずに上書きする** |

### 3.5 手を動かす: rm で消す

```sh
$ rm notes.txt                 # ファイルを消す
$ rm -i backup/memo2.txt       # -i: 消す前に確かめる。y で消す、n でやめる
remove backup/memo2.txt? y
$ rm -r backup                 # -r: フォルダを中身ごと消す（recursive）
```

> **注意**: `rm` で消したものは**ゴミ箱に入らず**、元に戻せません。特に `rm -r` はフォルダの中身をすべて消します。慣れるまでは `-i` を付け、消す前に `ls` で中身を確かめてください（11.3節で、`rm` をいつも `-i` 付きにする設定を作ります）。

### 3.6 手を動かす: cat・less・head・tail で中身を見る

```sh
$ cat LICENSE                  # 中身を全部表示する
no extension
$ less logs/app-3.log          # 長いファイルを1画面ずつ見る。スペースで次へ、q で終わる
$ head -n 3 logs/app-3.log     # 最初の3行だけ（-n を省くと10行）
log line from day 3
log line from day 3
log line from day 3
$ tail -n 2 logs/error.log     # 最後の2行だけ
error: something failed
```

`tail -f ファイル` は、最後を表示した後も待ち続け、足された行を表示し続けます（`Ctrl + C` で止める）。動いているサーバのログを見張るときに使います。

### 3.7 この節のコマンドのまとめ

| コマンド | 意味 | よく使うオプション |
| --- | --- | --- |
| `ls` | 一覧を表示 | `-l`、`-a`、`-h`、`-t`、`-F` |
| `mkdir` | フォルダを作る | `-p`（途中も作る） |
| `touch` | 空のファイルを作る（あれば、日時だけ更新） | |
| `cp` | コピー | `-R`（フォルダごと）、`-i`（上書きの前に確認） |
| `mv` | 移動・名前の変更 | `-i` |
| `rm` | 消す（ゴミ箱に入らない） | `-r`（フォルダごと）、`-i`（確認） |
| `cat` / `less` | 全部表示 / 1画面ずつ表示（`q` で終わる） | |
| `head` / `tail` | 最初 / 最後の数行を表示 | `-n 数`、`tail -f` |

macOS のコマンドは **BSD 版**で、Linux の **GNU 版**とオプションが少し違うことがあります（`sed -i`、`date` など）。インターネットで見つけたコマンドが動かないときは、`man` で Mac のマニュアルを確かめます。

## 4. グロブ（ワイルドカード）とクォート

### 4.1 手を動かす: シェルがグロブを展開するのを見る

この章でいちばん大事な考え方です。シェルは、打たれた文字をそのままコマンドに渡すのではなく、**コマンドを動かす前に、特別な記号を書き換えて（展開して）から**渡します。

その1つが**グロブ**（ワイルドカード）です。`echo` は受け取ったものを表示するだけなので、展開の結果を見るのにちょうどよい道具です。

```sh
$ cd ~/dev/ch01/playground
$ echo *.txt
draft final v2.txt meeting notes.txt memo.txt todo.txt
$ echo photos/IMG_00??.jpg
photos/IMG_0001.jpg photos/IMG_0002.jpg
$ echo src/**/*.js
src/app.js src/models/task.js src/routes/index.js src/routes/tasks.js
$ echo *.xyz
zsh: no matches found: *.xyz
$ bash -c 'echo *.xyz'             # bash -c '…' は、bash に1行だけ動かさせる
*.xyz
```

| 書き方 | 意味 | 例 |
| --- | --- | --- |
| `*` | 何文字でもよい（0文字も） | `*.txt` は「`.txt` で終わる名前すべて」 |
| `?` | ちょうど1文字 | `IMG_00??.jpg` |
| `[abc]`、`[0-9]` | かっこの中のどれか1文字 | `app-[12].log` |
| `**/` | 何段下のフォルダでもよい（0段も。zsh の機能） | `src/**/*.js` |
| `{a,b}` | `a` と `b` の両方を作る（ブレース展開。ファイルが無くても作られる） | `mkdir -p src/{routes,models}` |

- `echo` は `*.txt` という文字を受け取ったのではありません。シェルが先に、あてはまるファイル名の並びに置き換えています。`rm *.txt` も同じで、シェルが並べた名前を `rm` がまとめて消します。
- あてはまるものが無いとき、zsh は `no matches found` で**コマンドを動かしません**。bash は、グロブをそのままの文字として渡します。
- このため zsh では、`curl https://example.com/?q=1` のように URL に `?` があると、グロブとして読まれてエラーになります。URL はクォート（4.3節）で囲みます。

### 4.2 手を動かす: 変数

`名前=値` で**変数**に値を入れ、`$名前` で使います。`=` の前後に**空白を入れてはいけません**（空白があると、`名前` というコマンドを動かそうとします）。

```sh
$ name="My Documents"
$ echo $name
My Documents
$ name = "x"                 # 空白があると失敗する
zsh: command not found: name
```

`$name` も、グロブと同じく、シェルがコマンドを動かす前に中身に置き換えます。

### 4.3 手を動かす: クォートで展開を止める

| 書き方 | `$変数` を置き換えるか | グロブを展開するか | 使いどころ |
| --- | --- | --- | --- |
| `'...'`（シングルクォート） | しない | しない | 書いた文字を、そのまま渡したいとき |
| `"..."`（ダブルクォート） | する | しない | 変数を使うが、空白で分けたくないとき |
| クォートなし | する | する | |

```sh
$ echo '$name'        # シングルクォートの中は、そのままの文字
$name
$ echo "$name"        # ダブルクォートの中では、変数は置き換わる
My Documents
$ echo "*.txt"        # ダブルクォートの中では、グロブは展開されない
*.txt
$ ls "$name"          # "My Documents" が1つの引数として ls に渡る
履歴書.docx	写真 一覧.txt
```

クォートなしの `ls $name` は、zsh では動きますが、bash では `My` と `Documents` の2つに分かれてしまいます。シェルスクリプト（9節）は bash で書くので、**変数は、いつも `"$var"` とダブルクォートで囲む**習慣をつけます。

## 5. 標準入力・標準出力・標準エラー出力

### 5.1 3つの流れ

コマンド（プログラム）は、動き始めたときに3つの流れ（**ストリーム**）を持っています。

| 番号 | 名前 | 何が流れるか | 何もしなければ |
| --- | --- | --- | --- |
| 0 | **標準入力**（stdin） | プログラムが読むもの | キーボードから |
| 1 | **標準出力**（stdout） | 結果 | 画面へ |
| 2 | **標準エラー出力**（stderr） | エラーや途中経過の知らせ | 画面へ |

左の番号を**ファイルディスクリプタ**と呼びます。stdout と stderr は、どちらも画面に出るので見た目では区別がつきませんが、**別の流れ**です。結果は stdout、エラーは stderr に出すのが決まりで、こうしておくと「結果だけをファイルに保存し、エラーは画面で見る」ができます。Node.js では `console.log` が stdout、`console.error` が stderr に出ます（第3部）。

### 5.2 手を動かす: リダイレクトで行き先を変える

[samples/streams-demo.sh](samples/streams-demo.sh) は、stdout と stderr に1行ずつ出して、終了ステータス 3（7節）で終わるスクリプトです。

```sh
$ cd ~/dev/ch01
$ bash samples/streams-demo.sh
これは stdout（標準出力）です
これは stderr（標準エラー出力）です
$ bash samples/streams-demo.sh > out.txt      # stdout はファイルへ。画面には stderr だけ
これは stderr（標準エラー出力）です
$ cat out.txt
これは stdout（標準出力）です
$ bash samples/streams-demo.sh 2> err.txt     # stderr はファイルへ。画面には stdout だけ
これは stdout（標準出力）です
$ bash samples/streams-demo.sh &> all.txt     # 両方ファイルへ。画面には何も出ない
$ bash samples/streams-demo.sh 2> /dev/null   # stderr を捨てる
これは stdout（標準出力）です
$ rm out.txt err.txt all.txt                  # 片付け
```

| 書き方 | 意味 |
| --- | --- |
| `cmd > file` | stdout を file に書く。file があれば、中身を消して**上書き**する |
| `cmd >> file` | stdout を file の**最後に足す**（追記） |
| `cmd 2> file` | stderr を file に書く（`2` は stderr の番号） |
| `cmd &> file` | stdout と stderr の両方を file に書く |
| `cmd > file 2>&1` | stdout を file に書き、stderr も「今の stdout と同じ行き先」にする（`&>` と同じ結果） |
| `cmd < file` | file の中身を stdin として読ませる |
| `cmd > /dev/null` | 出力を捨てる（`/dev/null` は、書いたものが消える特別なファイル） |
| `echo 文 >&2` | この `echo` の stdout を stderr に向ける。エラーのメッセージを出すときの決まった書き方 |

> **注意**: `>` は、ファイルの中身を**何も聞かずに消して**から書きます。足したいときは `>>` です。

`2>&1` は「2番（stderr）の行き先を、**その時点で**1番（stdout）が向いている先と同じにする」という意味で、リダイレクトは**左から順に**処理されます。順番を逆にするとどうなるかは、練習問題11で確かめます。

### 5.3 手を動かす: ヒアドキュメントとコマンド置換

**ヒアドキュメント**は、複数の行をそのまま stdin として渡す書き方です。`cat` はファイル名を渡さないと stdin を読むので、`>` と組み合わせると「打った行でファイルを作る」になります。

```sh
$ cat > hello.txt <<'EOF'      # 次の行から、EOF とだけ書いた行の前までを stdin にする
こんにちは
二行目
EOF
$ cat hello.txt
こんにちは
二行目
```

`EOF` は終わりの印で、別の言葉でもかまいません。`'EOF'` とクォートすると、中の `$` が置き換えられず、書いたとおりに入ります（9節でスクリプトを作るときに使います）。

**コマンド置換** `$( )` は、かっこの中のコマンドを動かし、その stdout を文字列として使う書き方です。

```sh
$ date +%Y-%m-%d                # + の後ろで形を決める。%Y 年、%m 月、%d 日
2026-11-07
$ today=$(date +%Y-%m-%d)       # date の出力を、変数 today に入れる
$ echo "今日は $today です"
今日は 2026-11-07 です
$ echo "ここには $(ls | wc -l) 個あります"    # パイプ（6節）も入れられる
```

`date` の形には、ほかに `%H`（時）、`%M`（分）、`%S`（秒）があります。`date +%Y%m%d-%H%M` なら `20261107-1000` です。

## 6. パイプで小さな道具をつなぐ

### 6.1 手を動かす: 最初のパイプ

`|`（**パイプ**。`Shift + ¥`）は、左のコマンドの stdout を、右のコマンドの stdin につなぎます。

```sh
$ cd ~/dev/ch01
$ ls samples | wc -l           # ls の結果を、wc -l（行を数える）に渡す → ファイルの数
      10
```

「1つのことだけをうまくやる小さな道具を作り、組み合わせる」のが Unix（Mac や Linux の元になった OS）の考え方で、パイプはそのための仕組みです。次の道具は、どれも、ファイル名を渡せばそのファイルを、渡さなければ stdin を読みます。

| コマンド | 働き |
| --- | --- |
| `grep 言葉` | その言葉を含む行だけを通す |
| `wc -l` | 行の数を数える（word count の line） |
| `tr` | 文字を置き換える・消す |
| `sort` | 行を並べ替える |
| `uniq` | **隣り合った**同じ行を1つにまとめる |
| `cut` | 区切り文字で分けて、決めた列だけを取り出す |
| `awk` | 列を取り出す、条件で絞る、合計する（6.4節） |

### 6.2 手を動かす: 道具を1つずつ試す

[samples/access.log](samples/access.log) は、Web サーバの**アクセスログ**（だれが、いつ、どのページを見に来たかの記録）の例で、80行あります。

```sh
$ head -n 2 samples/access.log
203.0.113.5 - - [04/Nov/2026:09:03:15 +0900] "GET /static/style.css HTTP/1.1" 200 911
203.0.113.5 - - [04/Nov/2026:09:04:22 +0900] "GET /static/app.js HTTP/1.1" 304 0
```

**grep と wc**:

```sh
$ grep POST samples/access.log | head -n 2   # POST を含む行（の最初の2行）
$ grep -c POST samples/access.log            # -c: 行の代わりに、あてはまった行の数（count）
12
$ grep -v GET samples/access.log | wc -l     # -v: 含まない行を通す（invert）
      13
$ grep -i post samples/access.log | wc -l    # -i: 大文字と小文字を区別しない（ignore case）
      12
$ wc -l < samples/access.log                 # < で stdin から読ませると、ファイル名を表示しない
      80
```

Mac の `wc` は、数の前に空白を入れて表示します。

**tr**: `tr 元の文字 新しい文字` で置き換え、`-d` で消します（delete）。

```sh
$ echo "a:b:c" | tr ':' '\n'        # : を改行（\n）に置き換える
a
b
c
$ echo "a b c" | tr -d ' '          # 空白を消す
abc
$ echo "a1b22" | tr -d '0-9'        # 0-9 は「0〜9 のすべての数字」。数字を消す
ab
```

**sort と uniq**:

```sh
$ printf 'b\na\nb\nb\n' | sort | uniq -c   # printf は \n を改行にして表示する
   1 a
   3 b
$ printf 'b\na\nb\nb\n' | uniq -c          # sort しないと、離れた b はまとまらない
   1 b
   1 a
   2 b
```

| オプション | 意味 |
| --- | --- |
| `uniq -c` | まとめた数を前に付ける（count） |
| `sort -n` | 数として並べる（付けないと文字として並べるので、`10` が `9` より前になる） |
| `sort -r` | 逆の順（reverse）。`sort -rn` は「数として大きい順」 |
| `sort -k 2` | 2列目で並べる（key） |

**cut**: `cut -d 区切り -f 番号` で、その番号の列だけを取り出します（delimiter、field）。

```sh
$ echo "2026-11-07" | cut -d '-' -f 1           # - で区切った1番目
2026
$ head -n 1 samples/access.log | cut -d ' ' -f 1   # 空白で区切った1番目（IP アドレス）
203.0.113.5
$ head -n 1 samples/access.log | cut -d: -f2       # : で区切った2番目（日時の「時」）
09
```

### 6.3 手を動かす: 1段ずつ組み立てる

アクセスログを空白で区切ると、次の列に分かれます。

| 列（awk の `$n`） | 内容 | 例 |
| --- | --- | --- |
| `$1` | 接続してきたコンピュータの IP アドレス | `203.0.113.5` |
| `$4` `$5` | 日時 | `[04/Nov/2026:09:00:01` `+0900]` |
| `$6` | メソッド（先頭に `"` が付く） | `"GET` |
| `$7` | パス（どのページか） | `/` |
| `$9` | ステータスコード（200 は成功、404 は見つからない、など） | `200` |
| `$10` | 応答の大きさ（バイト） | `5123` |

「どのページがよく見られているか」を、**1段ずつ足して、毎回出力を確かめながら**組み立てます。

```sh
$ awk '{print $7}' samples/access.log | head -n 3                    # ① 7列目（パス）だけにする
/static/style.css
/static/app.js
/
$ awk '{print $7}' samples/access.log | sort | head -n 3             # ② 並べ替えて、同じものを隣どうしに
/
/
/
$ awk '{print $7}' samples/access.log | sort | uniq -c | head -n 3   # ③ まとめて数える
  11 /
   4 /about
   4 /admin
$ awk '{print $7}' samples/access.log | sort | uniq -c | sort -rn | head -n 5   # ④ 多い順に5つ
  18 /tasks
  12 /static/app.js
  11 /
   7 /api/report
   6 /login
```

一度に長いパイプを書くと、結果がおかしいときにどこが悪いのか分かりません。①〜④のように1段ずつ足せば、思ったのと違った段がすぐに分かります。前のコマンドは `↑` キーで呼び出して、後ろに足すと楽です。

### 6.4 手を動かす: awk で列と条件を扱う

`awk` は、1行ずつ読んで空白で列に分け、列ごとに処理する道具です。この教材で使うのは次の書き方だけです。

| 書き方 | 意味 |
| --- | --- |
| `awk '{print $7}'` | 7列目を表示する。`{ }` の中が「1行ごとにすること」 |
| `awk '{print $1, $9}'` | 1列目と9列目を、空白を挟んで表示する |
| `awk '{print "IP:", $1}'` | `"…"` で囲んだ文字と列を並べて表示する（`IP: 203.0.113.5`） |
| `awk '$9 == 404'` | 9列目が 404 の行だけを表示する（`{ }` を省くと、行をそのまま表示） |
| `awk '$9 == 404 {print $7}'` | 9列目が 404 の行の、7列目だけを表示する |
| `awk '{sum += $10} END {print sum}'` | 10列目を足していき、全部読んだ後（`END`）に1回だけ表示する |

- awk に渡すものは、シェルに `$7` を変数として置き換えられないよう、**シングルクォートで囲みます**（4.3節）。
- 条件には `==`（等しい）、`!=`（等しくない）、`>=`（以上）、`<`（より小さい）が使え、`&&`（かつ）でつなげます。`$9 >= 400 && $9 < 500` は「4xx」の行です。
- 変数は前もって用意せずに使えます（最初は 0）。`NR` は「ここまでに読んだ行の数」で、`END` の中では全体の行数です。

```sh
$ awk '{print $1, $9}' samples/access.log | head -n 2     # IP とステータスコード
203.0.113.5 200
203.0.113.5 304
$ awk '$9 == 404' samples/access.log | wc -l             # 404 の件数
      10
$ awk '$9 >= 500' samples/access.log | wc -l             # 5xx の件数
       7
$ awk '{sum += $10} END {print sum}' samples/access.log        # 10列目（大きさ）の合計
373903
$ awk '{sum += $10} END {print sum / NR}' samples/access.log   # 平均（合計 ÷ 行数）
4673.79
```

## 7. 終了ステータスと `&&` / `||`

### 7.1 手を動かす: $? で終了ステータスを見る

コマンドは、終わるときに 0〜255 の数（**終了ステータス**）を返します。**0 が成功、それ以外は失敗**です。直前のコマンドの終了ステータスは `$?` で見られます。

```sh
$ ls /存在しない
ls: /存在しない: No such file or directory
$ echo $?
1
$ ls / > /dev/null
$ echo $?
0
$ grep POST samples/access.log > /dev/null; echo $?    # ; は「前が成功しても失敗しても、次を動かす」
0
$ grep PUT samples/access.log > /dev/null; echo $?     # grep は、見つからなければ 1
1
```

画面のメッセージは人が読むためのもので、プログラムが読むには向きません。終了ステータスがあれば、スクリプトやほかのプログラムが「前のコマンドは成功したか」で次にすることを決められます。`grep` は「見つかった 0 / 見つからない 1 / エラー 2」のように、数を使い分けます。

### 7.2 手を動かす: `&&`・`||`・`( )` でつなぐ

```sh
$ mkdir -p tmp && cd tmp && pwd                    # && : 左が成功したときだけ、右を動かす
/Users/alice/dev/ch01/tmp
$ cd ..
$ cd nowhere || echo "移動できませんでした" >&2     # || : 左が失敗したときだけ、右を動かす
cd: no such file or directory: nowhere
移動できませんでした
$ (cd samples && ls | wc -l); pwd                  # ( ) の中は別のシェル（サブシェル）で動く
      10
/Users/alice/dev/ch01
```

`( )` で囲むと、その中だけ別のシェル（**サブシェル**）で動きます。中で `cd` しても、終わった後は元の場所のままです（1.4節の「別のプロセスでは今のシェルの場所は変わらない」を、わざと使う書き方です）。

### 7.3 パイプの終了ステータス

パイプ全体の終了ステータスは、ふつうは**最後のコマンドのもの**です。`grep 言葉 無いファイル | wc -l` は、`grep` が失敗しても `wc` が成功するので 0 になります。途中の失敗にも気づきたいときは、9.2節の `set -o pipefail` を使います。

テストは失敗すると 0 以外を返し、CI（第11部）はそれを見て「失敗」と判断します。Node.js では `process.exitCode = 1` で返せます（第3部）。

## 8. 権限（パーミッション）

### 8.1 ls -l の権限の読み方

ファイルには「だれが、何をしてよいか」という**権限**が付いています。`ls -l` の左の10文字です。

```
-  rwx  r-x  r-x
│   │    │    └ その他のユーザー: 読む・実行する
│   │    └ グループ（staff）の人: 読む・実行する
│   └ 持ち主（alice）: 読む・書く・実行する
└ 種類: - ファイル / d フォルダ / l シンボリックリンク（別の場所を指す印）
```

| 記号 | 数 | ファイルでの意味 | フォルダでの意味 |
| --- | --- | --- | --- |
| `r` | 4 | 読める（read） | 中の一覧を見られる |
| `w` | 2 | 書き換えられる（write） | 中にファイルを作ったり、消したりできる |
| `x` | 1 | 実行できる（execute） | 中に入れる（`cd` できる） |
| `-` | 0 | その権限が無い | |

3文字ずつ数を足して表せます。`rwx` = 4+2+1 = 7、`r-x` = 5、`rw-` = 6、`r--` = 4 なので、`rwxr-xr-x` は `755`、`rw-r--r--` は `644`、`rw-------` は `600` です。**グループ**はユーザーをまとめたもので、Mac の普通のユーザーは `staff` に入っています。

ファイルを消せるかどうかは、**ファイル自身ではなく、入っているフォルダの `w`** で決まります。「消す」は「フォルダの一覧を書き換える」ことだからです。

### 8.2 手を動かす: chmod で権限を変える

```sh
$ cd ~/dev/ch01/playground
$ touch run.sh secret.txt
$ ls -l run.sh
-rw-r--r--  1 alice  staff  0 11  7 10:00 run.sh
$ chmod +x run.sh              # 記号で: 全員に x（実行）を足す
$ ls -l run.sh
-rwxr-xr-x  1 alice  staff  0 11  7 10:00 run.sh
$ chmod 600 secret.txt         # 数で: rw------- にする（持ち主だけが読み書きできる）
$ ls -l secret.txt
-rw-------  1 alice  staff  0 11  7 10:00 secret.txt
$ chmod go-w,u+x secret.txt    # 記号で: グループとその他から w を外し、持ち主に x を足す
```

記号で書くときは「だれに」「足す・外す・決める」「何を」の順です。

| だれに | 意味 | | 足す・外す | 意味 |
| --- | --- | --- | --- | --- |
| `u` | 持ち主（user） | | `+` | 足す |
| `g` | グループ（group） | | `-` | 外す |
| `o` | その他（other） | | `=` | ちょうどこれにする |
| `a`、または書かない | 全員（all） | | | |

### 8.3 sudo は最後の手段

`sudo` を前に付けると、そのコマンドを、何でもできる管理者（**root**）として動かします（Mac のログインのパスワードを聞かれます）。

「`permission denied` が出たら `sudo` を付ける」は、危ない癖です。特に `sudo npm install -g …` や `sudo brew …` は、root が持ち主のファイルを作ってしまい、後で普通のユーザーとして操作できなくなる原因になります。第2章で入れる Homebrew と mise は、**sudo なしで使えるように作られています**。`permission denied` が出たら、まず `ls -l` で「そのファイルはだれの持ち物か」と「どこに書こうとしているか」を確かめます。

### 8.4 macOS 特有の属性

`ls -l` の権限の最後に `@` が付くことがあります。**拡張属性**（ファイルに付けた追加の情報）がある印です。インターネットからダウンロードしたファイルには `com.apple.quarantine` が付き、初めて開くときの「開いてもよいですか？」のもとになります（`ls -l@ ファイル` で見られます）。

また、ターミナルから `~/Desktop` や `~/Documents` を初めて操作すると、「"ターミナル"がフォルダにアクセスしようとしています」と出ることがあります。これは Unix の権限とは別の、macOS のプライバシーを守る仕組みです（システム設定 → プライバシーとセキュリティ）。

## 9. シェルスクリプトを書く

コマンドを1つのファイルにまとめたものを**シェルスクリプト**と呼びます。同じ手順を何度も打つ代わりに、ファイルを1つ動かせば済むようになります。

> **ファイルを書く道具**: この節の短いスクリプトは、5.3節のヒアドキュメントで作ります。VS Code が入っていれば（第4章1節）、`code ファイル名` で開いて書いてもかまいません。

### 9.1 手を動かす: 最初のスクリプト

```sh
$ cd ~/dev/ch01
$ cat > hello.sh <<'EOF'
#!/usr/bin/env bash
echo "こんにちは、$USER さん"
echo "今は $(pwd) にいます"
EOF
$ bash hello.sh                  # bash にファイルを読ませて、書いてあるコマンドを順に動かす
こんにちは、alice さん
今は /Users/alice/dev/ch01 にいます
$ ./hello.sh                     # ファイルの名前だけで動かすには、実行の権限が要る
zsh: permission denied: ./hello.sh
$ chmod +x hello.sh
$ ./hello.sh
こんにちは、alice さん
今は /Users/alice/dev/ch01 にいます
```

`./` が要る理由は、10.2節の PATH で説明します。

### 9.2 shebang と set

1行目の `#!/usr/bin/env bash` は **shebang**（シバン）と呼び、「このファイルを何で動かすか」を書きます。`./hello.sh` で動かすと、Mac はこの1行目を見て bash で動かします。必ず1行目に書きます。

教材のスクリプトは、2行目に次の1行を書いていることが多いです。`#` から行の最後までは**コメント**で、シェルは読み飛ばします。

```bash
set -euo pipefail
# -e: どこかのコマンドが失敗したら、そこで止まる（失敗したまま次に進まない）
# -u: 値を入れていない変数を使ったら、エラーにする（打ち間違いに気づける）
# -o pipefail: パイプの途中のコマンドが失敗しても、失敗として扱う（7.3節）
```

**この教材のスクリプトは bash で書きます**（人が打つときは zsh）。サーバ（Linux）や CI でもそのまま動くからです。macOS の `/bin/bash` は古い 3.2 という版なので、教材のスクリプトは 3.2 でも動く書き方にしています。

### 9.3 手を動かす: 引数を読み、条件で分ける

スクリプトに渡した引数は、特別な変数で読めます。

| 書き方 | 意味 |
| --- | --- |
| `$1`、`$2`、… | 1つ目、2つ目、…の引数 |
| `$#` | 引数の数 |
| `${1:-既定の値}` | 1つ目の引数。無ければ「既定の値」 |
| `$0` | スクリプト自身の名前 |

ファイルの行を数える `count.sh` を書きます。

```sh
$ cat > count.sh <<'EOF'
#!/usr/bin/env bash
if [[ $# -lt 1 ]]; then
  echo "使い方: $0 ファイル" >&2
  exit 1
fi
if [[ ! -f "$1" ]]; then
  echo "ファイルがありません: $1" >&2
  exit 1
fi
echo "$1 は $(wc -l < "$1" | tr -d ' ') 行です"
EOF
$ bash count.sh samples/access.log
samples/access.log は 80 行です
$ bash count.sh; echo "exit=$?"
使い方: count.sh ファイル
exit=1
$ bash count.sh nothing.txt 2> /dev/null; echo "exit=$?"
exit=1
```

| 書き方 | 意味 |
| --- | --- |
| `if [[ 条件 ]]; then … fi` | 条件が正しいときだけ、`then` と `fi` の間を動かす（`fi` は `if` を逆から書いたもの） |
| `else` | `if [[ … ]]; then A; else B; fi` で、正しくないときに B |
| `exit 数` | スクリプトをそこで終わらせ、その数を終了ステータスにする。最後まで進んだら、最後のコマンドの終了ステータスになる |
| `wc -l < "$1" \| tr -d ' '` | ファイル名を出さずに行を数え（5.2節）、前の空白を消す（6.2節） |

条件の書き方:

| 条件 | 正しいとき |
| --- | --- |
| `[[ -f "$file" ]]` | ファイルがある（file） |
| `[[ -d "$dir" ]]` | フォルダがある（directory） |
| `[[ -z "$s" ]]` | 文字列が空（zero） |
| `[[ -n "$s" ]]` | 文字列が空でない（non-zero） |
| `[[ "$a" == "$b" ]]` / `[[ "$a" != "$b" ]]` | 2つの文字列が同じ / 違う |
| `[[ $n -lt 1 ]]` | 数が 1 より小さい（`-lt` less than。ほかに `-gt` より大きい、`-eq` 等しい） |
| `[[ ! 条件 ]]` | 条件が正しくない |

完成形は [samples/count.sh](samples/count.sh) です。うまく動かないときは比べてください。

### 9.4 手を動かす: for でくり返す

`for 変数 in 並び; do … done` は、並びの1つ1つを変数に入れて、`do` と `done` の間をくり返します。フォルダの中のファイルを、行数つきで並べる `list.sh` を書きます。

```sh
$ cat > list.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
target="${1:-.}"                 # 1つ目の引数。無ければ "."（今いる場所）
for f in "$target"/*; do
  if [[ -f "$f" ]]; then
    echo "$(basename "$f"): $(wc -l < "$f" | tr -d ' ') 行"
  fi
done
EOF
$ bash list.sh playground/logs
app-1.log: 200 行
app-2.log: 400 行
app-3.log: 600 行
error.log: 1 行
```

- `"$target"/*` はグロブ（4.1節）で、フォルダの中のものに展開されます。フォルダは `-f` で飛ばしています。
- `basename パス` は、パスから最後の名前だけを取り出すコマンドです（`basename /a/b/c.txt` は `c.txt`）。

完成形は [samples/list.sh](samples/list.sh) です。

### 9.5 スクリプトが動かないときの3つの原因

| 原因 | 症状 | 調べ方 | 直し方 |
| --- | --- | --- | --- |
| 実行の権限が無い | `./x.sh` で `permission denied` | `ls -l x.sh` で `x` が無い | `chmod +x x.sh` |
| shebang が無い | `./x.sh` のとき、どのシェルで動くかが、呼び出した側しだいになる | `head -n 1 x.sh`（1行目を見る） | 1行目に `#!/usr/bin/env bash` を書く |
| 改行コードが CRLF | `$'\r': command not found` や、`cd: $'~\r'` のように、行の最後に見えない `\r` が付いたエラー | `file x.sh` が `with CRLF line terminators` と表示する。`cat -e x.sh` で行の最後が `^M$` | `tr -d '\r' < x.sh > fixed.sh` で `\r` を消した別のファイルを作る |

- `file` は、中身を見てファイルの種類を表示するコマンドです。`cat -e` は、見えない文字を記号にして表示します（行の終わり LF を `$`、CR を `^M`）。
- **改行コード**は、行の終わりを表す見えない文字です。Mac や Linux は LF（`\n`）、Windows は CR と LF（`\r\n`）を使います。Windows で作られたファイルをそのまま使うと、bash には行の最後に余計な `\r` が付いて見えます。

## 10. 環境変数と PATH

### 10.1 手を動かす: シェル変数と環境変数

4.2節の変数には2つの種類があります。**シェル変数**はそのシェルの中だけで使え、`export` した**環境変数**は、そのシェルから起動するプログラム（子のプロセス）にもコピーが渡ります。

確かめるために、環境変数 `GREETING` を表示するだけのスクリプトを書きます。

```sh
$ cd ~/dev/ch01
$ cat > greet.sh <<'EOF'
#!/usr/bin/env bash
echo "GREETING は「${GREETING:-（なし）}」です"
EOF
$ GREETING=hello                 # シェル変数
$ echo $GREETING                 # このシェルの中では見える
hello
$ bash greet.sh                  # 子のプロセス（bash）には渡らない
GREETING は「（なし）」です
$ export GREETING                # 環境変数にする
$ bash greet.sh
GREETING は「hello」です
$ GREETING=やあ bash greet.sh    # そのコマンドにだけ渡す
GREETING は「やあ」です
$ unset GREETING                 # 変数を消す
```

| 書き方 | 意味 |
| --- | --- |
| `名前=値` | シェル変数を作る |
| `export 名前` / `export 名前=値` | 環境変数にする（子のプロセスに渡る） |
| `名前=値 コマンド` | そのコマンドにだけ環境変数を渡す |
| `${名前:-既定}` | 変数が空か無いときは「既定」を使う（9.3節の `${1:-…}` と同じ形） |
| `unset 名前` | 変数を消す |
| `env` | 環境変数の一覧を表示する。`env \| grep HOME` で、ある名前を探せる |

子のプロセスが環境変数を変えても、親には戻りません（1.4節と同じ形です）。Node.js では `process.env.GREETING` で読めます（[samples/env-demo.mjs](samples/env-demo.mjs)。Node.js は第2章で入れます）。

Flask では、`FLASK_APP` や `FLASK_DEBUG` を環境変数で設定したかもしれません。Flask は起動するときにこれらを読んで、どのアプリを動かすか、デバッグのモードにするかを決めていました。Node.js でも `PORT=3000` のように、設定を環境変数で渡します（第5部）。

### 10.2 手を動かす: PATH でコマンドの場所を調べる

`ls` と打つと、シェルは `ls` というファイルを `PATH` という環境変数のフォルダから探します。PATH にはフォルダが `:` で区切って並んでいて、シェルは**前から順に**探し、最初に見つかったものを動かします。

```sh
$ echo $PATH | tr ':' '\n'     # : を改行にして、1行に1つずつ（6.2節の tr）
/opt/homebrew/bin
/opt/homebrew/sbin
/usr/local/bin
/usr/bin
/bin
/usr/sbin
/sbin
$ which git                    # 実際に使われる git の場所
/opt/homebrew/bin/git
$ which -a git                 # -a: PATH の中の候補をすべて（all）
/opt/homebrew/bin/git
/usr/bin/git
$ bash samples/show-path.sh    # 探される順番と、無いフォルダに ✗ を付けて表示する
 1 /opt/homebrew/bin
 2 /opt/homebrew/sbin
 ...
```

（`/opt/homebrew` は第2章で Homebrew を入れると増えます。今はまだ無いかもしれません。）

- **順番が大事**です。上の例では `/opt/homebrew/bin` が `/usr/bin` より前なので、Homebrew の git が先に見つかります。
- 今いる場所（`.`）は PATH に入っていません。だから自分で作ったスクリプトは `./hello.sh` と場所を書いて動かします。`.` を入れると、だれかが置いた同じ名前の悪いファイルを、うっかり動かす危険があるためです。
- `command not found` は「PATH のどのフォルダにも無かった」という意味です。入れたはずなのに出るときは、PATH を疑います。
- zsh は一度見つけた場所を覚えています。新しく入れたのに古いほうが動くときは、`rehash` で忘れさせます。

macOS では、ログインのときに `/usr/libexec/path_helper` が `/etc/paths` などから PATH の最初の値を作ります。`/usr/bin` などが最初から入っているのはこのためです。

## 11. zsh の設定ファイル

### 11.1 どのファイルが、いつ読まれるか

zsh は起動するときに、ホームフォルダの設定ファイルを読みます。

| ファイル | 読まれるとき | 書くもの |
| --- | --- | --- |
| `~/.zshenv` | 毎回（スクリプトを動かすときも） | ほぼ何も書かない（重くすると、すべてが遅くなる） |
| `~/.zprofile` | ログインシェルのとき | PATH の設定（Homebrew、`~/.local/bin` など） |
| `~/.zshrc` | 対話シェルのとき | エイリアス、関数、プロンプト、mise の設定 |

- **ログインシェル**: ログインしたときに最初に起動されるシェル。ターミナル.app は、新しいウィンドウやタブを毎回ログインシェルとして開きます。
- **対話シェル**: 人がコマンドを打つためのシェル。`bash script.sh` のシェルは対話シェルではないので、`.zshrc` は読まれません。

迷ったら「**PATH は `.zprofile`、それ以外の対話用の設定は `.zshrc`**」と覚えておけば十分です。どちらも、まだ無ければ自分で作ってかまいません。[samples/zshrc.sample](samples/zshrc.sample) に、コメント付きの `.zshrc` の例があります。そのままコピーせず、意味が分かった行だけを移してください。

### 11.2 手を動かす: .zshrc にエイリアスを足す

**エイリアス**は、長いコマンドに短い別名を付けるものです。書き換える前に、必ずバックアップを取ります。

```sh
$ touch ~/.zshrc                       # まだ無いときのために（あれば日時が変わるだけ）
$ cp ~/.zshrc ~/.zshrc.backup          # バックアップ
$ echo "alias ll='ls -lahF'" >> ~/.zshrc   # >> で最後に足す（> にすると中身が消える）
$ tail -n 1 ~/.zshrc
alias ll='ls -lahF'
$ ll                                   # まだ効かない（今のシェルは、足す前の .zshrc を読んだ）
zsh: command not found: ll
$ source ~/.zshrc                      # 今のシェルに .zshrc を読み込み直させる
$ ll
$ type ll
ll is an alias for ls -lahF
```

- `"alias ll='ls -lahF'"` は、外側をダブルクォート、中をシングルクォートにして、シングルクォートをそのまま書き込んでいます。
- `source` も今のシェルの状態を変えるので、組み込みコマンドです（1.4節）。新しいタブを開いても設定は効きます。
- `.zprofile` を書き換えたときは、`exec zsh -l`（今のシェルを、新しいログインシェル `-l` に入れ替える）で読み直します。

ファイルを開いて書き換えるときは `open -e ~/.zshrc`（テキストエディット `-e` で開く）か、第4章の後なら `code ~/.zshrc` を使います。

### 11.3 手を動かす: 関数を作る

引数を決まった位置で使いたいときは、エイリアスでなく**関数**にします。関数の中では、スクリプトと同じく `$1`・`$#` で引数を読めます（9.3節）。`.zshrc` の最後に、ヒアドキュメントで足します。

```sh
$ cat >> ~/.zshrc <<'EOF'

# mkcd フォルダ: フォルダを作って、そこへ移動する
mkcd() {
  mkdir -p "$1" && cd "$1"
}
EOF
$ source ~/.zshrc
$ mkcd ~/dev/ch01/playground/new/folder
$ pwd
/Users/alice/dev/ch01/playground/new/folder
$ type mkcd
mkcd is a shell function
```

`cat >> ファイル <<'EOF'` は「打った行を、ファイルの最後に足す」です（`>>`）。

`mkcd` は関数なので、今のシェルの中で動き、今のシェルのまま `cd` できます。同じ中身をスクリプトのファイルにして動かすと、スクリプトの別のプロセスの中で移動するだけで、元のシェルの場所は変わりません（練習問題9で確かめます）。また、関数を途中で終わらせるときは、`exit` ではなく `return` を使います。`exit` と書くと、シェル（ターミナルのタブ）ごと終わってしまいます。

### 11.4 手を動かす: 自分のコマンド置き場を PATH に足す

自分で書いたスクリプトを、どのフォルダからでも名前だけで動かせるようにします。置き場所は `~/.local/bin` にし、そこを PATH の先頭に足します。PATH の設定なので `.zprofile` に書きます。

```sh
$ mkdir -p ~/.local/bin
$ cp ~/dev/ch01/count.sh ~/.local/bin/count     # 拡張子を外した名前にする
$ chmod +x ~/.local/bin/count
$ touch ~/.zprofile && cp ~/.zprofile ~/.zprofile.backup
$ grep -c '.local/bin' ~/.zprofile               # もう書いてあるか（0 ならまだ）
0
$ echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zprofile   # 0 のときだけ、1回だけ打つ
$ exec zsh -l                                    # .zprofile を読み直す
$ cd ~ && which count
/Users/alice/.local/bin/count
$ count ~/dev/ch01/samples/access.log
/Users/alice/dev/ch01/samples/access.log は 80 行です
```

- `'export PATH="$HOME/.local/bin:$PATH"'` を**シングルクォート**で囲むのは、`$HOME` や `$PATH` を今は置き換えず、文字のまま `.zprofile` に書くためです。ログインのたびに、その時の PATH の前に `~/.local/bin` が足されます。
- 同じ行を2回足すと、PATH に同じフォルダが重なります（害はありませんが、`grep -c` で確かめてから足します）。
- 拡張子を外したのは、使う人にとって「何の言語で書かれているか」は関係ないからです。何で動かすかは、1行目の shebang で決まります。
- 第1部の成果物（dotfiles）を作った後は、`~/.zprofile` は dotfiles のリポジトリのファイルを指すリンクになっています。そのときは、リポジトリの `zprofile` を書き換えて、コミットします。

## まとめ

- コマンドは「コマンド名・オプション・引数」の並び。オプションの意味は `man` で調べる。実習は `~/dev/chNN` で行う。
- シェルは、コマンドを動かす**前に**、グロブ・変数・`$( )` を展開する。クォートで止められる。変数は `"$var"` と囲む。
- stdout・stderr・stdin は別々の流れで、リダイレクトとパイプで行き先を変えられる。パイプは1段ずつ組み立てる。
- 終了ステータスは 0 が成功。`&&`・`||`・`exit` で使う。
- 権限は「だれが・何をできるか」。`permission denied` を `sudo` で黙らせない。
- スクリプトは shebang・`set -euo pipefail`・引数の確かめ・エラーは stderr と 0 以外の終了ステータス、の形で書く。
- コマンドは PATH の**前から順に**探される。PATH は `.zprofile`、対話用の設定は `.zshrc`。今のシェルの状態を変えるもの（`cd`、`export`、`source`、関数）は、子のプロセスでは実現できない。
