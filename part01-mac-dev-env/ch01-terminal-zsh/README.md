# 第1章 ターミナルとzshの基本

この章では、教材全体を通して毎日使う**ターミナル**の操作を身につけます。ターミナルは、マウスでクリックする代わりに、文字でコマンドを打ってコンピュータを動かす道具です。

この章は、`cd` や `ls` を少し使ったことがあるくらいの人を想定して、コマンドの1つ1つ、オプションの1つ1つの意味から説明します。目標は、コマンドを暗記することではありません。**自分が打ったコマンドが、どう読まれ、何が起きたのかを説明できること**です。ここがあいまいなままだと、後の章で `node: command not found` や `permission denied` と表示されたときに、何が悪いのかを切り分けられません。

| 前提 | Mac を普段使っている（ターミナルは、`cd` や `ls` を打ったことがある程度でよい） |
| この章のゴール | コマンドとオプションの読み方が分かる / ファイルとフォルダをターミナルで操作できる / パイプとリダイレクトで小さな道具を組み合わせられる / 権限と PATH のトラブルを自分で直せる / `.zshrc` に何を書けばよいか判断できる |

> **この本文の読み方**
> - `$` から始まる行は「ターミナルに入力するコマンド」です。`$` 自体は入力しません。
> - `$` の無い行は、コマンドを実行したときに表示されるもの（出力）です。
> - `#` から後ろはコメント（説明）なので、入力しなくてかまいません。
> - 出力の例の `alice` は、ユーザー名の例です。自分の Mac では、自分のユーザー名になります。日付や数も、人によって違います。
> - 読むだけでなく、**例のコマンドを自分のターミナルで1つずつ打って**ください。打ってみると、文章だけでは分からないことに気づきます。

## 1. ターミナル・シェル・zsh の関係

### 1.1 3つの言葉

よく混ざって使われる3つの言葉を、区別しておきます。

| 用語 | 役割 | Mac での例 |
| --- | --- | --- |
| ターミナル（端末エミュレータ） | 文字を表示し、キーボードの入力を受け取る「窓」 | ターミナル.app、iTerm2、VS Code の統合ターミナル |
| シェル | 入力された文字を読み取って、プログラムを起動する「通訳」 | zsh（macOS Catalina から標準）、bash |
| コマンド | シェルが起動するプログラム、またはシェル自身の機能 | `ls`（プログラム）、`cd`（シェルの組み込みの機能） |

ターミナルは窓で、その中でシェル（Mac では zsh）が動いていて、シェルが私たちの打った文字を読んで、コマンドを動かしています。

ターミナル.app は「アプリケーション → ユーティリティ」にあります。Spotlight（`⌘ + Space`）で「ターミナル」と入力しても開けます。よく使うので、Dock に入れておくと便利です。

### 1.2 プロンプト

ターミナルを開くと、次のような1行が表示されて、入力を待っています。

```
alice@MacBook-Air ~ %
```

これを**プロンプト**（入力を促す印）と呼びます。zsh の標準のプロンプトは「ユーザー名@コンピュータ名 今いるフォルダ %」の形です。`~` は「自分のホームフォルダにいる」という意味です（2節）。この本文では、プロンプトを短く `$` と書きます。

### 1.3 コマンドの形: コマンド名・オプション・引数

コマンドは、空白で区切った「単語」の並びです。

```sh
$ ls -l Desktop
```

| 部分 | 名前 | 意味 |
| --- | --- | --- |
| `ls` | コマンド名 | 何をするか（ここでは「一覧を表示する」） |
| `-l` | オプション | どのようにするか（ここでは「詳しく」）。`-` で始まる |
| `Desktop` | 引数（ひきすう） | 何に対してするか（ここでは「Desktop フォルダの中を」） |

オプションには、次のような書き方があります。

- `-l` のように、`-` と1文字の短いもの。
- `-l -a` は、まとめて `-la` とも書けます（順番は関係ありません）。
- `--help` のように、`--` と単語の長いもの。
- `-n 20` のように、後ろに値を取るものもあります。

オプションは、コマンドごとに意味が違います。`ls` の `-l` と `grep` の `-l` は、まったく別の意味です。

**オプションを調べる方法**: `man コマンド名` で、そのコマンドのマニュアルを読めます。`↑`・`↓` かスペースキーで進み、`q` で終わります。`/` に続けて単語を打つと、その単語を探せます。

```sh
$ man ls          # ls のマニュアル。q で終わる
```

マニュアルは英語で長いので、全部を読む必要はありません。「この `-h` は何だろう」と思ったときに、そのオプションのところだけを探して読みます。

### 1.4 今使っているシェルを確かめる

```sh
$ echo $SHELL        # ログインしたときに使うシェルの設定
/bin/zsh
```

`echo` は、後ろに書いたものを、そのまま表示するコマンドです。`$SHELL` は「`SHELL` という変数の中身」という意味で、シェルが自分の名前に置き換えてから `echo` に渡します（変数は4.2節と10節で説明します）。

### 1.5 コマンドの種類を調べる: type

`type` を使うと、そのコマンドが何者かが分かります。

```sh
$ type cd
cd is a shell builtin          # シェルの組み込みの機能
$ type ls
ls is /bin/ls                  # ディスクの上にあるプログラム（/bin フォルダの ls というファイル）
```

`ls` は、`/bin/ls` という**ファイル**です。シェルは `ls` と打たれると、このファイルを探して、別のプログラムとして起動します。

一方 `cd` は、シェル自身が持っている機能（**組み込みコマンド**）です。これには理由があります。プログラムは、シェルとは別の**プロセス**（動いているプログラムの1つ1つ）として動きます。もし `cd` が別のプログラムだったら、そのプログラムの中で移動して終わり、シェル自身の場所は変わりません。「**今のシェルの状態を変えるものは、組み込みでなければならない**」と覚えておくと、10節の `export` や11節の `source` が分かりやすくなります。

## 2. ファイルシステムとパス

### 2.1 フォルダの木

macOS のファイルは、すべて `/`（**ルート**と読みます）から始まる、1本の木のような形に並んでいます。ターミナルでは「フォルダ」のことを**ディレクトリ**とも呼びますが、同じものです。

```
/
├── Applications/        アプリ
├── System/              macOS 本体（基本的に書き換えられない）
├── opt/homebrew/        Homebrew（第2章で入れる）
├── usr/bin/             macOS に最初から入っているコマンド（ls, git など）
└── Users/
    └── alice/           ホームフォルダ（~ と書ける。名前はログインに使うユーザー名）
        ├── Desktop/
        ├── Documents/
        ├── Library/
        └── ...
```

自分のユーザー名は、`whoami` で確かめられます。

```sh
$ whoami
alice
$ echo $HOME
/Users/alice
```

### 2.2 パスの書き方

ファイルやフォルダの場所を表す文字列を、**パス**と呼びます。

- **絶対パス**: `/` から始まる書き方。どこにいても同じ場所を指します。例: `/Users/alice/Desktop`
- **相対パス**: 今いる場所（**カレントディレクトリ**）からの道順。例: `Desktop/memo.txt`、`../other`

パスの中で使える特別な記号があります。

| 記号 | 意味 | 例 |
| --- | --- | --- |
| `~` | 自分のホームフォルダ（`/Users/alice`） | `~/Desktop` は `/Users/alice/Desktop` |
| `.` | 今いる場所 | `./script.sh` は「今いる場所の script.sh」 |
| `..` | 1つ上のフォルダ | `../..` は「2つ上」 |
| `/` | フォルダの区切り（先頭にあるときはルート） | `Desktop/memo.txt` |

### 2.3 移動する: pwd と cd

```sh
$ pwd                    # 今いる場所を表示する（print working directory）
/Users/alice
$ cd Desktop             # Desktop へ移動（相対パス。今いる /Users/alice から見て Desktop）
$ pwd
/Users/alice/Desktop
$ cd ..                  # 1つ上へ
$ pwd
/Users/alice
$ cd /usr/bin            # 絶対パスで移動
$ cd -                   # 直前にいた場所へ戻る（移動した先を表示してくれる）
/Users/alice
$ cd                     # 何も書かなければ、ホームへ
```

相対パスの例をもう1つ見ます。`/Users/alice/dev/playground/src/routes` にいて、`/Users/alice/dev/playground/docs` に行きたいとき、道順は「2つ上（`src` を出て `playground` へ）→ `docs` へ」なので、次のように書きます。

```sh
$ cd ../../docs
```

**Tab キーで補完する**: パスを途中まで打って `Tab` キーを押すと、残りを自動で入力してくれます。候補が複数あるときは、もう一度 `Tab` を押すと一覧が出ます。打ち間違いが減るので、**パスは手で全部打たず、Tab に任せる**のがおすすめです。

### 2.4 スペースや日本語を含むパス

フォルダの名前には、スペースや日本語が入ることがあります。シェルは**スペースで単語を区切る**ので、そのまま書くと、別々の引数として扱われてしまいます。

```sh
$ cd ~/My Documents          # だめ: "~/My" と "Documents" の2つの引数になる
$ cd ~/"My Documents"        # よい: クォート（" "）で1つの引数にまとめる
$ cd ~/My\ Documents         # よい: スペースの前に \ を付けて「ただの文字」にする（エスケープ）
```

`Tab` キーで補完すると、`\` は自動で付きます。また、Finder のフォルダをターミナルのウィンドウにドラッグ＆ドロップすると、エスケープされたパスが入力されます。

### 2.5 ローカルのフォルダと、クラウド同期のフォルダ

この教材のフォルダを、OneDrive や iCloud Drive のような、クラウドと同期するフォルダに置いている人もいるでしょう。テキストを読んだり、小さなスクリプトを動かしたりするぶんには問題ありません。でも、第3部から `npm install` をすると、`node_modules` という数千〜数万のファイルが入ったフォルダができ、同期がとても重くなります。

そこで、**アプリを作るときのフォルダは、同期されない `~/dev` の下に作ります**。今のうちに作っておきましょう。

```sh
$ mkdir -p ~/dev       # mkdir はフォルダを作るコマンド。-p は3節で説明します
```

## 3. ファイル操作の基本

この節では、ファイルとフォルダを扱うコマンドを、1つずつ見ていきます。まず、練習用のフォルダを作るスクリプトを動かします。[samples/make-playground.sh](samples/make-playground.sh) は、練習用のファイルとフォルダを `~/dev/playground` にまとめて作ります。

```sh
$ cd このフォルダ/samples                    # この README がある場所の samples（Tab で補完すると楽です）
$ bash make-playground.sh ~/dev/playground   # bash でスクリプトを動かす（9節で説明します）
作成しました: /Users/alice/dev/playground
$ cd ~/dev/playground
```

`このフォルダ` は、この README が入っているフォルダのことです。Finder でこの README のフォルダを開き、ターミナルに `cd ` と打ってから（`cd` の後にスペース）、フォルダをドラッグ＆ドロップすると、パスが入ります。

### 3.1 一覧を見る: ls

`ls` は、フォルダの中にあるものの一覧を表示します（list の略）。

```sh
$ ls
LICENSE			docs			logs			memo.txt		src
My Documents		draft final v2.txt	meeting notes.txt	photos			todo.txt
```

よく使うオプション:

| オプション | 意味 |
| --- | --- |
| `-l` | 詳しく表示する（1行に1つ。権限・持ち主・大きさ・更新した日時） |
| `-a` | `.` で始まる「隠しファイル」も表示する（all） |
| `-h` | 大きさを `1.2K` のように読みやすくする（`-l` と一緒に使う。human-readable） |
| `-t` | 更新した日時の新しい順に並べる（time） |
| `-F` | フォルダの後ろに `/`、実行できるファイルの後ろに `*` を付ける |

オプションは、まとめて書けます。`ls -lah` は `ls -l -a -h` と同じです。

```sh
$ ls -la
total 24
drwxr-xr-x  13 alice  staff   416 11  7 10:00 .
drwxr-xr-x   3 alice  staff    96 11  7 10:00 ..
-rw-r--r--   1 alice  staff     0 11  7 10:00 .hidden-config
-rw-r--r--   1 alice  staff    13 11  7 10:00 LICENSE
drwxr-xr-x   4 alice  staff   128 11  7 10:00 My Documents
...
```

`-l` の1行は、左から次の意味です。

| 例 | 意味 |
| --- | --- |
| `-rw-r--r--` | 種類と権限（8節）。最初の文字が `d` ならフォルダ、`-` ならファイル |
| `1` | リンクの数（気にしなくてよい） |
| `alice` | 持ち主のユーザー |
| `staff` | 持ち主のグループ |
| `13` | 大きさ（バイト） |
| `11  7 10:00` | 最後に変更した日時（11月7日 10:00） |
| `LICENSE` | 名前 |

`.` で始まる名前のファイル（`.hidden-config` や、11節の `.zshrc`）は**隠しファイル**で、`-a` を付けないと表示されません。設定のファイルによく使われます。Finder では `⌘ + Shift + .` で、隠しファイルの表示を切り替えられます。

`ls` の後ろにパスを書くと、そのフォルダの中を表示します。

```sh
$ ls photos
IMG_0001.jpg	IMG_0002.jpg	IMG_0103.jpg	screenshot.png
$ ls -l memo.txt              # ファイルを書くと、そのファイルだけを表示する
-rw-r--r--  1 alice  staff  0 11  7 10:00 memo.txt
```

### 3.2 作る: mkdir と touch

```sh
$ mkdir backup                 # backup というフォルダを作る（make directory）
$ mkdir -p backup/2026/11      # -p: 途中のフォルダ（2026）もまとめて作る。もうあってもエラーにしない
$ touch notes.txt              # 空のファイルを作る。もうあれば、更新した日時だけを今にする
```

`-p` を付けずに `mkdir backup/2026/11` とすると、`backup/2026` がまだ無いので `No such file or directory`（そんなファイルやフォルダは無い）というエラーになります。

### 3.3 コピーする・移動する: cp と mv

```sh
$ cp memo.txt memo-copy.txt          # memo.txt をコピーして memo-copy.txt を作る（copy）
$ cp memo.txt backup/                # backup フォルダの中に、同じ名前でコピーする
$ cp -R docs backup/                 # フォルダは -R を付けると、中身ごとコピーできる
$ mv memo-copy.txt memo2.txt         # 名前を変える（move）
$ mv memo2.txt backup/               # backup フォルダの中へ移動する
```

- `cp コピー元 コピー先`、`mv 移動元 移動先` の順に書きます。
- `cp` は、フォルダを `-R` 無しでコピーしようとすると、`cp: docs is a directory (not copied).` と言ってコピーしません。
- `mv` は「移動」と「名前の変更」の両方に使います。ファイルの名前を変えることは、「同じ場所の、別の名前へ移動すること」だからです。
- コピー先・移動先に同じ名前のファイルがあると、**何も聞かずに上書きします**。`-i` を付けると、上書きする前に `overwrite memo.txt? (y/n [n])` と聞いてくれます（interactive）。

### 3.4 消す: rm

```sh
$ rm notes.txt                 # ファイルを消す（remove）
$ rm -i backup/memo2.txt       # -i: 消す前に確かめる。y で消す、n でやめる
remove backup/memo2.txt? y
$ rm -r backup                 # -r: フォルダを中身ごと消す（recursive）
```

> **注意**: `rm` で消したものは、**ゴミ箱に入りません**。すぐに消えて、元に戻せません。特に `rm -r` は、フォルダの中身をすべて消します。慣れるまでは `-i` を付けて、1つずつ確かめながら消してください。11節で、`rm` がいつも `-i` 付きで動くようにする設定も紹介します。

### 3.5 中身を見る: cat・less・head・tail

```sh
$ cat LICENSE                  # ファイルの中身を全部表示する
no extension
$ less logs/app-3.log          # 長いファイルを、1画面ずつ見る。スペースで次へ、q で終わる
$ head logs/app-3.log          # 最初の10行だけ
$ head -n 3 logs/app-3.log     # -n 3: 最初の3行だけ（head -3 とも書ける）
$ tail -n 3 logs/app-3.log     # 最後の3行だけ
$ tail -f logs/app-3.log       # -f: 最後を表示した後も待ち続け、ファイルに足された行を表示し続ける。Ctrl + C で止める
```

`tail -f` は、動いているサーバのログを見張るときによく使います。

### 3.6 この節のコマンドのまとめ

| コマンド | 意味 | よく使うオプション |
| --- | --- | --- |
| `ls` | 一覧を表示 | `-l`（詳しく）、`-a`（隠しファイルも）、`-h`（大きさを読みやすく）、`-t`（新しい順） |
| `mkdir` | フォルダを作る | `-p`（途中も作る） |
| `touch` | 空のファイルを作る（あれば、日時だけ更新） | |
| `cp` | コピー | `-R`（フォルダごと）、`-i`（上書きの前に確認） |
| `mv` | 移動・名前の変更 | `-i` |
| `rm` | 消す（ゴミ箱に入らない） | `-r`（フォルダごと）、`-i`（確認） |
| `cat` / `less` | 中身を全部表示 / 1画面ずつ表示（`q` で終わる） | |
| `head` / `tail` | 最初 / 最後の数行を表示 | `-n 数`、`tail -f`（足された行を追いかける） |

もう1つ、知っておくとよいことがあります。macOS のコマンドは **BSD 版**で、Linux の **GNU 版**と、オプションが少し違うことがあります（例: `sed -i` の書き方、`date` のオプション）。インターネットで見つけたコマンドが Mac で動かないときは、まず `man コマンド名` で Mac のマニュアルを確かめましょう。

## 4. グロブ（ワイルドカード）とクォート

### 4.1 シェルは、コマンドを動かす前に書き換えている

ここが、この章でいちばん大事な考え方です。シェルは、私たちが打った文字を、そのままコマンドに渡すわけではありません。**コマンドを動かす前に**、特別な記号を見つけて、書き換えて（**展開**して）から渡します。

その特別な記号の1つが**グロブ**（ワイルドカード）です。グロブは、ファイル名の「型」を書いて、それにあてはまるファイル名の並びに展開されます。

| 書き方 | 意味 | 例 |
| --- | --- | --- |
| `*` | 何文字でもよい（0文字も含む） | `*.txt` は「`.txt` で終わる名前すべて」 |
| `?` | ちょうど1文字 | `file?.md` は `file1.md` や `fileA.md` |
| `[abc]` | かっこの中のどれか1文字。`[0-9]` は数字1文字 | `img[0-9].png` |
| `**/` | 何段下のフォルダでもよい（zsh の機能） | `**/*.js` |
| `{a,b}` | `a` と `b` の両方を作る（ブレース展開。ファイルが無くても展開される） | `mkdir -p src/{routes,models}` は `src/routes` と `src/models` を作る |

`echo` は「受け取ったものをそのまま表示する」だけのコマンドなので、シェルが何に展開したかを見るのにちょうどよい道具です。

```sh
$ cd ~/dev/playground
$ echo *.txt
draft final v2.txt meeting notes.txt memo.txt todo.txt
```

`echo` は `*.txt` という文字を受け取ったのではありません。シェルが先に `*.txt` を、あてはまるファイル名の並びに置き換えてから、`echo` に渡しています。`ls *.txt` や `rm *.txt` も同じです。`rm *.txt` は、シェルが `.txt` のファイルを全部並べてから `rm` に渡すので、まとめて消えます。

```sh
$ echo photos/IMG_00??.jpg            # ? は1文字ずつ。IMG_00 の後に2文字
photos/IMG_0001.jpg photos/IMG_0002.jpg
$ echo src/**/*.js                    # src の下の、どの段の .js も
src/app.js src/models/task.js src/routes/index.js src/routes/tasks.js
```

**あてはまるものが無いとき**の動きは、シェルによって違います。zsh は `no matches found`（あてはまるものが無い）というエラーにして、コマンドを動かしません。bash は、グロブをそのままの文字列として渡します。

```sh
$ echo *.xyz
zsh: no matches found: *.xyz
```

このため、zsh では `curl https://example.com/?q=1` のように、URL に `?` が入っていると、`?` がグロブとして読まれてエラーになります。URL はクォート（次の節）で囲みます。

### 4.2 変数

シェルでは、`名前=値` で**変数**に値を入れ、`$名前` で使えます。`=` の前後に**スペースを入れてはいけません**（スペースがあると、`名前` というコマンドを動かそうとしてしまいます）。

```sh
$ name="My Documents"
$ echo $name
My Documents
```

`$name` も、グロブと同じく、シェルがコマンドを動かす前に中身に置き換えます。

### 4.3 クォートの違い

クォート（引用符）で囲むと、シェルの書き換えを止められます。2種類あり、止めるものが違います。

| 書き方 | 変数 `$VAR` を置き換えるか | グロブ `*` を展開するか | 使いどころ |
| --- | --- | --- | --- |
| `'...'`（シングルクォート） | しない | しない | 書いた文字を、そのまま渡したいとき |
| `"..."`（ダブルクォート） | する | しない | 変数を使うが、スペースで分けたくないとき |
| クォートなし | する | する | |

```sh
$ echo '$name'        # シングルクォートの中は、そのままの文字
$name
$ echo "$name"        # ダブルクォートの中では、変数は置き換わる
My Documents
$ echo "*.txt"        # ダブルクォートの中では、グロブは展開されない
*.txt
$ ls "$name"          # よい: "My Documents" が1つの引数として ls に渡る
$ ls $name            # bash では "My" と "Documents" の2つに分かれてしまう（zsh は分けない）
```

最後の行の動きも、シェルによって違います。zsh は、対話で使うぶんには親切にできていますが、シェルスクリプト（9節）は bash で書かれることが多いので、**変数は、いつも `"$var"` とダブルクォートで囲む**習慣をつけておくと、どのシェルでも安全です。

## 5. 標準入力・標準出力・標準エラー出力

### 5.1 3つの流れ

コマンド（プログラム）は、動き始めたときに、3つの「流れ（**ストリーム**）」を持っています。

| 番号 | 名前 | 何が流れるか | 何もしなければ、どこにつながっているか |
| --- | --- | --- | --- |
| 0 | 標準入力（stdin） | プログラムが読むもの | キーボード |
| 1 | 標準出力（stdout） | 結果 | ターミナルの画面 |
| 2 | 標準エラー出力（stderr） | エラーや、途中経過の知らせ | ターミナルの画面 |

左の番号を、**ファイルディスクリプタ**と呼びます。

stdout と stderr は、どちらも画面に出るので、見た目では区別がつきません。でも、**別の流れ**です。結果は stdout に、エラーは stderr に出すのが決まりごとです。こうしておくと、「結果だけをファイルに保存して、エラーは画面で見る」といったことができます。Node.js では、`console.log` が stdout に、`console.error` が stderr に出ます（第3部）。

[samples/streams-demo.sh](samples/streams-demo.sh) は、stdout と stderr に1行ずつ出すスクリプトです。

```sh
$ cd このフォルダ/samples
$ bash streams-demo.sh
これは stdout（標準出力）です
これは stderr（標準エラー出力）です
```

### 5.2 リダイレクト: 流れの行き先を変える

**リダイレクト**を使うと、流れの行き先を、画面からファイルなどに変えられます。

| 書き方 | 意味 |
| --- | --- |
| `cmd > file` | stdout を file に書く。file があれば、中身を消して**上書き**する |
| `cmd >> file` | stdout を file の**最後に足す**（追記） |
| `cmd 2> file` | stderr を file に書く（`2` は stderr の番号） |
| `cmd &> file` | stdout と stderr の両方を file に書く（zsh と bash で使える） |
| `cmd > file 2>&1` | stdout を file に書き、stderr も「今の stdout と同じ行き先」にする（結果は `&>` と同じ） |
| `cmd < file` | file の中身を、stdin として読ませる |
| `cmd > /dev/null` | 出力を捨てる（`/dev/null` は、書いたものが消える特別なファイル） |

やってみましょう。

```sh
$ bash streams-demo.sh > out.txt      # stdout はファイルへ。画面には stderr の行だけが出る
これは stderr（標準エラー出力）です
$ cat out.txt                          # ファイルには stdout の行だけが入っている
これは stdout（標準出力）です
$ bash streams-demo.sh 2> err.txt     # stderr はファイルへ。画面には stdout の行だけ
これは stdout（標準出力）です
$ bash streams-demo.sh &> all.txt     # 両方ファイルへ。画面には何も出ない
$ bash streams-demo.sh 2> /dev/null   # stderr を捨てる
これは stdout（標準出力）です
$ rm out.txt err.txt all.txt          # 片付け
```

> **注意**: `>` は、ファイルの中身を**何も聞かずに消して**から書きます。大事なファイルに `>` を向けないように気をつけてください。足したいときは `>>` です。

`2>&1` は「2番（stderr）を、**その時点で**1番（stdout）が向いている先と同じにする」という意味です。リダイレクトは**左から順に**処理されるので、`cmd 2>&1 > file` と逆に書くと、`2>&1` の時点では stdout はまだ画面を向いているので、stderr は画面に向いたままになります。練習問題11で確かめます。

### 5.3 ヒアドキュメントとコマンド置換

**ヒアドキュメント**は、複数の行を、そのまま stdin として渡す書き方です。

```sh
$ cat > hello.txt <<'EOF'      # 次の行から、EOF とだけ書いた行の前までを cat の stdin にする
こんにちは
二行目
EOF
$ cat hello.txt
こんにちは
二行目
```

`cat` は、ファイル名を渡さないと stdin を読みます。それを `>` で `hello.txt` に書いているので、「書いた2行で `hello.txt` を作る」になります。`EOF` は終わりの印で、別の言葉でもかまいません。

**コマンド置換** `$( )` は、かっこの中のコマンドを動かし、その stdout を文字列として使う書き方です。

```sh
$ date                          # 今の日時を表示する
2026年11月 7日 土曜日 10時00分00秒 JST
$ date +%Y-%m-%d                # + の後ろで形を決める。%Y 年、%m 月、%d 日
2026-11-07
$ today=$(date +%Y-%m-%d)       # date の出力を、変数 today に入れる
$ echo "今日は $today です"
今日は 2026-11-07 です
```

`date` の形の指定には、ほかに `%H`（時）、`%M`（分）、`%S`（秒）などがあります。`date +%Y%m%d-%H%M` なら `20261107-1000` のようになります。

## 6. パイプで小さな道具をつなぐ

### 6.1 パイプとは

`|`（**パイプ**。Mac のキーボードでは `Shift + ¥`）は、左のコマンドの stdout を、右のコマンドの stdin につなぎます。

```sh
$ cd samples            # この章の samples フォルダで試す
$ ls | wc -l           # ls の結果を、wc -l（行を数える）に渡す → ファイルの数が分かる
       7
```

Unix（Mac や Linux の元になった OS）には、「1つのことだけをうまくやる、小さな道具を作り、それを組み合わせる」という考え方があります。パイプは、その組み合わせのための仕組みです。

パイプでよく使う道具を、1つずつ見ていきます。どれも、ファイル名を渡せばそのファイルを、渡さなければ stdin を読みます。

| コマンド | 働き |
| --- | --- |
| `grep 言葉` | その言葉を含む行だけを通す |
| `sort` | 行を並べ替える |
| `uniq` | **隣り合った**同じ行を1つにまとめる |
| `wc -l` | 行の数を数える（word count の line） |
| `cut` | 区切り文字で分けて、決めた列だけを取り出す |
| `awk` | 列を取り出したり、条件で絞ったり、合計したりする（6.4節） |
| `tr` | 文字を置き換える・消す |
| `head` / `tail` | 最初・最後の数行（3.5節） |

### 6.2 1つずつ試す

[samples/access.log](samples/access.log) は、Web サーバの**アクセスログ**（だれが、いつ、どのページを見に来たかの記録）の例です。80行あります。第2部で HTTP を学ぶと、各列の意味がよく分かります。

```sh
$ cd このフォルダ/samples
$ head -n 2 access.log
203.0.113.5 - - [04/Nov/2026:09:03:15 +0900] "GET /static/style.css HTTP/1.1" 200 911
203.0.113.5 - - [04/Nov/2026:09:04:22 +0900] "GET /static/app.js HTTP/1.1" 304 0
```

**grep**: 言葉を含む行だけを通します。

```sh
$ grep POST access.log | head -n 2        # POST を含む行（の最初の2行）
$ grep -c POST access.log                 # -c: 行を表示せず、あてはまった行の数だけを表示（count）
12
$ grep -v GET access.log | head -n 2      # -v: 含まない行を通す（invert）
$ grep -i post access.log | head -n 2     # -i: 大文字と小文字を区別しない（ignore case）
```

**wc -l**: 行の数を数えます。

```sh
$ wc -l access.log
      80 access.log
$ wc -l < access.log                      # < で stdin から読ませると、ファイル名を表示しない
      80
$ grep POST access.log | wc -l            # grep -c と同じ答え
      12
```

Mac の `wc` は、数の前に空白を入れて表示します。

**tr**: 文字を置き換えます。`tr 元の文字 新しい文字` の形です。`-d` を付けると、その文字を消します。

```sh
$ echo "a:b:c" | tr ':' '\n'        # : を改行（\n）に置き換える → 1行に1つ
a
b
c
$ echo "a b c" | tr -d ' '          # -d: 空白を消す（delete）
abc
```

**sort と uniq**: `sort` は行を並べ替えます。`uniq -c` は、隣り合った同じ行を1つにまとめて、その数を前に付けます（count）。

```sh
$ printf 'b\na\nb\nb\n' | sort           # printf は \n を改行にして表示する。b a b b を並べ替える
a
b
b
b
$ printf 'b\na\nb\nb\n' | sort | uniq -c # 並べ替えてから、まとめて数える
   1 a
   3 b
$ printf 'b\na\nb\nb\n' | uniq -c        # sort しないと、隣り合っていない b はまとまらない
   1 b
   1 a
   2 b
```

`uniq` は**隣り合った**同じ行しかまとめないので、先に `sort` で同じ行を隣どうしにします。`sort` のオプション:

| オプション | 意味 |
| --- | --- |
| `-n` | 数として並べる（`10` が `9` より後になる。付けないと文字として並べるので `10` が `9` より前になる） |
| `-r` | 逆の順（大きい順）にする（reverse） |
| `-k 2` | 2列目で並べる（key） |

`sort -rn` は「数として、大きい順」です。`uniq -c` の結果を件数の多い順にするときによく使います。

**cut**: `cut -d 区切り -f 番号` で、区切り文字で分けたときの、その番号の列だけを取り出します（delimiter、field）。

```sh
$ echo "2026-11-07" | cut -d '-' -f 1      # - で区切った1番目
2026
$ head -n 1 access.log | cut -d ' ' -f 1   # 空白で区切った1番目（IP アドレス）
203.0.113.5
```

### 6.3 組み合わせる

アクセスログを空白で区切ると、次のような列に分かれます。

```
203.0.113.5 - - [04/Nov/2026:09:00:01 +0900] "GET / HTTP/1.1" 200 5123
```

| 列（awk の `$n`） | 内容 | 例 |
| --- | --- | --- |
| `$1` | 接続してきたコンピュータの IP アドレス | `203.0.113.5` |
| `$4` `$5` | 日時 | `[04/Nov/2026:09:00:01` `+0900]` |
| `$6` | メソッド（先頭に `"` が付く） | `"GET` |
| `$7` | パス（どのページか） | `/` |
| `$8` | プロトコル | `HTTP/1.1"` |
| `$9` | ステータスコード（200 は成功、404 は見つからない、など） | `200` |
| `$10` | 応答の大きさ（バイト） | `5123` |

「どのページがよく見られているか」を調べてみます。**1段ずつ足して、毎回出力を確かめる**のがコツです。

```sh
$ awk '{print $7}' access.log | head -n 3                    # ① 7列目（パス）だけにする（awk は次の節）
/static/style.css
/static/app.js
/
$ awk '{print $7}' access.log | sort | head -n 3             # ② 並べ替えて、同じパスを隣どうしにする
/
/
/
$ awk '{print $7}' access.log | sort | uniq -c | head -n 3   # ③ まとめて数える
  11 /
   4 /about
   4 /admin
$ awk '{print $7}' access.log | sort | uniq -c | sort -rn | head -n 5   # ④ 件数の多い順に5つ
  18 /tasks
  12 /static/app.js
  11 /
   7 /api/report
   6 /login
```

一度に長いパイプを書いて、結果がおかしいと、どこが悪いのか分かりません。①②③④のように、1段ずつ足していけば、どこで思ったのと違ったかがすぐに分かります。

### 6.4 awk の基本

`awk` は、1行ずつ読んで、空白で列に分け、列ごとに処理する道具です。awk は1つの小さなプログラミング言語ですが、この教材で使うのは次の書き方だけです。

| 書き方 | 意味 |
| --- | --- |
| `awk '{print $7}'` | 7列目を表示する。`{ }` の中が「1行ごとにすること」 |
| `awk '{print $1, $9}'` | 1列目と9列目を、空白を挟んで表示する |
| `awk '$9 == 404'` | 9列目が 404 の行だけを表示する（`{ }` を省くと、行をそのまま表示） |
| `awk '$9 == 404 {print $7}'` | 9列目が 404 の行の、7列目だけを表示する |

awk に渡すものは、シェルに `$7` を変数として置き換えられないように、**シングルクォートで囲みます**（4.3節）。

条件には `==`（等しい）、`!=`（等しくない）、`>=`（以上）、`<`（より小さい）などが使えます。`$9 >= 500` なら「ステータスコードが 500 以上」（サーバのエラー）の行です。2つの条件を両方満たす行は `&&`（かつ）でつなぎます。`$9 >= 400 && $9 < 500` なら「400 以上、500 より小さい」（4xx）の行です。

```sh
$ awk '{print $1, $9}' access.log | head -n 3     # IP とステータスコード
203.0.113.5 200
203.0.113.5 304
198.51.100.23 200
$ awk '$9 == 404' access.log | wc -l             # 404 の件数
      10
$ awk '$9 >= 500' access.log | wc -l             # 5xx の件数
       7
```

**合計を出す**: awk では、変数を前もって用意せずに、いきなり使えます（最初は 0 です）。`END { }` の中は「全部の行を読み終わった後に1回だけすること」です。`NR` は「ここまでに読んだ行の数」で、`END` の中では全体の行数になります。

```sh
$ awk '{sum += $10} END {print sum}' access.log          # 10列目（大きさ）の合計
373903
$ awk '{sum += $10} END {print sum / NR}' access.log     # 平均（合計 ÷ 行数）
4673.79
```

`sum += $10` は「`sum` に10列目の値を足す」という意味です。1行ごとに足していき、最後に `END` で表示しています。

**`cut` で別の文字で区切る**: ログの日時 `[04/Nov/2026:09:03:15 +0900]` を `:` で区切ると、2番目が「時」になります。

```sh
$ cut -d: -f2 access.log | head -n 3      # -d: は -d ':' と同じ
09
09
09
```

## 7. 終了ステータスと `&&` / `||`

### 7.1 終了ステータス

コマンドは、終わるときに 0〜255 の数（**終了ステータス**）を返します。**0 が成功、それ以外は失敗**です。画面には表示されませんが、直前のコマンドの終了ステータスは `$?` で見られます。

```sh
$ ls /存在しない
ls: /存在しない: No such file or directory
$ echo $?
1
$ ls /
Applications	Library	System	Users	...
$ echo $?
0
```

なぜ数で返すのでしょう。画面のメッセージは人が読むためのもので、プログラムが読むには向いていません。終了ステータスがあれば、スクリプトやほかのプログラムが「前のコマンドは成功したか」を確かめて、次にすることを決められます。

`grep` のように、0 以外の数を使い分けるコマンドもあります。`grep` は、見つかったら 0、見つからなかったら 1、エラー（ファイルが無いなど）なら 2 を返します。

### 7.2 `&&` と `||`

```sh
$ mkdir -p build && cd build                         # && : 左が成功したときだけ、右を動かす
$ cd somewhere || echo "移動できませんでした" >&2     # || : 左が失敗したときだけ、右を動かす
```

`>&2` は「この `echo` の stdout を、stderr に向ける」という意味で、エラーのメッセージを出すときの決まった書き方です。

### 7.3 パイプの終了ステータス

パイプ全体の終了ステータスは、ふつうは**最後のコマンドのもの**になります。`grep 言葉 存在しないファイル | wc -l` は、`grep` が失敗しても `wc` が成功するので 0 です。途中の失敗にも気づきたいときは、9節の `set -o pipefail` を使います。

終了ステータスは、後の章で何度も出てきます。テストは失敗すると 0 以外を返し、CI（第11部）はそれを見て「失敗」と判断します。Node.js では `process.exitCode = 1` で返せます（第3部）。

## 8. 権限（パーミッション）

### 8.1 ls -l の権限の読み方

ファイルには「だれが、何をしてよいか」という**権限**が付いています。`ls -l` の左の10文字が、それです。

```sh
$ ls -l
-rwxr-xr-x  1 alice  staff  120 11  4 10:00 deploy.sh
drwxr-xr-x  3 alice  staff   96 11  4 10:00 src
-rw-------  1 alice  staff  411 11  4 10:00 id_ed25519
```

10文字は「種類1文字 + 持ち主の3文字 + グループの3文字 + その他の3文字」です。

```
-  rwx  r-x  r-x
│   │    │    └ その他のユーザー: 読む・実行する
│   │    └ グループ（staff）の人: 読む・実行する
│   └ 持ち主（alice）: 読む・書く・実行する
└ 種類: - ファイル / d フォルダ / l シンボリックリンク（別の場所を指す印）
```

**グループ**は、ユーザーをまとめたものです。Mac の普通のユーザーは、`staff` というグループに入っています。

| 記号 | 数 | ファイルでの意味 | フォルダでの意味 |
| --- | --- | --- | --- |
| `r` | 4 | 読める（read） | 中の一覧を見られる |
| `w` | 2 | 書き換えられる（write） | 中にファイルを作ったり、消したりできる |
| `x` | 1 | 実行できる（execute） | 中に入れる（`cd` できる） |
| `-` | 0 | その権限が無い | |

3文字ずつ、数を足して表すこともできます。

| 権限 | 計算 | 数 |
| --- | --- | --- |
| `rwx` | 4 + 2 + 1 | 7 |
| `rw-` | 4 + 2 + 0 | 6 |
| `r-x` | 4 + 0 + 1 | 5 |
| `r--` | 4 + 0 + 0 | 4 |
| `---` | 0 | 0 |

`rwxr-xr-x` は `755`、`rw-r--r--` は `644`、`rw-------` は `600` です。

### 8.2 権限を変える: chmod

`chmod`（change mode）で権限を変えます。数で書く方法と、記号で書く方法があります。

```sh
$ chmod 600 secret.txt         # 数で: rw------- にする（持ち主だけが読み書きできる）
$ chmod +x deploy.sh           # 記号で: 全員に x（実行）を足す
$ chmod u+x,go-w file          # 記号で: 持ち主に実行を足し、グループとその他から書き込みを外す
```

記号で書くときは、「だれに」「足す・外す・決める」「何を」の順に書きます。

| だれに | 意味 | | 足す・外す | 意味 |
| --- | --- | --- | --- | --- |
| `u` | 持ち主（user） | | `+` | 足す |
| `g` | グループ（group） | | `-` | 外す |
| `o` | その他（other） | | `=` | ちょうどこれにする |
| `a`、または書かない | 全員（all） | | | |

やってみましょう。

```sh
$ cd ~/dev/playground
$ touch run.sh
$ ls -l run.sh
-rw-r--r--  1 alice  staff  0 11  7 10:00 run.sh
$ chmod +x run.sh
$ ls -l run.sh
-rwxr-xr-x  1 alice  staff  0 11  7 10:00 run.sh
```

ファイルを消せるかどうかは、**ファイル自身ではなく、それが入っているフォルダの `w` の権限**で決まります。「ファイルを消す」は、「フォルダの中の一覧を書き換える」ことだからです。

### 8.3 sudo は最後の手段

`sudo` を前に付けると、そのコマンドを、何でもできる管理者（**root**）として動かします。Mac のログインのパスワードを聞かれます。

「`permission denied`（許可されていない）が出たら、`sudo` を付ける」は、危ない癖です。特に `sudo npm install -g ...` や `sudo brew ...` は、root が持ち主のファイルを作ってしまい、後で普通のユーザーとして操作できなくなる原因になります。第2章で入れる Homebrew と mise は、**sudo なしで使えるように作られています**。`permission denied` が出たら、まず「そのファイルはだれの持ち物か（`ls -l`）」「どこに書こうとしているか」を確かめましょう。

### 8.4 macOS 特有の属性

`ls -l` の権限の最後に `@` が付くことがあります。これは、**拡張属性**（ファイルに付けられた追加の情報）がある、という印です。

```sh
$ ls -l@ downloaded.zip
-rw-r--r--@ 1 alice  staff  1024 11  4 10:00 downloaded.zip
	com.apple.quarantine	  57
```

`com.apple.quarantine` は、インターネットからダウンロードしたファイルに付く印で、初めて開くときの「開いてもよいですか？」の確認のもとになっています。

また、ターミナルから `~/Desktop` や `~/Documents` を初めて操作すると、「"ターミナル"がフォルダにアクセスしようとしています」という確認が出ることがあります。これは Unix の権限とは別の、macOS のプライバシーを守る仕組みです（システム設定 → プライバシーとセキュリティ で管理します）。

## 9. シェルスクリプトを書く

### 9.1 最初のスクリプト

いくつかのコマンドを、1つのファイルにまとめて書いたものを**シェルスクリプト**と呼びます。何度も同じ手順を打つ代わりに、ファイルを1つ動かせば済むようになります。

作ってみましょう。ヒアドキュメント（5.3節）でファイルを作ります。

```sh
$ cd ~/dev/playground
$ cat > hello.sh <<'EOF'
#!/usr/bin/env bash
echo "こんにちは、$USER さん"
echo "今は $(pwd) にいます"
EOF
$ bash hello.sh                  # bash にファイルを読ませて動かす
こんにちは、alice さん
今は /Users/alice/dev/playground にいます
```

`bash ファイル名` は、「bash というシェルに、このファイルを読ませて、書いてあるコマンドを順に動かす」という意味です。

ファイルの名前だけで動かすこともできます。そのためには、実行の権限（8節）が要ります。

```sh
$ ./hello.sh
zsh: permission denied: ./hello.sh
$ chmod +x hello.sh
$ ./hello.sh                     # 今いる場所（.）の hello.sh を動かす
こんにちは、alice さん
今は /Users/alice/dev/playground にいます
```

`./` が要る理由は、10.2節の PATH で説明します。

### 9.2 shebang と set

1行目の `#!/usr/bin/env bash` は **shebang**（シバン）と呼び、「このファイルを何で動かすか」を書きます。`./hello.sh` のように動かしたとき、Mac はこの1行目を見て、bash で動かします。必ず1行目に書きます。`#!/usr/bin/env bash` は「PATH（10節）から bash を探して、それで動かす」という意味です。

教材のスクリプトは、2行目に次の1行を書いていることが多いです。

```bash
set -euo pipefail
# -e: どこかのコマンドが失敗したら、そこで止まる（失敗したまま次に進まない）
# -u: 値を入れていない変数を使ったら、エラーにする（打ち間違いに気づける）
# -o pipefail: パイプの途中のコマンドが失敗しても、失敗として扱う（7.3節）
```

`#` から行の最後までは**コメント**で、シェルは読み飛ばします。

### 9.3 if と for

少し長いスクリプトの例です。

```bash
#!/usr/bin/env bash
set -euo pipefail

target="${1:-.}"          # 1つ目の引数（9.4節）。無ければ "."
if [[ ! -d "$target" ]]; then
  echo "フォルダではありません: $target" >&2
  exit 1
fi

for f in "$target"/*; do
  echo "$(basename "$f")"
done
```

- `if [[ 条件 ]]; then … fi` は、条件が正しいときだけ、`then` と `fi` の間を動かします（`fi` は `if` を逆から書いたもの）。`! ` は「〜でない」なので、`[[ ! -d "$target" ]]` は「`$target` がフォルダでない」です。
- `else` を書くと、条件が正しくないときに動かす部分も書けます。

  ```bash
  if [[ -f memo.txt ]]; then
    echo "memo.txt があります"
  else
    echo "memo.txt がありません"
  fi
  ```

- `for f in 並び; do … done` は、並びの1つ1つを `f` に入れて、`do` と `done` の間を繰り返します。ここでは `"$target"/*`（グロブ）で、フォルダの中のものを1つずつ取り出しています。
- `basename` は、パスから最後の名前だけを取り出すコマンドです（`basename /a/b/c.txt` は `c.txt`）。

**この教材のスクリプトは bash で書きます。** 人が打つときは zsh、スクリプトは bash、という使い分けはよく見られます。サーバ（Linux）や CI でも、そのまま動くからです。ただし、macOS に最初から入っている `/bin/bash` は、古い 3.2 という版です（ライセンスの都合で新しくなっていません）。そのため、教材のスクリプトは bash 3.2 でも動く書き方にしています。

### 9.4 引数と条件

スクリプトに渡した引数は、次の特別な変数で読めます。

| 書き方 | 意味 |
| --- | --- |
| `$1`、`$2`、… | 1つ目、2つ目、…の引数 |
| `$#` | 引数の数 |
| `${1:-既定の値}` | 1つ目の引数。無ければ「既定の値」 |
| `$0` | スクリプト自身の名前 |

`bash count.sh memo.txt` と動かしたら、`$1` は `memo.txt`、`$#` は `1` です。

`if [[ 条件 ]]` の条件には、次のようなものが使えます。前に `!` を付けると「〜でない」になります。

| 条件 | 正しいとき |
| --- | --- |
| `[[ -f "$file" ]]` | ファイルがある（file） |
| `[[ -d "$dir" ]]` | フォルダがある（directory） |
| `[[ -z "$s" ]]` | 文字列が空（zero） |
| `[[ "$a" == "$b" ]]` | 2つの文字列が同じ |
| `[[ "$a" != "$b" ]]` | 2つの文字列が違う |
| `[[ $# -lt 1 ]]` | 引数の数が 1 より少ない（`-lt` は less than。ほかに `-gt` より大きい、`-eq` 等しい） |

`exit 数` で、スクリプトをそこで終わらせ、その数を終了ステータス（7節）にします。最後まで進んだときは、最後のコマンドの終了ステータスになります。

```bash
#!/usr/bin/env bash
if [[ $# -lt 1 ]]; then
  echo "使い方: $0 ファイル" >&2     # 使い方は stderr へ
  exit 1
fi
if [[ ! -f "$1" ]]; then
  echo "ファイルがありません: $1" >&2
  exit 1
fi
echo "$1 は $(wc -l < "$1") 行です"   # < でファイルを stdin から読ませると、wc はファイル名を表示しない
```

### 9.5 スクリプトが動かないときの3つの原因

自分で作ったり、人からもらったりしたスクリプトが動かないとき、次の3つがよくある原因です。

| 原因 | 症状 | 調べ方 | 直し方 |
| --- | --- | --- | --- |
| 実行の権限が無い | `./x.sh` で `permission denied` | `ls -l x.sh` で `x` が無い | `chmod +x x.sh` |
| shebang が無い | `./x.sh` のとき、どのシェルで動くかが、呼び出した側しだいになる | `head -n 1 x.sh`（1行目を見る） | 1行目に `#!/usr/bin/env bash` を書く |
| 改行コードが CRLF | `$'\r': command not found` や、`cd: $'~\r'` のように、行の最後に見えない `\r` が付いたエラー | `file x.sh` が `with CRLF line terminators` と表示する。`cat -e x.sh` で、行の最後が `^M$` になる | `tr -d '\r' < x.sh > fixed.sh` で `\r` を消した別のファイルを作る。VS Code なら、右下の「CRLF」を押して「LF」に変えて保存する |

- `file` は、ファイルの中身を見て、何の種類のファイルかを表示するコマンドです。
- **改行コード**は、行の終わりを表す、目に見えない文字です。Mac や Linux は LF（`\n`）の1文字、Windows は CR と LF（`\r\n`）の2文字を使います。Windows で作られたファイルをそのまま使うと、bash には、行の最後に `\r` という余計な文字が付いて見えます。
- `cat -e` は、見えない文字を記号にして表示するオプションです。行の終わり（LF）を `$`、CR を `^M` と表示します。

## 10. 環境変数と PATH

### 10.1 シェル変数と環境変数

4.2節で使った変数には、2つの種類があります。

```sh
$ GREETING=hello            # シェル変数: このシェルの中だけで使える
$ export GREETING=hello     # 環境変数: このシェルから起動するプログラムにも、コピーが渡される
$ GREETING=hello node app.js   # そのコマンドにだけ、環境変数を渡す
```

`env` は、環境変数の一覧を表示するコマンドです。`grep` と組み合わせると、ある名前の環境変数があるかを確かめられます。

```sh
$ env | grep HOME            # 環境変数 HOME の行だけを表示
HOME=/Users/alice
$ echo $HOME $USER           # よく使う環境変数。ホームフォルダとユーザー名
/Users/alice alice
```

プログラムを起動するとき、シェルは**環境変数のコピー**を子のプロセス（起動したプログラム）に渡します。子が環境変数を変えても、親には戻りません（1.5節の「`cd` が組み込みである理由」と同じ形です）。

Node.js では `process.env.GREETING` で読めます。[samples/env-demo.mjs](samples/env-demo.mjs) で確かめられます（Node.js は第2章で入れます）。

Flask を使ったことがあれば、`FLASK_APP` や `FLASK_DEBUG` を環境変数で設定したかもしれません。Flask は、起動するときにこれらの環境変数を読んで、どのアプリを動かすか、デバッグのモードにするかを決めていました。Node.js でも同じように、`NODE_ENV=production` や `PORT=3000` のように、環境変数で設定を渡します（第5部）。

### 10.2 PATH: コマンドはどこから探されるか

`ls` と打ったとき、シェルは `ls` というファイルを、どこから探すのでしょう。その答えが、`PATH` という環境変数です。PATH には、フォルダのパスが `:` で区切って並んでいます。シェルは、**前から順に**それぞれのフォルダを探し、最初に見つかったものを動かします。

```sh
$ echo $PATH
/opt/homebrew/bin:/opt/homebrew/sbin:/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin
$ echo $PATH | tr ':' '\n'     # : を改行にして、1行に1つずつ表示する（6.2節の tr）
/opt/homebrew/bin
/opt/homebrew/sbin
/usr/local/bin
/usr/bin
/bin
/usr/sbin
/sbin
$ which git                    # 実際に使われる git の場所
/opt/homebrew/bin/git
$ which -a git                 # -a: PATH の中にある候補をすべて（all）
/opt/homebrew/bin/git
/usr/bin/git
```

（`/opt/homebrew` は第2章で Homebrew を入れると増えます。今はまだ無いかもしれません。）

- 今いる場所（`.`）は PATH に入っていません。だから、自分で作ったスクリプトは `./hello.sh` と、場所をはっきり書いて動かします。`.` を PATH に入れると、だれかが置いた同じ名前の悪いファイルを、うっかり動かしてしまう危険があるためです。
- **順番が大事**です。上の例では、`/opt/homebrew/bin` が `/usr/bin` より前にあるので、Homebrew で入れた新しい git が、macOS に最初から入っている git より先に見つかります。
- `command not found` は、「PATH のどのフォルダにも見つからなかった」という意味です。入れたはずなのに出るときは、PATH の設定を疑います（第2章で Node.js を入れるときに、また出てきます）。
- zsh は、一度見つけたコマンドの場所を覚えています。新しくコマンドを入れたのに古いほうが動くときは、`rehash` と打つと、覚えたものを忘れさせられます。

PATH にフォルダを足すときは、今の値の前（先に探される）か、後ろにつなげます。

```sh
export PATH="$HOME/.local/bin:$PATH"     # 自分のコマンド置き場を、いちばん先に探させる
```

`"$HOME/.local/bin:$PATH"` は、`$HOME` と `$PATH` が置き換わって、`/Users/alice/.local/bin:/opt/homebrew/bin:…` という1つの文字列になります。これを PATH に入れ直しています。

[samples/show-path.sh](samples/show-path.sh) は、PATH を1行ずつ、探される順番と、そのフォルダがあるかどうかを付けて表示します。

```sh
$ bash samples/show-path.sh
 1 /opt/homebrew/bin
 2 /opt/homebrew/sbin
 ...
```

### 10.3 macOS の path_helper

macOS では、ログインシェル（11節）が起動するときに、`/usr/libexec/path_helper` というプログラムが、`/etc/paths` というファイルなどから PATH の最初の値を作ります。`/usr/bin` などが最初から入っているのは、このためです。

## 11. zsh の設定ファイル

### 11.1 どのファイルが、いつ読まれるか

zsh は、起動するときに、ホームフォルダにある設定のファイルを読みます。エイリアス（11.2節）や PATH の設定を書いておくと、ターミナルを開くたびに、自動で設定されます。

| ファイル | 読まれるとき | 書くもの |
| --- | --- | --- |
| `~/.zshenv` | 毎回（スクリプトを動かすときも） | ほぼ何も書かない（重くすると、すべてが遅くなる） |
| `~/.zprofile` | ログインシェルのとき | PATH の設定（Homebrew の設定など） |
| `~/.zshrc` | 対話シェルのとき | エイリアス、関数、プロンプト、補完、mise の設定 |
| `~/.zlogin` | ログインシェルのとき（`.zshrc` の後） | ふつうは使わない |

- **ログインシェル**: ログインしたときに最初に起動されるシェル。macOS のターミナル.app は、新しいウィンドウやタブを、毎回ログインシェルとして開きます。
- **対話シェル**: 人がコマンドを打つためのシェル。`bash script.sh` で動くシェルは対話シェルではないので、`.zshrc` は読まれません。

迷ったら、「**PATH は `.zprofile`、それ以外の対話用の設定は `.zshrc`**」と覚えておけば十分です。どちらのファイルも、まだ無ければ、自分で作ってかまいません。

### 11.2 設定ファイルを書き換える

```sh
$ cp ~/.zshrc ~/.zshrc.backup   # 書き換える前に、バックアップ（コピー）を取る。まだ無ければ不要
$ open -e ~/.zshrc              # テキストエディット.app で開く（-e: テキストエディットで）
$ code ~/.zshrc                 # VS Code で開く（第4章で code コマンドを使えるようにします）
```

ファイルがまだ無いと `open -e` が開けないので、先に `touch ~/.zshrc` で空のファイルを作ります。

書き換えた設定は、今開いているシェルには、まだ効いていません。次のどれかで効かせます。

```sh
$ source ~/.zshrc               # 今のシェルに、.zshrc を読み込み直させる
$ exec zsh -l                   # 今のシェルを、新しいログインシェル（-l）に入れ替える。.zprofile も読み直される
```

新しいタブやウィンドウを開いても、設定は効きます。`source` も、今のシェルの状態を変えるので、組み込みコマンドです（1.5節）。

[samples/zshrc.sample](samples/zshrc.sample) に、コメント付きの `.zshrc` の例があります。そのまま使うのではなく、1行ずつ意味が分かったものだけを、自分の `.zshrc` に移してください。第1部の成果物（dotfiles）で、この設定を Git で管理します。

### 11.3 エイリアスと関数

**エイリアス**は、長いコマンドに、短い別名を付けるものです。

```zsh
alias ll='ls -lahF'      # ll と打つと、ls -lahF が動く
alias gs='git status'
alias rm='rm -i'         # rm がいつも -i 付きで動く（消す前に確かめる）
```

引数を、決まった位置で使いたいときは、**関数**にします。関数の中では、スクリプトと同じく `$1`・`$#` で引数を読めます（9.4節）。

```zsh
# mkcd フォルダ: フォルダを作って、そこへ移動する
mkcd() {
  mkdir -p "$1" && cd "$1"
}
```

`.zshrc` に書いて `source ~/.zshrc` した後、`type` で確かめられます（1.5節）。

```sh
$ type ll
ll is an alias for ls -lahF
$ type mkcd
mkcd is a shell function
```

`mkcd` はシェルの関数なので、今のシェルの中で動き、今のシェルのまま `cd` できます。同じ中身をスクリプトのファイルにして動かすと、スクリプトの別のプロセスの中で移動するだけで、元のシェルの場所は変わりません（1.5節）。

関数を途中で終わらせるときは、`exit` ではなく `return` を使います。関数は今のシェルの中で動いているので、`exit` と書くと、シェル（ターミナルのタブ）ごと終わってしまいます。

## まとめ

- ターミナルは窓、シェルは通訳。コマンドは「コマンド名・オプション・引数」の並びで、オプションの意味は `man` で調べる。
- シェルは、コマンドを動かす**前に**、グロブ・変数を展開する。クォートで止められる。
- stdout・stderr・stdin は別々の流れで、リダイレクトとパイプで行き先を変えられる。パイプは1段ずつ組み立てる。
- 終了ステータスは 0 が成功。`&&`・`||` やスクリプトで、成功したかどうかを使う。
- 権限は「だれが・何をできるか」。`permission denied` を `sudo` で黙らせない。
- コマンドは PATH の**前から順に**探される。PATH は `.zprofile`、対話用の設定は `.zshrc`。
- 今のシェルの状態を変えるもの（`cd`、`export`、`source`、関数）は、子のプロセスでは実現できない。
