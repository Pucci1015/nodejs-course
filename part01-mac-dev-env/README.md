# 第1部 Mac の開発環境と道具

この先ずっと使う道具を最初に整え、「自分の環境で何が起きているか」を説明できる状態にします。
ここで扱うターミナル、PATH、Git、デバッガは、第2部以降のすべての章で毎日使います。急いで先に進むより、ここで「なぜそう動くのか」を理解しておく方が、後で何倍もの時間の節約になります。

| 章 | 内容 | 目安 |
| --- | --- | --- |
| [第1章 ターミナルと zsh の基本](ch01-terminal-zsh/README.md) | ファイル操作、グロブとクォート、標準入出力とパイプ、終了ステータス、権限、シェルスクリプト、環境変数と PATH、`.zshrc` | 3〜4時間 |
| [第2章 Homebrew と Node.js のインストール](ch02-homebrew-node/README.md) | Apple Silicon の注意点、Homebrew の仕組みと使い方、Brewfile、LTS、mise による Node.js のバージョン管理 | 2〜3時間 |
| [第3章 Git と GitHub](ch03-git-github/README.md) | 3つの領域、コミットの中身、取り消し、ブランチとマージ、コンフリクト、リモート、SSH 鍵、プルリクエスト、`.gitignore` | 4〜5時間 |
| [第4章 エディタとデバッガ](ch04-editor-debugger/README.md) | VS Code の設定の階層と拡張機能、編集の機能、EditorConfig、Node.js のデバッグ、Chrome DevTools | 3〜4時間 |
| [成果物 dotfiles](project-dotfiles/README.md) | 第1部の設定を Git リポジトリにまとめ、GitHub で管理する | 2〜3時間 |

## 各章の使い方

各章のフォルダは同じ構成です。

| 場所 | 中身 |
| --- | --- |
| `README.md` | 本文。番号の付いた節（1, 2, 3, …）に分かれている |
| `samples/` | 本文で使うサンプル。本文の中からリンクしている |
| `exercises/` | 練習問題（`README.md`）と、問題で使うファイル |
| `solutions/` | 模範解答（`README.md`）と、解答のファイル |

1. 本文を読みながら、`$` で始まるコマンドを自分のターミナルで実行する（読むだけでは身につきません）
2. 章の最後まで読んだら、練習問題に取り組む
3. 自分で解いてから模範解答を読み、考え方の違いを確かめる

練習問題の多くは、`~/dev/` の下に練習用のフォルダやリポジトリを作ります。何度でも作り直せるので、壊すつもりで試してください。作り直すときは、そのフォルダの中身を確認してから削除します。

## 第1部を終えたときにできること

- ターミナルで起きたエラー（`command not found`、`permission denied`、`no matches found` など）の原因を切り分けられる
- 自分の Mac の Node.js が、どこに、どのバージョンで入っているかを説明できる
- プロジェクトごとに Node.js のバージョンを固定し、他の人と共有できる
- Git で変更を記録し、失敗を取り消し、ブランチとプルリクエストで変更を取り込める
- ブレークポイントとステップ実行で、自分の思い込みではなく実際の値を見てバグを探せる
- 新しい Mac を、dotfiles のリポジトリから短時間で同じ環境に整えられる

## 第1部で作るもの

- `~/.local/bin/log-summary`、`env-check.sh` などの自作コマンド（第1章の練習問題、第2章の練習問題10）
- GitHub の `git-practice` リポジトリ（第3章の練習問題9）
- GitHub の `dotfiles` リポジトリ（成果物）
