# 第4部 フレームワークなしで Web サーバを作る

Flask では `@app.route` を書くだけで Web アプリが動きました。その裏で、だれかが「HTTP のリクエストを読み、URL で処理を選び、ファイルを返し、フォームを読み、HTML をエスケープし、Cookie でログインを覚える」仕事をしていました。
この部では、その仕事を Node.js の `node:http` だけで、自分で書きます。フレームワークを使わずに一度作っておくと、第5部の Express や、その先のどのフレームワークを使うときも、「これは裏で何をしているのか」「どこに気をつければよいのか」が分かるようになります。
各章で作った部品は、次の章でそのまま使い、最後に組み合わせて掲示板を作ります。

| 章 | 内容 | 目安 |
| --- | --- | --- |
| [第17章 `node:http` で最小のサーバ](ch17-minimal-server/README.md) | リクエストの一生、レスポンスの返し方、例外とサーバの止まり方、返し方の部品、グレースフルシャットダウン、時間の制限 | 4〜5時間 |
| [第18章 ルーティングを自作する](ch18-routing/README.md) | URL の分解、ルートの表とパスパラメータ、404・405・HEAD・OPTIONS、ルートの選び方、最後の `/`、URLPattern、クエリの確かめ、ミドルウェア | 4〜5時間 |
| [第19章 静的ファイル配信](ch19-static-files/README.md) | Content-Type、パストラバーサルを防ぐ、Stream で流す、ETag と 304、Range、圧縮 | 5〜6時間 |
| [第20章 フォームと JSON を受け取る](ch20-request-body/README.md) | チャンクで届くボディ、Content-Type と 415、上限と 413、フォームと JSON、400 と 422、プロトタイプ汚染、ファイルのアップロード | 5〜6時間 |
| [第21章 HTML を生成する](ch21-html-templates/README.md) | エスケープの決まり、自動でエスケープする `html` タグ、レイアウトと部品、テンプレートエンジンの中身、`<script>` に JSON を渡す、CSP | 5〜6時間 |

| [成果物 簡易掲示板](project-bbs/README.md) | 登録・ログイン・スレッド・返信・削除のある掲示板を、第17〜22章の部品で作る。データは JSON のファイル | 10〜15時間 |

## 各章の使い方

第1〜3部と同じ構成です。

| 場所 | 中身 |
| --- | --- |
| `README.md` | 本文。番号の付いた節（1, 2, 3, …）に分かれている |
| `samples/` | 本文で使うサンプル（`samples/README.md` に一覧・ポート・動かし方） |
| `exercises/` | 練習問題（`README.md`）と、問題で使うファイル |
| `solutions/` | 模範解答（`README.md`）と、解答のファイル |

- 練習問題の多くは、**テスト**（`node --test ○○.test.mjs`）か**確認スクリプト**（`bash check-○○.sh`）で確かめます。最初はほとんど失敗し、すべて成功すれば完成です。模範解答は `MODULE=../solutions/○○.mjs node --test ○○.test.mjs` や `bash check-○○.sh ../solutions/○○.mjs` で確かめられます。
- 確認スクリプトは、`bash check-○○.sh` のように `bash` を付けて動かします。サーバを起動して確かめ、最後に止めます。
- 後の章のサンプルと練習問題は、前の章の模範解答を `import` して使います（第18章の Router は、第17章の `createApp` を使う、など）。前の章の自分の解答を使いたいときは、`import` のパスを書き換えてください。
- サーバは `127.0.0.1` だけで待ち受けます。ポートは章ごとに分けています: 第17章 9170〜9179、第18章 9180〜9184、第19章 9190〜9195、第20章 9200〜9205、第21章 9210〜9215、第22章 9220〜9225、成果物 9230（テストは 9231）。
- 外部のパッケージは使いません。`npm install` は不要です。成果物は `~/dev/bbs` で作ります（OneDrive の中に Git のリポジトリやデータを作らないため）。
- ファイルを作るサンプルと練習問題は、OS の一時フォルダに作って、最後に消します。
- 攻撃の仕組みにふれる練習問題（パストラバーサル、プロトタイプ汚染、セッションの扱い）は、どれも**自分の Mac の中で動かしているサーバ**だけを相手にし、「自分のサーバが正しく断るか」を確かめるものです。
- Node.js は、第1部 第2章で mise を使って入れたものを使います。この部は Node.js 24 以降を前提にしていて、執筆時点では 24 と 26 で動作を確かめています。
- Flask と比べる説明では、まず Flask（と、その中の Werkzeug・Jinja2）が何をしてくれていたのかを説明してから、Node.js で同じことを書きます。

## 第4部を終えたときにできること

- `node:http` のリクエストとレスポンスの流れを説明し、例外でサーバを落とさず、安全に止められるサーバを書ける
- URL を分解し、パスパラメータ・クエリ・405・HEAD を正しく扱うルーターを作れる
- パストラバーサルを防ぎ、キャッシュ（304）と Range に対応した静的ファイルのサーバを書ける
- ボディを上限付きで読み、フォーム・JSON・アップロードを正しいステータスコード（400・413・415・422）で扱える
- 値を自動でエスケープする仕組みで HTML を作り、場所ごとのエスケープの違いと CSP を説明できる
- 推測できない ID のセッションで、ログイン・ログアウト・flash・CSRF トークンを作れる
- 小さな部品を組み合わせて、フレームワークなしで Web アプリを1つ作り上げられる

## 第4部で作るもの

- `createApp`（エラー・リクエスト ID・ログ）、返し方の部品、安全に止まるサーバ（第17章）
- パスのパターン、Router、クエリの確かめ、Koa 風の `compose`（第18章）
- 安全なパスの解決、`serveStatic`（ETag・304・Range）、圧縮の選び方（第19章）
- `readBody`・`readJson`・`readForm`、安全なマージ、画像のアップロード（第20章）
- `attrs`・`safeUrl`・`jsonForScript`・`queryString`、ページ分け、小さなテンプレートエンジン（第21章）
- `parseCookies`・`serializeCookie`、署名、`SessionStore`・`withSession`（第22章）
- フレームワークなしの簡易掲示板（成果物）
