## 基本

### 問題1 自分の Mac のアドレスとポートを調べる

1. `ipconfig getifaddr en0` と `curl -s https://api.ipify.org` を実行する。それぞれのアドレスは、本文2.2節の表のどれに当たるか。
2. 2つが違う理由を、「ルーター」「NAT」という言葉を使って1〜2文で説明する。
3. `lsof -nP -iTCP -sTCP:LISTEN` を実行し、表示されたものを1つ選ぶ。その `PID` を `ps -p PID` で調べ、何のプログラムかを書く。
4. 3 で選んだものの `NAME` は `127.0.0.1:番号` か `*:番号` か。同じ Wi-Fi の別の機器から接続できるのはどちらか。

### 問題2 相手のアドレスと「何人目か」を返すサーバ

本文3.2節の `first-server.mjs` を元に、`hello-server.mjs` を作ってください。

- 7010番ポートで、`127.0.0.1` だけで待ち受ける
- 接続してきた相手に `あなたは 127.0.0.1:52344 です（1 人目）` のように送って、接続を終える
- サーバのターミナルにも `1 人目: 127.0.0.1:52344` と表示する
- 「何人目か」は、接続のたびに 1 ずつ増える

確かめ方: `nc 127.0.0.1 7010` を3回実行し、1〜3 人目と表示されること。また、ポート番号が毎回違うことを確かめる。

ヒント: 「何人目か」を数える変数（`let count = 0;`）は、`net.createServer(...)` の**外**に置きます。中に置くと、接続のたびに 0 から始まってしまいます。

### 問題3 ポートを引数で変えられるようにする

`hello-server.mjs` を、`node hello-server.mjs 7011` のように、ポート番号を引数で指定できるようにしてください。省略したときは 7010 にします（本文4.2節の `process.argv[2] ?? ...`）。

1. `node hello-server.mjs` と `node hello-server.mjs 7011` を、2つのターミナルで同時に起動する。両方に `nc` で接続できることを確かめる。
2. `lsof -nP -iTCP -sTCP:LISTEN` に、2つとも表示されることを確かめる。
3. さらに3つ目のターミナルで `node hello-server.mjs` を起動すると、どんなエラーが出るか。エラーの名前と意味を書く。
4. 3 のエラーを、`lsof` と `kill` を使って解決する手順を書き、実際に行う（自分で起動した `hello-server.mjs` を終了する）。

### 問題4 dig で DNS を調べる

1. `dig example.com` を2回続けて実行し、ANSWER SECTION の TTL と `Query time` を比べる。違いが出る理由を、本文5.1節の「キャッシュ」という言葉を使って説明する。
2. `dig www.github.com` の ANSWER SECTION には、何種類のレコードがあるか。ブラウザが最終的に接続する IP アドレスはどれか。
3. `dig +short gmail.com MX` と `dig +short github.com NS` を実行する。それぞれ何の情報か（本文5.1節の表）。
4. `dig +short @8.8.8.8 example.com` と `dig +short @1.1.1.1 example.com` を実行する。`@` の後ろは何を指定しているか。答えは同じだったか。

### 問題5 受け取ったものを送り返すサーバ

`echo-server.mjs` を作ってください。

- 7020番ポートで、`127.0.0.1` だけで待ち受ける
- 受け取ったものを、そのまま相手に送り返す（**エコー**）
- 受け取るたびに、サーバのターミナルに `[受信] 6 バイト` のように、届いたバイト数を表示する
- 相手が `bye` と送ってきたら、`さようなら` と送って接続を終える

確かめ方:

```sh
$ nc 127.0.0.1 7020
hello                ← 入力
hello                ← 返ってくる
bye                  ← 入力
さようなら
$
```

ヒント:

- 受け取るには、`net.createServer` の関数の中で `socket.on('data', (chunk) => { ... })` を使います（本文4.2節の表）。
- `chunk.length` で、届いたバイト数が分かります。
- `nc` は Return で入れた改行も送るので、届く文字は `'bye\n'` です。`'bye\n'.trim()` のように `trim()` を使うと、前後の空白や改行を取り除いた `'bye'` になります。
- `socket.end('さようなら\n')` と書くと、送ってから接続を終えます。

## 応用

### 問題6 1行送って返事を表示するクライアント

`ask.mjs` を作ってください。`node ask.mjs ポート 文字列` で、そのポートに接続して文字列を1行送り、返ってきた返事を1つ表示して終わります。

- 送るのは `文字列` の後ろに改行（`\n`）を付けたもの
- 返事は `返事: hello` のように、前後の改行を取って表示する
- 返事を1つ受け取ったら、`socket.end()` で接続を終える
- サーバが起動していない（`ECONNREFUSED`）ときは、`7021番でサーバが起動していません` と表示する。それ以外のエラーは `エラー: コード` と表示する

確かめ方（問題5の `echo-server.mjs` を起動しておく）:

```sh
$ node ask.mjs 7020 hello
返事: hello
$ node ask.mjs 7021 hello
7021番でサーバが起動していません
```

ヒント: 接続できたら送るので、`socket.write(...)` は `socket.on('connect', () => { ... })` の中に書きます。2つ目の引数は `process.argv[3]` です。

### 問題7 ポートが open か closed かを調べる

`check-port.mjs` を作ってください。`node check-port.mjs ポート [ホスト]` で、次のどれかを1行表示します（ホストを省略したら `127.0.0.1`）。

| 結果 | 表示 | いつ |
| --- | --- | --- |
| open | `127.0.0.1:7020 open（待ち受けている）` | 接続できた。調べるだけなので、すぐ `socket.destroy()` で閉じる |
| closed | `127.0.0.1:7021 closed（拒否された）` | `ECONNREFUSED` |
| timeout | `192.0.2.1:80 timeout（2秒待っても返事が無い）` | 2秒何も起きない |
| その他 | `... エラー EHOSTUNREACH` など | それ以外のエラー |

確かめ方: `echo-server.mjs` を起動したまま、`7020`、`7021`、`80 192.0.2.1` の3つを調べる。

### 問題8 改行で区切って1行ずつ受け取るサーバ

[ex-sender.mjs](ex-sender.mjs) は、4行のメッセージを、わざと区切りを崩して送るクライアントです（1回の送信に2行入れる、1行を2回に分けて送る、など）。

1. まず、[naive-line-server.mjs](naive-line-server.mjs)（「1回の `'data'` が1行」と思い込んで書いたサーバ）で試す。表示がどう崩れるかを見て、本文4.3節の言葉で理由を説明する。

   ```sh
   $ node exercises/naive-line-server.mjs     # ターミナル1（~/dev/ch05 で）
   $ node exercises/ex-sender.mjs             # ターミナル2
   ```

2. 本文4.3節の `split` と `pop` を使って、`line-server.mjs` を作る。
   - 7100番ポートで、`127.0.0.1` だけで待ち受ける
   - 改行までを1行として、`1: apple` のように番号を付けて表示する
   - 1行受け取るたびに、相手に `受け取りました: apple` と送る

3. `node exercises/ex-sender.mjs` で試し、次のように表示されることを確かめる。3行目の日本語が文字化けするのは、この段階では正しい動きです（問題10で直します）。

   ```
   1: apple
   2: banana
   3: こ���にちは
   4: 最後のメッセージ
   ```

ヒント: 本文4.3節の REPL の手順を、`socket.on('data', ...)` の中で行います。`buffer` は、`net.createServer` の関数の中（接続ごと）に `let buffer = '';` と用意します。取り出した行は `for (const line of lines) { ... }` で1つずつ処理します。

### 問題9 名前解決の2つの方法を比べる

本文5.4節の `lookup.mjs` を元に、`dns-check.mjs` を作ってください。`node dns-check.mjs 名前` で、次の4行を表示します。

```
lookup:   127.0.0.1
resolve4: 失敗 ENOTFOUND
resolve6: 失敗 ENOTFOUND
→ OS は知っているが DNS には無い名前（/etc/hosts に書かれているかもしれない）
```

- `dns.lookup`、`dns.resolve4`、`dns.resolve6`（AAAA レコード。使い方は `resolve4` と同じ）を、それぞれ `try` / `catch` で囲んで調べる
- `resolve4` と `resolve6` の答えは配列なので、`addresses.join(', ')` でつなげて表示する
- 最後の行は、次のように決める
  - lookup が成功し、resolve4 が失敗した → `OS は知っているが DNS には無い名前（/etc/hosts に書かれているかもしれない）`
  - lookup が失敗した → `どこにも見つからない名前`
  - それ以外 → `DNS に登録されている名前`

確かめ方: `localhost`、`example.com`、`no-such-name.invalid` の3つで試す。

ヒント: 成功したかを覚えておく変数（`let lookupOk = false;`）を用意し、`try` の中の最後で `true` にします。

## 発展

### 問題10 文字化けしない行サーバ

問題8の `line-server.mjs` を、次のように直してください。

1. 日本語が文字化けしない（本文4.4節の StringDecoder を使う）
2. 接続が終わったとき（`'end'` イベント）に、改行の無いデータが残っていたら、それも1行として扱う。終わるときは `decoder.end()` で、デコーダに残っているバイトも取り出す
3. 2つのクライアントが同時に送っても、それぞれの行が混ざらない。番号も接続ごとに 1 から数え、`[接続1] 1: apple` のように、どの接続の行かを表示する

確かめ方:

```sh
$ node exercises/ex-sender.mjs & node exercises/ex-sender.mjs      # 2つ同時に送る（& は「終わるのを待たずに次へ」）
$ printf 'no newline' | nc 127.0.0.1 7100      # 改行の無い1行を送って終わる
```

`printf` は、文字を（`echo` と違って改行を付けずに）出力するコマンドです。

ヒント: 接続ごとに別々に持つべき変数（`buffer`、`decoder`、番号）は、すべて `net.createServer` の関数の中に置きます。同じ処理（番号を増やして表示し、返事を送る）が `'data'` と `'end'` の2か所で要るので、関数にまとめると書きやすくなります。

### 問題11 ポートの範囲を一度に調べる

`port-scan.mjs` を作ってください。`node port-scan.mjs 7000 7100` で、`127.0.0.1` の 7000〜7100番を調べ、全部の結果がそろったら、次のように表示します。

```
7000〜7100 の 101 個を 21ms で調べました
open 2 個: 7000, 7020
closed 99 個、その他 0 個
```

> **重要**: ポートを調べるのは、**自分の Mac（127.0.0.1）に対してだけ**にしてください。他人のコンピュータやネットワークに対して行うと、攻撃の下調べとみなされ、法律（不正アクセス禁止法など）や利用規約に触れるおそれがあります。接続先は `'127.0.0.1'` と書き、変えられないようにします。

- 範囲は 1000 個までにする（超えたら、メッセージを表示して終わる）
- `for` で、範囲のすべてのポートに**一度に**接続を始める（1つずつ終わるのを待たない）
- 1つのポートにつき 1秒で時間切れにする
- open のポート番号は配列に入れ（`open.push(port)`）、表示する前に小さい順に並べる（第4章8.1節の `sort`）
- かかった時間は、`Date.now()`（今の時刻をミリ秒で返す）を最初と最後で取り、差を表示する

ヒント: 接続は一度に始まり、結果はばらばらの順で届きます。「結果が出た数」を数える変数を用意し、`'connect'`・`'error'`・`'timeout'` のどれが起きても1つ増やします。その数が全体の数と同じになったときが「全部そろったとき」です。

確かめ方: 問題5の `echo-server.mjs` などを起動した状態で実行し、`lsof -nP -iTCP -sTCP:LISTEN` の結果と比べる。

### 問題12 TCP と UDP の違いを確かめる

だれも待ち受けていないポート（7999。`lsof -nP -iTCP:7999` で何も出ないことを確かめる）に、TCP で接続した場合と、UDP で送った場合の違いを確かめる `udp-vs-tcp.mjs` を作ってください。

1. TCP: `net.connect(7999, '127.0.0.1')` で接続し、起きたイベントとエラーのコードを表示する。
2. UDP: `dgram.createSocket('udp4')` で作り、`send('hello', 7999, '127.0.0.1', (err) => { ... })` で送る。`err` が無ければ `エラーなしで送り終わった` と表示し、最後に `close()` する。
3. 1 と 2 の結果の違いを、本文4節の表の「接続」「届くことの保証」の言葉を使って説明する。
4. 動画通話のアプリが TCP ではなく UDP を使うことが多いのはなぜか。「0.5秒前の映像のコマが1枚なくなったとき、送り直してもらうべきか」を考えて答える。
