## 1. 階層で考える

インターネットの通信は、役割の違う**層（レイヤー）**の組み合わせでできています。下の層は、上の層の荷物を運ぶことだけをします。

| 層 | 役割 | 代表的なもの | この教材 |
| --- | --- | --- | --- |
| アプリケーション層 | 何を、どんな形式で送るかの約束事 | HTTP、DNS、SSH | 第6〜7章 |
| （セキュリティ） | 暗号化と相手の確認 | TLS | 第8章 |
| トランスポート層 | プログラム（ポート）どうしをつなぐ | TCP、UDP | この章の3〜4節 |
| インターネット層 | コンピュータ（IP アドレス）からコンピュータへ届ける | IP | この章の2節 |

手紙に例えると、HTTP は「手紙の書き方」、TCP は「書留郵便（届いたか確かめ、なくなったら送り直す）」、IP は「住所をもとに運ぶ郵便局」です。

## 2. IP アドレス

**IP アドレス**は、ネットワークにつながった機器の住所です。`192.168.1.23` のような形（**IPv4**）と、`2001:db8::1` のような形（**IPv6**）があります。

### 2.1 手を動かす: 自分のアドレスを2つ調べる

```sh
$ ipconfig getifaddr en0
192.168.1.23
$ curl -s https://api.ipify.org
203.0.113.77
```

| コマンド | 意味 |
| --- | --- |
| `ipconfig getifaddr en0` | ネットワークの出入口（インターフェース）`en0` のアドレスを表示する。多くの Mac では `en0` が Wi-Fi。何も出ないときは `en1` を試す |
| `curl -s URL` | URL にアクセスして、返ってきた中身を表示する。`-s`（silent）は進み具合の表示を消す |
| `https://api.ipify.org` | 「アクセスしてきた相手のアドレス」を返すだけのサービス。インターネット側から見た自分のアドレスが分かる |

2つの値は違うはずです。理由は 2.3 で分かります。

### 2.2 特別なアドレス

| アドレス | 意味 |
| --- | --- |
| `127.0.0.1`（IPv6 は `::1`） | **ループバック**。自分自身。`localhost` という名前はこれを指す。外には出ていかない |
| `192.168.x.x`、`10.x.x.x`、`172.16.x.x`〜`172.31.x.x` | **プライベートアドレス**。家や会社の中だけで使う。インターネットから直接は届かない |
| `0.0.0.0` | サーバが待ち受けるときに使うと「この機器のすべてのアドレスで」という意味 |
| `192.0.2.x`、`198.51.100.x`、`203.0.113.x` | 説明用。どこにも割り当てられない（この教材の例で使う） |

### 2.3 NAT

家の Wi-Fi ルーターは、インターネット側の1つのアドレス（**グローバルアドレス**）を、家の中の機器で共有させています。外へ出る通信の送り主をルーターのアドレスに書き換え、返ってきた通信を元の機器に戻します。これを **NAT** と言います。

```
 家の中（プライベート）           ルーター                      インターネット
 Mac     192.168.1.23 ─┐
 iPhone  192.168.1.24 ─┼─▶ 192.168.1.1 │ 203.0.113.77 ──▶ サーバ
                       ┘   （中の住所）  （外の住所）
```

2.1 の2つの値が違ったのはこのためです。また、外から届いた通信を、ルーターはどの機器に渡せばよいか分からないので、**自分の Mac で動かしたサーバに、インターネットから直接つないでもらうことは通常できません**（第12部でクラウドに置くのはこのためです）。

## 3. ポートと、最初の TCP サーバ

### 3.1 ポート番号

1台のコンピュータの中では、多くのプログラムが同時に通信します。どのプログラム宛てかを区別するのが**ポート番号**（0〜65535）です。**IP アドレスが建物の住所なら、ポート番号は部屋番号**です。

| 番号 | 用途 |
| --- | --- |
| 22 | SSH（第3章） |
| 53 | DNS |
| 80 / 443 | HTTP / HTTPS |
| 5432 | PostgreSQL（第6部） |
| 3000、5000、8000 など | 開発用のサーバでよく使う（決まりではない） |

`https://example.com/` にポート番号が無いのは、`https` なら 443、`http` なら 80 と既定値が決まっているからです。

### 3.2 手を動かす: 最初の TCP サーバを書く

`~/dev/ch05/first-server.mjs` を作り、次のように書きます。

```js
import net from 'node:net';

const server = net.createServer((socket) => {
  console.log('接続されました');
  socket.write('こんにちは\n');
  socket.end();
});

server.listen(7001, '127.0.0.1', () => {
  console.log('7001番で待ち受けています');
});
```

起動して、別のターミナルから `nc`（netcat。TCP で接続して、文字をやり取りするコマンド）で接続します。`nc ホスト ポート` の形で書きます。

```sh
$ node first-server.mjs              # ターミナル1
7001番で待ち受けています
接続されました                        ← ターミナル2で nc を実行したときに出る

$ nc 127.0.0.1 7001                  # ターミナル2
こんにちは
$                                    ← サーバが socket.end() したので、nc も終わる
```

| 行 | 意味 |
| --- | --- |
| `import net from 'node:net'` | Node.js に最初から入っている TCP の道具（`node:net` モジュール）を、`net` という名前で使えるようにする |
| `net.createServer((socket) => { ... })` | サーバを作る。`{ ... }` の関数は、**だれかが接続してくるたびに**呼ばれる。`socket` は、その「1本の接続」 |
| `socket.write('こんにちは\n')` | 相手に文字を送る |
| `socket.end()` | 送り終わったので、接続を終える |
| `server.listen(7001, '127.0.0.1', () => { ... })` | 7001番ポートで、`127.0.0.1` からの接続を待ち受け始める。準備ができたら `{ ... }` の関数が呼ばれる |

> `(socket) => { ... }` は**アロー関数**です。`function (socket) { ... }` とほぼ同じ意味で、「後で呼ばれる関数」を渡すときによく使います（第3部で詳しく学びます）。

### 3.3 手を動かす: 接続してきた相手を知る

`console.log('接続されました')` を、次のように変えて、サーバを起動し直します（`Ctrl + C` で止めてから、もう一度 `node first-server.mjs`）。

```js
  console.log(`接続されました: ${socket.remoteAddress}:${socket.remotePort}`);
```

`nc 127.0.0.1 7001` を2回実行すると、次のように表示されます。

```
接続されました: 127.0.0.1:52344
接続されました: 127.0.0.1:52351
```

`socket.remoteAddress` は相手の IP アドレス、`socket.remotePort` は相手のポートです。接続する側（`nc`）にもポート番号があり、**OS が空いている番号を毎回選びます**。1本の TCP 接続は「相手の IP・相手のポート・自分の IP・自分のポート」の4つの組で区別されるので、同じサーバに何本でも同時に接続できます。

### 3.4 手を動かす: 待ち受けているポートを調べる

サーバを起動したまま、別のターミナルで調べます。

```sh
$ lsof -nP -iTCP -sTCP:LISTEN
COMMAND   PID  USER   FD   TYPE  DEVICE SIZE/OFF NODE NAME
node    12345 alice   21u  IPv4  0x...      0t0  TCP 127.0.0.1:7001 (LISTEN)
```

`lsof` は、プログラムが開いているファイルや通信の一覧を表示するコマンドです。オプションで絞り込みます。

| オプション | 意味 |
| --- | --- |
| `-n` / `-P` | IP アドレス / ポート番号を、名前に直さず数字のまま表示する |
| `-iTCP` | TCP の通信だけ。`-iTCP:7001` と書くと、7001番だけ |
| `-sTCP:LISTEN` | 待ち受けている（LISTEN）ものだけ |

`PID` はプログラムに付いた番号、`NAME` は待ち受けているアドレスとポートです（`*:7001` なら、すべてのアドレス）。

次に、サーバを起動したまま、**もう1つのターミナルで同じサーバを起動**してみます。

```sh
$ node first-server.mjs
Error: listen EADDRINUSE: address already in use 127.0.0.1:7001
```

**`EADDRINUSE`** は「そのポートは、もう別のプログラムが使っている」という意味です。今後、サーバを止め忘れるとよく見るエラーです。直し方は、止め忘れたサーバのターミナルで `Ctrl + C` を押すか、ターミナルが分からないときは PID を調べて終了します。

```sh
$ lsof -nP -iTCP:7001 -sTCP:LISTEN      # PID を調べる
$ ps -p 12345                           # その PID のプログラムが何か確かめる（-p は PID を指定）
$ kill 12345                            # 終了してもらう
```

自分が起動したものか分からないプログラムは、終了しないでください（macOS の部品であることがあります）。

### 3.5 127.0.0.1 で待ち受けるか、0.0.0.0 で待ち受けるか

| `listen` に渡すアドレス | 接続できる人 |
| --- | --- |
| `'127.0.0.1'` | 自分の Mac の中のプログラムだけ |
| `'0.0.0.0'`、または省略 | 同じ Wi-Fi にいる他の人も（`192.168.1.23:7001` で）接続できる |

Flask の `app.run()` が既定で `127.0.0.1` を使い、`host='0.0.0.0'` で外から見えるようになったのはこのためです。Node.js の `listen(7001)` は、アドレスを**省略するとすべてのアドレスで**待ち受けるので、この教材では `'127.0.0.1'` を必ず書きます。カフェなどの共有の Wi-Fi で、開発中のサーバを外から見えるようにしないでください。

## 4. TCP と UDP

| | TCP | UDP |
| --- | --- | --- |
| 接続 | 送る前に接続を作る | 作らない。いきなり送る |
| 届くことの保証 | 届いたか確かめ、なくなったら送り直す | 保証しない |
| データの区切り | **区切りのないバイトの流れ** | 1回の送信が1つのメッセージ |
| 使いどころ | HTTP、SSH、データベース | DNS、動画通話、ゲーム |

### 4.1 TCP の接続の作り方

TCP は、データを送る前に3回のやり取り（**3ウェイハンドシェイク**）で接続を作ります。

```
クライアント                          サーバ
    │ ── SYN（接続したい） ──────────▶ │
    │ ◀── SYN + ACK（いいよ） ──────── │
    │ ── ACK（了解） ────────────────▶ │   ← ここからデータを送れる
```

接続を作るだけで1往復かかります。第7章の keep-alive や HTTP/2、第8章の TLS 1.3 の工夫は、この往復を減らすためのものです。

### 4.2 手を動かす: クライアントを書き、失敗の種類を見る

今度は接続する側を書きます。`~/dev/ch05/first-client.mjs`:

```js
import net from 'node:net';

const port = Number(process.argv[2] ?? 7001);

const socket = net.connect(port, '127.0.0.1');

socket.on('connect', () => console.log('接続できました'));
socket.on('data', (chunk) => console.log(`受信: ${chunk.toString()}`));
socket.on('end', () => console.log('相手が接続を終えました'));
socket.on('error', (err) => console.log(`エラー: ${err.code}`));
```

| 書き方 | 意味 |
| --- | --- |
| `process.argv[2]` | コマンドの1つ目の引数（`node first-client.mjs 7002` の `7002`）。文字列で入っている |
| `A ?? B` | A が無い（`undefined`）ときは B を使う。引数を省略したときの既定値に使う |
| `Number(...)` | 文字列を数にする |
| `net.connect(ポート, ホスト)` | TCP で接続を始める |
| `socket.on('名前', 関数)` | 「その出来事（**イベント**）が起きたら、この関数を呼んで」と登録する |
| `chunk.toString()` | 届いたデータ（バイト列）を文字列にする |
| `err.code` | エラーの種類を表す短い名前 |

`socket` で起きる主なイベントは次のとおりです。

| イベント | 起きるとき |
| --- | --- |
| `'connect'` | 接続ができた（3ウェイハンドシェイクが終わった） |
| `'data'` | データが届いた。関数には届いたデータ（`chunk`）が渡される |
| `'end'` | 相手が「送り終わった」と伝えてきた |
| `'error'` | 何か失敗した。関数にはエラー（`err`）が渡される |

first-server.mjs を起動した状態と、起動していないポートで試します。

```sh
$ node first-client.mjs 7001
接続できました
受信: こんにちは

相手が接続を終えました
$ node first-client.mjs 7002
エラー: ECONNREFUSED
```

（`受信:` の後の空行は、サーバが送った `\n` です。）だれも待ち受けていないポートに接続すると、相手の OS がすぐに「拒否」を返し、**`ECONNREFUSED`**（connection refused）になります。

では、相手の機器にそもそも届かないときはどうなるでしょう。届かないと「拒否」も返ってこないので、待ち続けることになります。待つ時間を決めるため、`net.connect(...)` の次の行に次を足します。

```js
socket.setTimeout(3000);
socket.on('timeout', () => {
  console.log('時間切れ: 3秒待っても返事がありません');
  socket.destroy();
});
```

| 書き方 | 意味 |
| --- | --- |
| `socket.setTimeout(3000)` | 3000ミリ秒（3秒）何も起きなければ、`'timeout'` イベントを起こす |
| `socket.destroy()` | 接続をあきらめて、すぐに閉じる |

接続先を説明用のアドレス（どこにも無い）に変えられるよう、`const host = process.argv[3] ?? '127.0.0.1';` を足し、`net.connect(port, host)` にします（完成形は [samples/first-client.mjs](samples/first-client.mjs)）。

```sh
$ node first-client.mjs 80 192.0.2.1
時間切れ: 3秒待っても返事がありません
```

（ネットワークによっては、`EHOSTUNREACH` などのエラーがすぐに出ることもあります。）

**すぐに拒否される**なら「相手の機器には届いたが、そのポートでだれも待っていない」、**時間切れ**なら「相手の機器まで届いていない（またはファイアウォールが黙って捨てている）」と、原因を切り分けられます。

### 4.3 手を動かす: TCP は「バイトの流れ」

TCP で最も大切で、最も誤解されやすい性質です。届いたデータの大きさを表示するサーバで確かめます。

```sh
$ node samples/tcp-echo-server.mjs          # ターミナル1（~/dev/ch05 で）
127.0.0.1:7000 で待ち受けています（Ctrl + C で終了）
$ nc 127.0.0.1 7000                          # ターミナル2
こんにちは。文字を送ると大文字にして返します
hello tcp                                    ← 入力して Return
HELLO TCP
```

ターミナル1には、`[受信] ... 10 バイト: "hello tcp\n"` のように、1回の `'data'` で何バイト届いたかが表示されます。`nc` は1行ずつ送るので、1行が1回の `'data'` になっています。

では、プログラムから細かく送ったり、大きく送ったりするとどうなるでしょうか。

```sh
$ node samples/tcp-stream-demo.mjs
(1) "hello\n" "world\n" "bye\n" を3回に分けて write
  受信 1 回目: "hello\nworld\nbye\n"
  → 'data' は合計 1 回、16 バイト
(2) 1MB のデータを1回で write
  → 'data' は合計 17 回、1048576 バイト
```

（回数は環境によって変わります。）

- 3回に分けて送ったものが、**1回にまとまって**届いた
- 1回で送った大きなデータが、**何回にも分かれて**届いた

**TCP は、送った側の `write` の区切りを覚えていません。** 受け取る側は、データの中身から「どこまでが1つのメッセージか」を判断する必要があります。よく使う決め方は「改行までが1つ」です（第6章の HTTP のヘッダもこの考え方です）。

改行で区切る練習を、Node.js の対話モード（REPL、第2章7.2節）でしてみましょう。`node` とだけ打つと始まり、`.exit` で終わります。`//` から後ろは説明なので、打たなくてかまいません。

```
$ node
> let buffer = 'apple\nban'          // 1回目の 'data' で届いた文字
> let lines = buffer.split('\n')     // 改行で分ける
> lines
[ 'apple', 'ban' ]
> buffer = lines.pop()               // 最後の1つを取り出して、buffer に残す
'ban'
> lines                              // 残ったものが「改行まで届いた行」
[ 'apple' ]
> buffer += 'ana\n'                  // 2回目の 'data' で届いた文字を足す
'banana\n'
> lines = buffer.split('\n')
[ 'banana', '' ]
> buffer = lines.pop()
''
> lines
[ 'banana' ]
```

| 書き方 | 意味 |
| --- | --- |
| `文字列.split('\n')` | 改行のところで分けて、配列にする。改行で終わっていれば、最後は `''`（空の文字列）になる |
| `配列.pop()` | 配列の最後の要素を取り出して返す（配列からは無くなる） |
| `a += b` | `a = a + b` と同じ。文字列なら、後ろにつなげる |

`split` した最後の1つは、**まだ改行が来ていない途中の部分**です。それを `pop()` で `buffer` に残しておき、次の `'data'` の文字とつなげれば、行の途中で分かれて届いても、正しく1行ずつ取り出せます。練習問題で、この考え方を使ったサーバを書きます。

### 4.4 日本語がバイトの途中で分かれたとき

`'data'` で届くのは**バイト列**（Node.js では `Buffer`）です。日本語の1文字は、UTF-8 で3バイトです。分かれ目が1文字の途中に来ると、`toString()` では文字化けします。

```sh
$ node samples/decoder-demo.mjs
「こんにちは」は 15 バイト
(1) 1つずつ toString() すると:
  こ� / ��にちは
(2) StringDecoder を通すと:
  こ / んにちは
```

`node:string_decoder` の **StringDecoder** は、文字の途中で切れたバイトを次まで持っておき、そろってから文字にしてくれます。使い方は次の3行です（[samples/decoder-demo.mjs](samples/decoder-demo.mjs) の後半）。

```js
import { StringDecoder } from 'node:string_decoder';
const decoder = new StringDecoder('utf8');   // UTF-8 用のデコーダを1つ作る
const text = decoder.write(chunk);           // chunk.toString() の代わりに使う
```

### 4.5 UDP

UDP は接続を作らず、いきなり送ります。[samples/udp-demo.mjs](samples/udp-demo.mjs) を動かすと、3回送ったものが、3つのメッセージのまま届きます。

```sh
$ node samples/udp-demo.mjs
受信: "hello"（127.0.0.1:61234 から）
受信: "world"（127.0.0.1:61234 から）
受信: "bye"（127.0.0.1:61234 から）
```

| 書き方（`node:dgram`） | 意味 |
| --- | --- |
| `dgram.createSocket('udp4')` | IPv4 の UDP の口を作る |
| `s.bind(ポート, アドレス)` | そのポートで受け取り始める（TCP の `listen` に当たる） |
| `s.on('message', (msg, rinfo) => ...)` | メッセージが届いたら呼ばれる。`rinfo.address` / `rinfo.port` が送り主 |
| `s.send(文字列, ポート, アドレス, (err) => ...)` | 送る。送り終わったら関数が呼ばれる |
| `s.close()` | 閉じる |

UDP には「接続」も「届いたかの確認」もありません。**だれも受け取っていないポートに送っても、送った側は何も知らされません。** 動画通話では、少し前のコマが1つなくなっても、送り直してもらうより次のコマを見せるほうがよいので、UDP がよく使われます。

## 5. DNS: 名前から IP アドレスを調べる

人は `example.com` のような**ドメイン名**で覚えますが、通信には IP アドレスが必要です。名前から IP アドレスを調べる仕組みが **DNS** で、この作業を**名前解決**と言います。

### 5.1 名前解決の流れ

```
 Mac ──①www.example.com は？──▶ リゾルバ（プロバイダや 8.8.8.8 など）
                                    │ ②ルートに聞く        → 「com はあちら」
                                    │ ③com に聞く          → 「example.com はあちら」
                                    │ ④example.com に聞く  → 「93.184.215.14」
 Mac ◀──⑤93.184.215.14──────────── │（答えを TTL の間覚えておく）
```

ドメイン名は右から「ルート → `com` → `example` → `www`」と区切られていて、それぞれの区分の情報を、その区分の **権威 DNS サーバ** が持っています。Mac は、**リゾルバ**に「代わりに全部調べて」と頼みます。リゾルバは答えを**キャッシュ**するので、2回目からはすぐ返ります。覚えておいてよい時間は、答えに付いた **TTL**（秒）で決まります。

DNS の情報は**レコード**として登録されています。

| 種類 | 中身 |
| --- | --- |
| A / AAAA | IPv4 / IPv6 のアドレス |
| CNAME | 別名（「この名前は、あの名前と同じ」） |
| MX | メールの受け取り先 |
| NS | そのドメインを管理する権威 DNS サーバ |
| TXT | 任意の文字列（ドメインの持ち主の確認などに使う） |

### 5.2 手を動かす: dig で調べる

`dig` は DNS に問い合わせて、答えを表示するコマンドです。

```sh
$ dig example.com

;; QUESTION SECTION:
;example.com.                   IN      A

;; ANSWER SECTION:
example.com.            1234    IN      A       93.184.215.14

;; Query time: 12 msec
;; SERVER: 192.168.1.1#53(192.168.1.1) (UDP)
```

出力は長いですが、まず `ANSWER SECTION` を見ます。`1234` が TTL（残り秒数）、`A` がレコードの種類、最後が値です。`Query time` は答えが返るまでの時間、`SERVER` は問い合わせた DNS サーバです（最後の `(UDP)` のとおり、DNS はふつう UDP の 53番ポートを使います）。

| 書き方 | 意味 |
| --- | --- |
| `dig 名前 種類` | 種類（`AAAA`、`CNAME`、`MX`、`NS`、`TXT`）を指定して調べる。省略すると `A` |
| `dig +short 名前` | 答えの値だけを表示する。`dig` のオプションは `+` で始まるものが多い |
| `dig @8.8.8.8 名前` | 問い合わせる DNS サーバを指定する（8.8.8.8 は Google の公開 DNS） |
| `dig +trace 名前` | リゾルバに頼まず、ルートから順にたどって、途中の答えもすべて表示する（5.1 の②〜④） |

```sh
$ dig +short example.com
93.184.215.14
$ dig +short www.github.com
github.com.
20.27.177.113
```

`www.github.com` は、まず CNAME（`github.com.` の別名）が返り、次にその A レコードが返っています。

### 5.3 Mac の中での名前解決と /etc/hosts

アプリが名前解決するとき、macOS は次の順に調べます。

1. `/etc/hosts` ファイル（手で書いた「名前 → IP アドレス」の表）
2. macOS 自身のキャッシュ
3. 設定された DNS サーバ

```sh
$ cat /etc/hosts
127.0.0.1       localhost
::1             localhost
```

`localhost` が `127.0.0.1` になるのは、DNS ではなく `/etc/hosts` に書かれているからです。

DNS の設定を変えたのに古い答えが返るときは、macOS のキャッシュを消します（`sudo` は管理者の権限で実行する。Mac のパスワードを聞かれる）。

```sh
$ sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder
```

### 5.4 手を動かす: Node.js で名前解決する

`~/dev/ch05/lookup.mjs`:

```js
import dns from 'node:dns/promises';

const host = process.argv[2] ?? 'localhost';
const result = await dns.lookup(host);
console.log(result);
```

```sh
$ node lookup.mjs example.com
{ address: '93.184.215.14', family: 4 }
$ node lookup.mjs localhost
{ address: '127.0.0.1', family: 4 }
```

**`await`** は「結果が届くまで待ってから、次の行に進む」という意味です。DNS の答えは少し後で届くので、待つ必要があります（`.mjs` のファイルでは、関数の外で `await` を使えます。詳しくは第3部）。

存在しない名前を渡すと、エラーで止まってしまいます。

```sh
$ node lookup.mjs no-such-name.invalid
Error: getaddrinfo ENOTFOUND no-such-name.invalid
```

止まらないようにするには、**`try` / `catch`** を使います。`try { ... }` の中でエラーが起きると、そこで止まらずに `catch (err) { ... }` に進みます。

```js
try {
  const result = await dns.lookup(host);
  console.log(`lookup: ${result.address}`);
} catch (err) {
  console.log(`lookup: 失敗 ${err.code}`);
}
```

Node.js には、名前解決の方法が2つあります。

| 関数 | 調べ方 | `localhost` |
| --- | --- | --- |
| `dns.lookup(名前)` | OS に聞く（5.3 の 1〜3。`/etc/hosts` も見る）。`fetch` などの普段の通信はこちら | 見つかる |
| `dns.resolve4(名前)` | DNS サーバに直接聞く（A レコード）。答えはアドレスの配列 | 見つからない（`ENOTFOUND`） |

両方を試す完成形は [samples/lookup.mjs](samples/lookup.mjs) です。

## 6. 通り道を調べる: ping と traceroute

```sh
$ ping -c 3 example.com
64 bytes from 93.184.215.14: icmp_seq=0 ttl=52 time=110.3 ms
$ traceroute example.com
```

- `ping` は相手に「聞こえますか」と小さなデータを送り、返事までの時間を測ります。`time=` が**往復時間**（RTT）で、4.1 の「1往復」はこの時間です。`-c 3` は「3回（count）で終わる」。付けないと止まらないので `Ctrl + C` で止めます。
- `traceroute` は、相手に届くまでに通るルーターを、近い順に表示します。`* * *` はそのルーターが返事をしなかったという意味で、珍しくありません。

`ping` に返事をしない設定のサーバも多いので、返事が無くても「つながらない」とは限りません。

## まとめ

- 通信は層の組み合わせ。HTTP は TCP の上で、TCP は IP の上で動く。
- IP アドレスは機器の住所、ポート番号は部屋番号。`127.0.0.1` は自分自身。開発用のサーバは `127.0.0.1` で待ち受ける。
- `net.createServer` でサーバ、`net.connect` でクライアントを作り、`socket.on('data', ...)` などで「起きたこと」に応じて動く。
- `ECONNREFUSED` は「届いたが、だれも待っていない」、時間切れは「届いていない」。`EADDRINUSE` は「そのポートは使用中」。
- TCP は区切りのないバイトの流れ。改行などで区切りを決め、途中の部分は次の `'data'` までためておく。日本語は StringDecoder で文字化けを防ぐ。
- DNS は名前を IP アドレスに変える。`dig` で調べられる。Mac は `/etc/hosts` → キャッシュ → DNS サーバの順に調べる。
