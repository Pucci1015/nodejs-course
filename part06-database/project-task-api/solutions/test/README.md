# test — 外から HTTP で確かめるテスト

| ファイル | 中身 |
| --- | --- |
| [api.test.mjs](api.test.mjs) | 30 個のテスト（1〜25 は第5部と同じ、26〜30 は第6部で足したもの）。サーバを別のプロセスで起動し、`fetch` だけで確かめる |

```sh
$ npm test                                          # 完成例を確かめる
$ API_SERVER=../../task-api/src/server.mjs npm test   # 別の場所のサーバを確かめる（test/ から見たパス）
```

- PostgreSQL が要ります。先に `~/dev/part06` で `docker compose up -d --wait` を動かしておきます。つなぎ先は、データベース `taskapi`（`TEST_DATABASE_URL` で変えられる）です
- テストは、起動するサーバごとに、`taskapi` の中に新しいスキーマ（`test_` で始まる名前）を作り、`DATABASE_SCHEMA` で渡します。サーバは、そのスキーマにマイグレーションを動かしてから始まるので、最初は空です。テストが終わると、スキーマごと消します（`npm start` で使う `public` のテーブルには触りません）
- サーバは `127.0.0.1:9461` で起動します。テスト 23・24・28〜30 は、別のサーバを `9462` で起動します。ほかのものがこのポートを使っていると、失敗します
- テストは上から順に動き、同じサーバのデータを使い続けます。1つだけ動かしたいときは、`node --test --test-name-pattern='SSE' "test/*.test.mjs"` のようにします（ただし、前のテストで作ったデータが無いと失敗するものもあります）
- テストは、中の作り（どのファイルに何を書いたか）を見ません。要件（`../../README.md` の2節）だけを確かめるので、自分の API にもそのまま使えます（第28章 6節の契約のテスト）
