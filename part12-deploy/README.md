# 第12部 デプロイと運用

第11部までで、ログインできて、テストと CI が整ったタスク管理アプリができました。でも、動くのは自分の Mac の中だけです。この部では、**アプリを本番に出し、動かし続ける**ための知識を学びます。開発と本番の違い、コンテナ、クラウドの PaaS と独自ドメイン、ファイルをオブジェクトストレージに置くこと、時間のかかる仕事をバックグラウンドに回すこと、CDN とキャッシュ、監視と台を増やすこと、と順に手を動かして確かめます。成果物で、タスク管理アプリに画像の添付とメールの仕事の列を足し、コンテナにして、独自ドメインで公開する準備を整えます。

## 準備

第12部のサンプルと練習問題は、外部のパッケージ（AWS SDK・BullMQ・node-redis など）と、Docker を使います。第5〜11部と同じく、**第12部のフォルダを `~/dev/part12` にコピーし、そこで動かします**。第60章の最初に、次を1回だけ実行します。

```sh
$ bash （ここに Finder から part12-deploy フォルダの中の setup-part12.sh をドラッグ）
```

- `~/dev/part12` が作られ、`npm ci` でパッケージが入ります。終わったら `cd ~/dev/part12/ch60-production` で第60章のフォルダに移ります
- [setup-part12.sh](setup-part12.sh) は、作成先（既定 `~/dev/part12`）が既にあれば、何もせずに終わります。作り直すときは、別の名前を指定するか、中身を確かめてから自分で消してください
- 入るパッケージとバージョンは [package.json](package.json) と [package-lock.json](package-lock.json) のとおりです（@aws-sdk/client-s3 3.1161.0、bullmq 6.5.4、redis 6.3.1、express 5.3.0、pg 8.23.1、pino 10.4.0、nodemailer 10.3.1、zod 4.6.7、typescript 6.0.3 など）
- 第61章から Docker Desktop（か OrbStack）を使います（第6部 第32章で入れたもの）。第60・62・64・66章と成果物は、第6部の `compose.yaml` の PostgreSQL と Redis（`~/dev/part06` で `docker compose up -d --wait`）も使います
- 練習用の S3 互換のサーバ・偽の SMTP サーバ・小さな CDN は [tools/](tools/) にあります（`npm run s3`・`npm run mail`・`npm run cdn`）
- 成果物だけは、`~/dev/task-api` で進めます（[project-task-deploy/README.md](project-task-deploy/README.md) の1節）

## 各章の使い方

第1〜11部と同じ構成です。

| 場所 | 中身 |
| --- | --- |
| `README.md` | 本文。番号の付いた節（1, 2, 3, …）に分かれている。「手を動かす」の節で、ファイルを自分で書いて動かす |
| `samples/` | 「手を動かす」で書くプログラムの完成形（`samples/README.md` に一覧と動かし方） |
| `exercises/` | 練習問題（`README.md`）と、問題で使うファイル |
| `solutions/` | 模範解答（`README.md`）と、解答のファイル |

- コードは第7部からと同じく TypeScript（`.ts`）です。`node x.ts` で動かし、`npx tsc` で型を確かめます。練習問題は `node --test x.test.ts`、模範解答は `MODULE=../solutions/x.ts node --test x.test.ts` で確かめます
- サーバは `127.0.0.1` だけで待ち受けます（コンテナの中だけは `0.0.0.0`。第61章 2節）。ポートは、第60章 9807・9808、第61章 9817、第62章 9820〜9829、第63章 9837（練習用の S3 は 9800）、第65章 9856〜9858、第66章 9860・9867・9868 です。第64章はポートを使いません。成果物は開発の API 9490・画面 5173、E2E に 9495〜9498、`docker compose` に 9801〜9803 を使います
- データベースと Redis を使うテストは、`test_` で始まるスキーマ・キーの頭を作り、終わったら消します。第6〜11部の成果物のデータには触りません
- パスワード・鍵・合言葉は、`dev-only-…` で始まる開発用の仮のものです。本物の値は、リポジトリにもこの教材にも書きません。例のメールアドレスは `alice@example.com`・`bob@example.com`、ドメインは `example.com` です
- Flask と比べる説明では、Gunicorn・Celery・Werkzeug の `ProxyFix` などが何をしているかを説明してから、Node.js で同じことを書きます

## 第12部を終えたときにできること

- 開発と本番の違いを説明し、設定を環境変数から読んで起動のときに確かめ、秘密の値を安全に扱える
- プロキシの後ろで、客の IP と https を正しく知り、`Secure` の Cookie を付けられる。ヘルスチェックを作れる
- 自分のアプリの Docker イメージを、小さく・速く・安全に作り、Compose でデータベースと一緒に動かせる
- PaaS にデプロイし、独自ドメインと HTTPS を設定し、止めずに新しい版へ入れ替える流れを説明できる
- ファイルをオブジェクトストレージに置き、署名付き URL で渡し、種類と大きさを確かめて受け取れる
- 時間のかかる仕事・失敗しうる仕事を列とワーカーに回し、再試行と「2回動いても困らない」作りにできる
- `Cache-Control` を、ブラウザと CDN に向けて設計し、ハッシュ付きのファイル名で長く覚えさせられる
- ログとメトリクスで見張り、計測してから直し、台を増やしても壊れない作りにできる

## 第12部で作るもの

- 設定を確かめる `loadConfig`、プロキシの後ろの客の IP、落ちたら起こし直す仕組み、`/healthz`・`/readyz`（第60章）
- 自分のアプリの Dockerfile（マルチステージ）、Dockerfile を点検するコマンド、Compose（第61章）
- 止めずに入れ替えるプロキシ、デプロイのワークフロー、新しい版を待つコマンド（第62章）
- S3 の SDK・署名付き URL・アップロードのルーター・`BlobStore` と契約テスト・孤児の掃除（第63章）
- PostgreSQL の仕事の列、BullMQ のワーカー、メールの仕事、毎朝のお知らせ（第64章）
- `Cache-Control` の方針、ハッシュ付きのファイル名、画面を配るサーバ、印で消すキャッシュ（第65章）
- ログの集計、メトリクス、ヒストグラムとパーセンタイル、ロードバランサ、全部の台に知らせを流すハブ（第66章）
- 画像の添付・メールの仕事の列・2台で動く SSE・監視・Docker・デプロイの設定を足したタスク管理アプリ（成果物）
