# 第62章 練習問題4: 考えて答える

本文を見ながら、答えを書いてください。動かして確かめられるものは、確かめてかまいません。答えは [../solutions/README.md](../solutions/README.md) の問題4にあります。

1. PaaS で動かしたアプリが、ローカルでは動くのに「ヘルスチェックが通らない」ままデプロイに失敗します。ログには `http://127.0.0.1:10000/ で待っています` と出ていました。何が原因で、どう直しますか（2節）。

2. 本文 3.2節で、プロキシを通さずアプリに直接 POST したとき、`Set-Cookie` に `Secure` が付いていたのに、`req.secure` は `false` でした。本番でアプリの番号を外に出してしまうと、`trust proxy` を 1 にしていることで、どんな困ったことが起きますか（3節、第60章 7節）。

3. 上限 100 の PostgreSQL に、`Pool` の `max` を 20 にしたアプリを 4 台で動かしています。ふだんは動いているのに、デプロイのたびに `sorry, too many clients already` が出ます。なぜですか。どう直しますか（4.2節）。

4. 次のマイグレーションを、新しい版と一緒にデプロイしました。release の段階で流れた後、新しい版に入れ替わるまでの数十秒の間に、何が起きますか。止めずにデプロイするには、どう分けますか（4.3節）。

   ```sql
   ALTER TABLE tasks RENAME COLUMN due_date TO due_on;
   ```

5. 本文 6.1節で、止めてから起動したときに `失敗502=4` が出ました。アプリの起動に 5 秒かかるとしたら、失敗は何回くらいになりそうですか（`poll.ts` は、およそ何ミリ秒ごとに聞いていますか）。

6. `deploy.yml` で `concurrency` の `cancel-in-progress` を `true` にすると、2つのコミットを続けて main に入れたときに、何が起こりえますか（7節）。
