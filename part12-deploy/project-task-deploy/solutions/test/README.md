# test — API のテスト（第11部で、層ごとのフォルダに分けた。第12部で 24 個足した）

| フォルダ               | 層           | 中身                                                                                                                                    | 要るもの          | 数  |
| ---------------------- | ------------ | --------------------------------------------------------------------------------------------------------------------------------------- | ----------------- | --- |
| [unit/](unit/)         | 単体         | サービスとパスワードの決まりを、偽物のリポジトリと決まった時刻で確かめる。第12部: 仕事の部品（日付・孤児の掃除・メールを 2 回送らない） | なし              | 29  |
| [contract/](contract/) | 契約（結合） | `TaskRepo` の約束を、メモリの偽物と PostgreSQL の両方に確かめる。第12部: `BlobStore` の約束を、メモリの偽物と S3（mini-s3）に           | PostgreSQL        | 25  |
| [http/](http/)         | HTTP（結合） | サーバを子プロセスで起動し、HTTP だけで確かめる（第10部の 45 個と、第12部の 12 個）                                                     | PostgreSQL・Redis | 57  |
| [support/](support/)   |              | テストの道具（サーバの起動、偽の SMTP サーバ・IdP・S3、偽物のリポジトリと置き場所、テスト用のスキーマ）                                 |                   |     |

```sh
$ npm test                    # 全部（node --test "test/**/*.test.ts"）
$ npm run test:unit           # 単体テストだけ（PostgreSQL が無くても動く）
$ node --test test/contract/task-repo.test.ts   # 1つのファイルだけ
$ API_SERVER=../../task-api/src/server.ts npm test   # 別の場所のサーバを確かめる（test/ から見たパス。第10部と同じ）
```

- `"test/**/*.test.ts"` の `**` は、どの深さのフォルダでも、の意味です。`support/` のファイルは `.test.ts` で終わらないので、テストとしては動きません
- 第12部: `http/` は Redis（`127.0.0.1:6380`。`TEST_REDIS_URL` で変えられる）も要ります。サーバごとに、Redis のキーの頭をスキーマの名前にして、終わったら消します
- PostgreSQL が要るテストは、`test_` で始まるスキーマを作って、終わったら消します。つなぎ先は、データベース `taskapi`（`TEST_DATABASE_URL` で変えられる）です
- 応答の JSON は `any` のまま読み、`assert` で確かめます。そのため `eslint.config.js` で、`test/` だけ `no-unsafe-…` のルールを止めています
