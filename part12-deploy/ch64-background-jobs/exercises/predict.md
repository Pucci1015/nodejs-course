# 第64章 練習問題4: 考えて答える

本文を見ながら、答えを書いてください。答えは [../solutions/README.md](../solutions/README.md) の問題4にあります。

1. 登録の API で、確認メールを `void sendMail(...)`（`await` しない）で送り、すぐに 201 を返すようにしました。応答は速くなりましたが、困る場面を2つ挙げてください（1.1節）。

2. 3.1節の `claimNext` で、処理中の印を `locked_until`（期限つき）ではなく、`locked boolean`（`true` にしたら、終わるまでそのまま）にしたとします。ワーカーが仕事の途中で落ちると、その仕事はどうなりますか。

3. メールを送るワーカーが、次の順で動いています。2 の直前で、デプロイの `SIGKILL` で殺されました。この仕事は、この後どうなりますか。利用者には何が届きますか。どうすれば減らせますか（4.2節、7.1節）。
   1. メールを送る
   2. 「終わった」と書く（`complete`）

4. 5.2節の `bull-add.ts` は `attempts: 4`、`backoff: { type: 'exponential', delay: 500 }` で仕事を入れます。ワーカーを `FAIL=10 node samples/bull-worker.ts`（どの仕事も 10 回目まで失敗する）で動かして、仕事を1つ入れると、仕事は何回始まり、それぞれ前の失敗から何秒後ですか。最後はどうなりますか。予想してから試してください（試したら `Ctrl+C` で止めます）。

5. 毎朝 8 時（日本時間）のお知らせのつもりで、`upsertJobScheduler('daily-digest', { pattern: '0 8 * * *' }, …)` と書き（`tz` なし）、Render（サーバの時刻は UTC）にデプロイしました。お知らせは、日本時間の何時に届きますか（6節）。

6. `bull-add.ts` から `removeOnComplete`・`removeOnFail` を消して、1 日に 10 万通のメールを送るアプリを、半年動かしました。何が起きそうですか（5.2節）。
