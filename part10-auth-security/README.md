# 第10部 認証とセキュリティ

第9部までのタスク管理アプリは、だれでも、どのタスクでも読んだり消したりできました。この部では、**ユーザー**を足します。パスワードを安全に保存して確かめる方法、ログインした状態を Cookie とセッションで覚える方法、メールで本人を確かめる方法、ほかのサービス（IdP）にログインを任せる方法を学び、最後に、ここまでのアプリの守りを1つの表で点検します。成果物で、タスク管理アプリに「登録・メールの確認・ログイン」を足し、自分のタスクだけを扱えるようにします。

> **攻撃の再現は、自分の Mac の中で動かしているものだけを相手にします。** ほかの人のサイトやサービスに、この部で学ぶことを試してはいけません。教材の例は、守り方と「自分のサーバが正しく断るか」を確かめる形にしてあります。

| 章 | 内容 | 目安 |
| --- | --- | --- |

| [第53章 メール送信と本人確認](ch53-email/README.md) | メールが届くまで（SMTP・MX・SPF・DKIM・DMARC）、SMTP を手で話す、nodemailer、メールのリンクのトークン、登録とメールアドレスの確認、パスワードの再設定、送るのを待たせない | 5〜6時間 |

## 準備

第10部のサンプルと練習問題は、外部のパッケージ（express-session・helmet・nodemailer など）を使います。第5〜9部と同じく、**第10部のフォルダを `~/dev/part10` にコピーし、そこで動かします**。第51章の最初に、次を1回だけ実行します。

```sh
$ bash （ここに Finder から part10-auth-security フォルダの中の setup-part10.sh をドラッグ）
```

- `~/dev/part10` が作られ、`npm ci` でパッケージが入ります。終わったら `cd ~/dev/part10/ch51-auth-basics` で第51章のフォルダに移ります
- [setup-part10.sh](setup-part10.sh) は、作成先（既定 `~/dev/part10`）が既にあれば、何もせずに終わります。作り直すときは、別の名前を指定するか、中身を確かめてから自分で消してください
- 入るパッケージとバージョンは [package.json](package.json) と [package-lock.json](package-lock.json) のとおりです（express 5.3.0、express-session 1.19.0、helmet 8.3.0、nodemailer 10.3.1、zod 4.6.7、typescript 6.0.3、eslint 10.13.0、typescript-eslint 8.72.1 など）
- メールの受け取り口と、練習用の IdP は [tools/](tools/) にあります（`npm run mail`・`npm run idp`）。Docker を入れてあれば、メールは Mailpit（[compose.yaml](compose.yaml)）でも受け取れます（第53章 2.1節）
- 成果物だけは、`~/dev/task-api` で進めます（[project-task-auth/README.md](project-task-auth/README.md) の1節）。PostgreSQL は第6部の `compose.yaml` のものを使います

## 各章の使い方

第1〜9部と同じ構成です。

| 場所 | 中身 |
| --- | --- |
| `README.md` | 本文。番号の付いた節（1, 2, 3, …）に分かれている。「手を動かす」の節で、ファイルを自分で書いて動かす |
| `samples/` | 「手を動かす」で書くプログラムの完成形（`samples/README.md` に一覧と動かし方） |
| `exercises/` | 練習問題（`README.md`）と、問題で使うファイル |
| `solutions/` | 模範解答（`README.md`）と、解答のファイル |

- コードは第7部からと同じく TypeScript（`.ts`）で、`node x.ts` で動かし、`npx tsc` で型を確かめます
- 練習問題は `node --test x.test.ts` で確かめます。模範解答は `MODULE=../solutions/x.ts node --test x.test.ts` のように指定して確かめられます。テストの中に、型の間違いを `tsc` で調べるテストも入っています
- サーバは `127.0.0.1`（`localhost`）だけで待ち受けます。ポートは、第51章 9610 番台、第52章 9620 番台、第53章 9630 番台（メールの受け取り口は SMTP 1025・見る所 8025）、第54章 9640（練習用の IdP）と 9647、第55章 9650 番台です。成果物の API は第7部と同じ 9490、画面は 5173 です
- パスワード・鍵・`client_secret` などの値は、`dev-only-…` で始まる、この Mac の中だけで使う開発用の仮のものです。本物の値は、ファイルにもリポジトリにも書きません（第12部 第60章）
- メールは、本物の宛先には送りません。例のアドレスは `alice@example.com`・`bob@example.com` です（`example.com` は説明のための決まったドメイン）
- Node.js は、第1部 第2章で mise を使って入れたものを使います。この部は Node.js 24 以降を前提にしています
- Python と比べる説明では、Flask の `session`（署名付きの Cookie）、Flask-Login、Werkzeug の `generate_password_hash` などが何をしているかを説明してから、Node.js で同じことを書きます

## 第10部を終えたときにできること

- パスワードを Argon2 や scrypt で保存し、時間をそろえて確かめ、総当たりを遅くできる
- 認証と認可を分け、「その人がしてよいか」を1か所で決められる
- Cookie のセッションでログインを覚え、`HttpOnly`・`Secure`・`SameSite`・セッション固定・CSRF への備えを説明できる。JWT との違いと、使いどころを説明できる
- メールのリンクで本人を確かめ、パスワードを再設定できる。そのとき、登録済みかどうかを漏らさない作りにできる
- OpenID Connect の認可コードフロー + PKCE の流れを説明し、ID トークンを確かめて、外のログインを自分のユーザーに結びつけられる
- セキュリティのヘッダ・CSP・認可の漏れ・SSRF・依存パッケージ・エラーの中身を点検できる

## 第10部で作るもの

- パスワードのハッシュ、パスワードの決まり、登録とログインの API、回数の上限、認可の関数（第51章）
- express-session のログイン、ログインしている人だけを通すミドルウェア、CSRF のトークン、小さな JWT、すべての端末からのログアウト（第52章）
- メールの送り方（`Mailer`）、メールのトークン、確認のメール・再設定のメール、送るのを待たない仕組み（第53章）
- 認可コードフローを手で動かすスクリプト、ID トークンを確かめる関数、IdP でログインするアプリ、外のログインを結びつける判断（第54章）
- CSP の nonce、Fetch Metadata で断るミドルウェア、`execFile` で動かすコマンド、持ち主を確かめる API、外へ取りに行く URL の確かめ、エラーを見せないハンドラ、`npm audit` の結果で止める CLI（第55章）
- ユーザー登録・メールの確認・ログインのあるタスク管理アプリ（成果物）
